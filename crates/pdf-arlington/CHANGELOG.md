# Changelog

## 0.1.0 (unreleased)

- **The model.** The Arlington PDF Model's `tsv/latest` at `d148fee` (`COMMIT`), embedded by `build.rs`, with the cells corrected where it contradicts ISO 32000-2 or the reference it cites (`model/corrections.tsv`, `grammar::corrections`) and the rows and tables added that a reference defines and it lacks (`model/additions`, `grammar::additions`); the build stops when upstream has changed a corrected cell or has an added row itself. `Grammar::embedded()` reads it once, the first time it's asked for, and gives it as a `&'static Grammar`; `Grammar::load` reads a checkout whole, a model its caller holds, as the crate chooses none. `Grammar::hash` is the XXH64 of a model's tables.
- **The tables.** A `Table` per object and a `Row` per key or element, upstream's 12 columns, the Type cell split into its `ArlType`s, a cell with an item per type into those items, and the version predicates around a type, a value or a link kept beside it (`Wrapped`, `Wrap`, `WrapFn`).
- **The predicates.** `predicate::parse` reads the language in the cells, which every predicate in the model prints back as; `required`, `holds`, `holds_fully`, `required_value`, `ignored`, `reference`, `since` and `gate` evaluate a cell on an object where it sits, a `Cx`, made for each row by its file's `FileCx`: the trailer, the version, a `resolve` closure that gives the object a reference names, the file's length and the extensions it's checked under, and what the predicates read once a file, kept inside it (its name trees' keys, its structure tree's content items, its form's fields' names). A name tree is kept by where its root was written and the number of the object its entry names, and read again each time when it's known by neither. The structure tree's content items, which `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems` read, know each object an item names by where it was written and, when a reference names it, its number, and a row's container by the number `Cx::id` gives, or without one its own span: an indirect object by its number alone, as an object stream's header can start two objects at one offset, or one inside another, and an object written directly is never an indirect one; a container that can't be told apart from an item that could be it is unknown, never false. The 34 functions of `SUPPORTED` are evaluated, `fn:IsFullyQualifiedFieldName` among them, which this crate defines for the corrections; any other, or a value that can't be read, comes to `Truth::Unknown`, saying what's in the way.
- **Errors.** `Grammar::load` gives a `grammar::Error` when a model doesn't read: its folder, or a table in it, that can't be read, a table's name that isn't UTF-8, no tables, or a rule of the model's files a table breaks, a `grammar::TableError`, after the table's file and line. `predicate::parse` gives a `predicate::Error`: the predicate, then what stopped the parser, and where when it knows. Each derives `Display` and `std::error::Error` with thiserror, `#[non_exhaustive]`; its `Display` is the whole message and none has a `source`, a std error under one being a field, said after `: `.
- **Extensions.** `extension::declared` gives the extensions a file declares, as the model names them, from its trailer's `/Root`, its XMP metadata and a closure that gives the object a reference names, as its own; `Grammar::extensions` every extension a model names, and `extension::ISO` ISO's by number.
- **From pdf-lint.** These are pdf-lint 0.2.0's `grammar`, `predicate` and `extension` modules and the model, what they do unchanged, which pdf-lint re-exports where they were; which model a check reads stays pdf-lint's, so `grammar()`, `use_model` and `grammar::NAMED` aren't here, `Grammar::embedded()` gives the embedded model as a `&'static Grammar`, read once, where it gave an owned `Result<Grammar>` read anew at each call, and `extension::named()` is `Grammar::extensions`, so a model `Grammar::load` reads can be asked too; `Grammar::load` and `predicate::parse` give the typed errors above, each saying what pdf-lint's anyhow errors said, word for word, so the crate depends on pdf-objects and thiserror and not anyhow; `extension::declared` takes the catalog and the metadata in place of pdf-lint's `Source`, so the crate depends on pdf-objects' types alone, `fn:IsHexString` reads the string's own `Form`, unknown when it has none, where pdf-lint's `Cx` asked a `hex` closure by the string's place, and `predicate::TOLERANCE` is public. `predicate::SUPPORTED` and `extension::ISO` are `&[...]`, not arrays of a fixed length, and `predicate::Expr` is `#[non_exhaustive]`, so a function, an extension or a form of predicate can come without a breaking release; a `Cx` is made from a `FileCx`, one a file, its fields private, where pdf-lint's was a literal of public fields beside caches its caller held (`predicate::{Fields, Structure, Trees}`, not here), so a name tree is read once a file and not once a row, and is kept by where its root was written and its number, not where it's kept in memory, and the structure tree's content items and a row's container are known by their numbers, or without one by where they were written, where pdf-lint's knew them by address (`Cx::id` gives the container's number); `Cx` has two lifetimes, the row's borrow and the file's, and its setters, `FileCx`'s too, are `#[must_use]`; `Grammar`, `FileCx` and `Cx` have `Debug`; and `pdf_objects` is re-exported, so its types can be named at the version this crate takes. Rust 1.85 builds it.
- **Tests.** Every table of the embedded model reads, and its hashes are the references'; every predicate in it parses and prints back as written, with a census of its functions; each supported function means what INTERNAL_GRAMMAR.md says, on the model's own cells where it has them; the extensions declared, and every one the model names found; XXH64 against the reference's values; each error's words, every rule a table breaks, a folder that doesn't load and each way a predicate doesn't parse; a name tree read once a file, and kept by where its root was written and its number, two roots at one span among them; the content items known by number or by where they were written, an object stream's two objects at one offset among them; and the README's example as a doctest.
