# Changelog

## 0.1.0 (unreleased)

- **The model.** The Arlington PDF Model's `tsv/latest` at `d148fee` (`COMMIT`), embedded by `build.rs`, with the cells corrected where it contradicts ISO 32000-2 or the reference it cites (`model/corrections.tsv`, `grammar::corrections`) and the rows and tables added that a reference defines and it lacks (`model/additions`, `grammar::additions`); the build stops when upstream has changed a corrected cell or has an added row itself. `Grammar::embedded()` reads it once, the first time it's asked for, and gives it as a `&'static Grammar`; `Grammar::load` reads a checkout whole, a model its caller holds, as the crate chooses none. `Grammar::hash` is the XXH64 of a model's tables, computed by twox-hash.
- **Ids are pdf-objects' struct.** What a resolver is asked, `ObjectId`, is pdf-objects' struct of `number` and `generation`, where it was the pair `(u32, u16)`: `(1, 0)` is `ObjectId::new(1, 0)`, `id.0` is `id.number`.
- **The tables.** A `Table` per object and a `Row` per key or element, upstream's 12 columns, the Type cell split into its `ArlType`s, a cell with an item per type into those items, and the version predicates around a type, a value or a link kept beside it (`Wrapped`, `Wrap`, `WrapFn`).
- **The predicates.** `predicate::parse` reads the language in the cells, which every predicate in the model prints back as; `required`, `holds`, `holds_fully`, `required_value`, `ignored`, `reference`, `since` and `gate` evaluate a cell on an object where it sits, a `Cx`, made for each row by its file's `FileCx`: the trailer, the version, what gives the object a reference names, the file's length and the extensions it's checked under, and what the predicates read of the file as a whole, kept inside it once read (its name trees' keys, its structure tree's content items, its form's fields' names). `FileCx<'a, R>` takes any of pdf-objects' `Resolve` as its resolver, a closure among them, its type `R`, whose default, `FileCx<'a>`, is one over any resolver, a `dyn Resolve`, as a `Cx` reads through it: so `&FileCx` in a signature takes a reference to one over any resolver, and one kept is kept by its resolver's type, or boxed (`Box<FileCx>`). An object the resolver gives none for is null, whatever the reason: over a reading by position, one whose bytes the source failed to give, in that row and in any tree read then. pdf-structure's `Reading::failed_resolves` counts those, for a caller to learn that some were. It's `Send` and `Sync` when its resolver is, what it keeps read once and stored behind a lock, the first stored kept, so one a file is shared across threads, each making its rows' `Cx`s; a `Cx` resolves through it as a `dyn Resolve`, so its type names no resolver. A name tree is kept by where its root was written and the number of the object its entry names, and read again each time when it's known by neither. The structure tree's content items, which `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems` read, know each object an item names by where it was written and, when a reference names it, its number, and a row's container by the number `Cx::id` gives, or without one its own span: an indirect object by its number alone, as an object stream's header can start two objects at one offset, or one inside another, and an object written directly is never an indirect one; a container that can't be told apart from an item that could be it is unknown, never false. Spans are places in one file's bytes, so an object copied from another file is given its number, or its spans dropped (pdf-objects' `Object::unplace`). The 41 functions of `SUPPORTED` are evaluated, `fn:IsFullyQualifiedFieldName` among them, which this crate defines for the corrections; any other, or a value that can't be read, comes to `Truth::Unknown`, saying what's in the way.
- **A cycle told.** `fn:NoCycle`, which the model asks of an object stream's `/Extends`, is evaluated: the row's key followed from its container through each object its value refers to is true where it ends (at an object without the key, or whose value isn't a reference, or names no object), false where it comes back to an object met on the way, the container among them, known by its number where `Cx::id` gives it, else by where it was written, and unknown past as many objects as a value goes through to its object.
- **The pages.** `fn:NumberOfPages` and `fn:PageProperty`, which the model asks of a target dictionary's `/P` and `/A`, are evaluated over the pages a `FileCx` is given, in order, each its dictionary as the resolver gives it (`FileCx::pages`, `#[must_use]`, as a page tree's walk by ISO 32000-2's rules gives them): `fn:NumberOfPages()` their count; `fn:PageProperty(page, path)` the page at an index from 0, or the one a reference resolves to, the path walked from its dictionary as any path is, `fn:ArrayLength` taking it, and a key after an array in it each element's, so `@A==fn:PageProperty(@P,Annots::@NM)` holds where one of the page's annotations has that `/NM`, doesn't where none has, and can't be told where one's can't be compared. A page named by a string (a named destination), an index past the pages, a reference to no page, or the pages not given, can't be told; nor can either function in a row whose `parent::` is a target dictionary (one with `/R`, where an action has `/S`), a target under another's `/T`, whose pages are another document's (ISO 32000-2, 12.6.4.4).
- **The colorants and the fonts.** `fn:HasSpotColorants` and `fn:HasProcessColorants`, which the model asks of a DeviceN space's attributes (`/Colorants`, `/Process`) of the space's names (`parent::1`), and `fn:KeyNameIsColorant`, which it asks of a Type 5 halftone's other keys, are evaluated by what a colorant's name says of it, read as pdf-color reads it (`Colorant::of`), so the crate depends on pdf-color too: a name is a process colorant where it's one of the four of CMYK; a spot colorant where it's any other but `All` and `None`, which name none (ISO 32000-2, 8.6.6.4), and but those the attributes' process dictionary lists among its `/Components`, which are the space's process colorants (8.6.6.5), so an NChannel space over an RGB process naming `Red`, `Green` and `Blue` it lists is asked no `/Colorants`; each names through its references, true where one is, false where each element is a name and none is, unknown where one isn't a name. A halftone's key names a colorant where it's any name but `All` and `None` (10.6.5.6). Before PDF 1.6, `/Colorants`' cell has its version predicate vacant, which leaves the function alone, as the evaluator reduces every cell: there a spot colorant asks it of any DeviceN space. `fn:FontHasLatinChars`, which the model asks of a font descriptor's `/CapHeight` (9.8.1, Table 120), is evaluated over what a `FileCx` is told of the fonts (`FileCx::latin`, `#[must_use]`, a `Latin`, `Clone`, filled by `insert` and read by `get`, re-exported at the root beside `FileCx`): which descriptors' fonts have Latin characters, as only a reader of the fonts can say, each descriptor known by its number, else by where it was written, as the structure tree's content items are, and true where one said of twice has them by either; one not said of, or with nothing given, can't be told, as before. `FileCx`'s `Debug` says whether it was given.
- **The model's predicates parsed once.** `FileCx::grammar` (`#[must_use]`) gives a `FileCx` the model its rows are of, and `required`, `holds`, `holds_fully`, `reference`, `required_value` and `ignored` then read a predicate of the model's rows through it: each text they parse from a row's cells, as the model splits them (its SinceVersion but a version, its Required and IndirectReference but `TRUE` and `FALSE`, each SpecialCase and each PossibleValues item), is parsed the first time a `FileCx` given the model asks, on whichever thread, kept with the model, and read from there by every file and thread after, where it was parsed every time it was asked. Nothing's kept until it's asked for, and then only the texts asked, so a caller that gives no model pays nothing for it, and one that asks a few texts of it pays for those alone; the model keeps as many texts as it has rows, near enough, more than its rows' cells hold, and past that a text it hasn't is parsed as before and not kept, so what's kept is bounded by the model. What's kept is every text asked through a `FileCx` given the model, first come, a caller's own as well as the rows', so a caller's texts take room from the rows' and are kept as long as the model is: `Grammar::embedded()`'s for the process, shared by every file and thread. The docs of `FileCx::grammar`, `Grammar` and `Grammar::embedded`, and the README, say so, and the README's example gives its `FileCx` the model. `FileCx::since` reads a SinceVersion cell as `since` does, under the extensions the `FileCx` is checked under and through its model: a `Since` is a file's, as its extensions are. Every answer is the same with the model given and without, a predicate that doesn't parse included, and `FileCx` and `Grammar` are `Send` and `Sync` as before; `FileCx`'s `Debug` shows the model it's given.
- **A kept predicate's unsupported function found once.** `holds_fully` reads which function of a predicate kept through the model isn't one it evaluates, the first in it, as it's kept, with its parse, where it looked through the parse for one at every call. A predicate it parses afresh is looked through as before. Every answer is unchanged.
- **A kept predicate found by a quicker hash.** A text asked through the model is found among those kept by rustc's Fx hash, from the rustc-hash crate (MIT OR Apache-2.0, no `unsafe` code, no dependencies of its own, without its default features), where std's SipHash, keyed afresh for each model, found it: the texts are the model's rows' and the caller's own, never a file's, and the search for one ends at the first free slot or the slots' count, whatever they are. Every answer is unchanged.
- **Errors.** `Grammar::load` gives a `grammar::Error` when a model doesn't read: its folder, or a table in it, that can't be read, a table's name that isn't UTF-8, no tables, or a rule of the model's files a table breaks, a `grammar::TableError`, after the table's file and line. `predicate::parse` gives a `predicate::Error`: the predicate, then what stopped the parser, and where when it knows. Each derives `Display` and `std::error::Error` with thiserror, `#[non_exhaustive]`; its `Display` is the whole message and none has a `source`, a std error under one being a field, said after `: `.
- **Extensions.** `extension::declared` gives the extensions a file declares, as the model names them, from its trailer's `/Root`, what its XMP metadata claims, given as `extension::Claims` (`#[non_exhaustive]`, each value as the metadata has it, filled from `Default`), and a closure that gives the object a reference names, as its own; `Grammar::extensions` every extension a model names, and `extension::ISO` ISO's by number.
- **From pdf-lint.** These are pdf-lint 0.2.0's `grammar`, `predicate` and `extension` modules and the model, what they do unchanged, which pdf-lint re-exports where they were; which model a check reads stays pdf-lint's, so `grammar()`, `use_model` and `grammar::NAMED` aren't here, `Grammar::embedded()` gives the embedded model as a `&'static Grammar`, read once, where it gave an owned `Result<Grammar>` read anew at each call, and `extension::named()` is `Grammar::extensions`, so a model `Grammar::load` reads can be asked too; `Grammar::load` and `predicate::parse` give the typed errors above, each saying what pdf-lint's anyhow errors said, word for word, so the crate depends on pdf-objects and thiserror (and twox-hash, for the model's hash), not anyhow; `extension::declared` takes the catalog and the metadata in place of pdf-lint's `Source`, so the crate depends on pdf-objects' types alone, `fn:IsHexString` reads the string's own `Form`, unknown when it has none, where pdf-lint's `Cx` asked a `hex` closure by the string's place, and `predicate::TOLERANCE` is public. `predicate::SUPPORTED` and `extension::ISO` are `&[...]`, not arrays of a fixed length, and `predicate::Expr` is `#[non_exhaustive]`, so a function, an extension or a form of predicate can come without a breaking release; a `Cx` is made from a `FileCx`, one a file, over any resolver, its fields private, where pdf-lint's was a literal of public fields beside caches its caller held (`predicate::{Fields, Structure, Trees}`, not here), so a name tree is read once a file and not once a row, and is kept by where its root was written and its number, not where it's kept in memory, and the structure tree's content items and a row's container are known by their numbers, or without one by where they were written, where pdf-lint's knew them by address (`Cx::id` gives the container's number); `Cx` has two lifetimes, the row's borrow and the file's, and its setters, `FileCx`'s too, are `#[must_use]`; `Grammar`, `FileCx` and `Cx` have `Debug`; and `pdf_objects` is re-exported, so its types can be named at the version this crate takes. Rust 1.85 builds it.
- **Tests.** Every table of the embedded model reads, and its hashes are the references'; every predicate in it parses and prints back as written, with a census of its functions; each supported function means what INTERNAL_GRAMMAR.md says, on the model's own cells where it has them; the extensions declared, and every one the model names found; XXH64 against the reference's values and xxHash's own sanity check; each error's words, every rule a table breaks, a folder that doesn't load and each way a predicate doesn't parse; a name tree read once a file, and kept by where its root was written and its number, two roots at one span among them; the content items known by number or by where they were written, an object stream's two objects at one offset among them; a `FileCx` over a closure, by reference, as a `dyn Fn` and boxed, each read as one over any resolver, `Send` and `Sync` over a `Sync` one, and shared by eight threads, each reading each tree at most once and saying what one alone does; what a model keeps parsed each what parsing its text again gives, an error too, every function saying the same of every row of every table with the model given and without, each text parsed once through it and every time without, a model whose predicates don't parse answering through it as without, a text of no row kept as a row's is, a text past the model's room parsed each time and not kept, the parses made only once a `FileCx` given the model asks, and eight threads asking one text parsing it once; and the README's example as a doctest.
