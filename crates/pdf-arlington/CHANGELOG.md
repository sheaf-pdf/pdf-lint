# Changelog

## 0.1.0-alpha.1 (unreleased)

The first release, and an alpha: until a release says it's stable, any alpha may change the API, each saying here what changed and how code follows. A crate that depends on an alpha names it exactly, `=0.1.0-alpha.1`: cargo's default, `0.1.0-alpha.1`, takes any later alpha of 0.1.0 too. A type is exhaustive on purpose where a caller matches every variant and wants the compiler to check it, and `#[non_exhaustive]` where the model or its language may add to it, or where it's read by its fields, each one's doc saying which (below). The crate is Apache-2.0 alone, as the model it embeds is, whose `LICENSE` and `NOTICE.txt` are in its package. Its code is pdf-lint 0.1.0's `grammar`, `predicate` and `extension` modules and the model, which pdf-lint re-exports where they were: "From pdf-lint", below, says what a user of those meets.

- **The model.** The Arlington PDF Model's `tsv/latest` at `d148fee` (`COMMIT`), embedded by `build.rs`, with the cells corrected where it contradicts ISO 32000-2 or the reference it cites (`model/corrections.tsv`, `grammar::corrections`) and the rows and tables added that a reference defines and it lacks (`model/additions`, `grammar::additions`); the build stops when upstream has changed a corrected cell or has an added row itself. `Grammar::embedded()` reads it once, the first time it's asked for, and gives it as a `&'static Grammar`; `Grammar::load` reads a checkout whole, a model its caller holds, as the crate chooses none. `Grammar::table` finds a table by its name, and `Grammar::tables` gives every table in order of name as a `grammar::Tables`, an iterator of its own type, so it can be named in a signature and held in a struct: `Clone`, read from either end (`DoubleEndedIterator`), knowing how many are left (`ExactSizeIterator`, which its `Debug` gives) and giving none after its last (`FusedIterator`), its `fold` and `rfold` one pass.
- **The model's name.** `Grammar::digest` is what names a model, as pdf-lint's reports give it: a `grammar::Digest`, the SHA-256, by RustCrypto's sha2, of each table's file in byte order of the files' names, its name (`Catalog.tsv`), a newline and its bytes, which `sha256sum` works out over a `tsv/latest` folder by the loop its doc gives. The embedded model's, of its corrected and added tables, is `2bf6c3ab3fb4783fec94c0d6bdec719117128719259e4f994b8574e0d48f83bc`, and upstream's at the same commit `3493c24c602b0637685e453bbb01cc16f1aee2aba8cbfaa0bf336426b17d2c1b`. `Digest` is `Copy`, `Eq`, `Ord` (by its bytes, first to last) and `Hash`, its 32 bytes by `as_bytes`, and `Display` and `Debug` write it as 64 lowercase hex digits. A `Grammar` is `PartialEq`, `Eq` and `Hash` by it, what it keeps of the predicates asked through it no part of what it is, so two models are equal when their tables' files are, byte for byte, as SHA-256 is made so that no two inputs that differ can be found with one digest; clippy's `mutable_key_type` warns of a set of `&Grammar`, reading the lock those predicates are kept behind as a key that can change, where neither `Hash` nor `==` reads it, and a map keyed by the digest is keyed alike. A table whose name holds a tab, a line feed or a carriage return, which the hash would read as a table's text, doesn't load (`grammar::Error::Separator`), and `Grammar::load` refuses it before it reads the file: so no two models that load hash the same bytes.
- **The tables.** A `Table` per object and a `Row` per key or element, upstream's 12 columns (`HEADER`), the Type cell split into its `ArlType`s, a cell with an item per type into those items, and the version predicates around a type, a value or a link kept beside it (`Wrapped`, `Wrap`, `WrapFn`). `Table::row` finds the row at a key or an index (`At`), a repeating set's or the wildcard's where no other is, and `Table::repeating` gives the repeating rows. `ArlType::ALL` and `WrapFn::ALL` give every variant once, in the order its enum lists them, as `&[...]`, so a type or a wrapping predicate can come without a breaking release; `ArlType::name`, `ArlType::named` and `WrapFn::name` read them by the model's names. `grammar::version` reads a version as the model writes it.
- **The predicates.** `predicate::parse` reads the language in the cells, which every predicate in the model prints back as; `required`, `holds`, `holds_fully`, `required_value`, `ignored`, `reference`, `since` and `gate` evaluate a cell on an object where it sits, a `Cx`, made for each row by its file's `FileCx`: the trailer, the version, what gives the object a reference names, the file's length and the extensions it's checked under, and what the predicates read of the file as a whole, kept inside it once read (its name trees' keys, its structure tree's content items, its form's fields' names). `FileCx<'a, R>` takes any of pdf-objects' `Resolve` as its resolver, a map of objects and a closure (through pdf-objects' `resolve_fn`) among them, its type `R`, whose default, `FileCx<'a>`, is one over any resolver, a `dyn Resolve`, as a `Cx` reads through it: so `&FileCx` in a signature takes a reference to one over any resolver, and one kept is kept by its resolver's type, or boxed (`Box<FileCx>`). An object the resolver gives none for is null, whatever the reason: over a reading by position, one whose bytes the source failed to give, in that row and in the form's fields and the structure tree read then. pdf-structure's `Reading::failed_resolves` counts those, for a caller to learn that some were. `fn:InNameTree` alone asks why (`Resolve::try_resolve`), of each reference on the way to its name tree and in it, the row's own value aside: where one doesn't read, by a cap, a password, damage or the source, or a chain of references runs past those a value is followed through, the tree isn't read whole, as pdf-semantics' `tree::names` has it, and a key its readable part doesn't hold is unknown, not false; a tree is kept as it was read, not whole for a source's failure too, so a caller whose source may give the bytes if asked again asks through another `FileCx`. It's `Send` and `Sync` when its resolver is, what it keeps read once and stored behind a lock, the first stored kept, so one a file is shared across threads, each making its rows' `Cx`s; a `Cx` resolves through it as a `dyn Resolve`, so its type names no resolver. A name tree is kept by where its root was written and the number of the object its entry names, and read again each time when it's known by neither. The structure tree's content items, which `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems` read, know each object an item names by where it was written and, when a reference names it, its number, and a row's container by the number `Cx::id` gives, or without one its own span: an indirect object by its number alone, as an object stream's header can start two objects at one offset, or one inside another, and an object written directly is never an indirect one; a container that can't be told apart from an item that could be it is unknown, never false. Spans are places in one file's bytes, so an object copied from another file is given its number, or its spans dropped (pdf-objects' `Object::unplace`). The 41 functions of `SUPPORTED` are evaluated, `fn:IsFullyQualifiedFieldName` among them, which this crate defines for the corrections; any other, or a value that can't be read, comes to `Truth::Unknown`, saying what's in the way, and never nothing: a text that doesn't parse, or isn't the call its cell asks for, by itself as written, and an empty one by `an empty predicate`, as `Reference::Unknown` and `Since::Unknown` are.
- **The trees' caps.** `predicate::Limits`, at the root too (`#[non_exhaustive]`, `Copy`, `Eq`), holds the caps a file's trees are read under, set on a copy of `Limits::DEFAULT` (its `Default`) and given to a file by `FileCx::limits`: how deep and how many nodes of a name tree are read (`tree_depth`, 2,048 levels by default, and `tree_nodes`, 100,000), each node once and each `/Kids` and `/Names` array once, however many nodes hold it, so its depth costs nothing its nodes and the file's arrays don't; how deep and how many of the form's fields, an array and a field each a level (`field_depth`, 2,048, and `field_nodes`, 100,000), each once, and how many bytes of their fully qualified names are made (`field_bytes`, 16 MiB), each counted before it's made, as a field's name is its parent's, a period and its own, so a deep form of long names makes far more than it holds; and how deep the structure tree is read (`structure_depth`, 8,192) and how many of its dictionaries, each read once, and of the kids of an array read again, under a page other than those it's been read under (`structure_nodes`, 1,000,000), as an array is read once under each page it's reached from, its marked-content identifiers on that page: so a `/K` array that holds itself is read once, and one many pages' elements share costs no more than the cap. Past one, what's left isn't read, and a key, a name or an item the part read doesn't hold is unknown, never false. How many references a value goes through to its object, 32, is a constant, not a cap a caller sets: past it a value is null wherever it's read but on the way to a name tree or in it, where the tree isn't then read whole; that null is a guess, which a lowered cap would make common.
- **A cycle told.** `fn:NoCycle`, which the model asks of an object stream's `/Extends`, is evaluated: the row's key followed from its container through each object its value refers to is true where it ends (at an object without the key, or whose value isn't a reference, or names no object), false where it comes back to an object met on the way, the container among them, known by its number where `Cx::id` gives it, else by where it was written, and unknown past as many objects as a value goes through to its object.
- **The pages.** `fn:NumberOfPages` and `fn:PageProperty`, which the model asks of a target dictionary's `/P` and `/A`, are evaluated over the pages a `FileCx` is given, in order, each its dictionary as the resolver gives it (`FileCx::pages`, as a page tree's walk by ISO 32000-2's rules gives them): `fn:NumberOfPages()` their count; `fn:PageProperty(page, path)` the page at an index from 0, or the one a reference resolves to, the path walked from its dictionary as any path is, `fn:ArrayLength` taking it, and a key after an array in it each element's, so `@A==fn:PageProperty(@P,Annots::@NM)` holds where one of the page's annotations has that `/NM`, doesn't where none has, and can't be told where one's can't be compared. A page named by a string (a named destination), an index past the pages, a reference to no page, or the pages not given, can't be told; nor can either function in a row whose `parent::` is a target dictionary (one with `/R`, where an action has `/S`), a target under another's `/T`, whose pages are another document's (ISO 32000-2, 12.6.4.4).
- **The colorants and the fonts.** `fn:HasSpotColorants` and `fn:HasProcessColorants`, which the model asks of a DeviceN space's attributes (`/Colorants`, `/Process`) of the space's names (`parent::1`), and `fn:KeyNameIsColorant`, which it asks of a Type 5 halftone's other keys, are evaluated by what a colorant's name says of it, read as pdf-color reads it (`Colorant::of`), so the crate depends on pdf-color too: a name is a process colorant where it's one of the four of CMYK; a spot colorant where it's any other but `All` and `None`, which name none (ISO 32000-2, 8.6.6.4), and but those the attributes' process dictionary lists among its `/Components`, which are the space's process colorants (8.6.6.5), so an NChannel space over an RGB process naming `Red`, `Green` and `Blue` it lists is asked no `/Colorants`; each names through its references, true where one is, false where each element is a name and none is, unknown where one isn't a name. A halftone's key names a colorant where it's any name but `All` and `None` (10.6.5.6). Before PDF 1.6, `/Colorants`' cell has its version predicate vacant, which leaves the function alone, as the evaluator reduces every cell: there a spot colorant asks it of any DeviceN space. `fn:FontHasLatinChars`, which the model asks of a font descriptor's `/CapHeight` (9.8.1, Table 120), is evaluated over what a `FileCx` is told of the fonts (`FileCx::latin`, a `Latin`, `Clone`, filled by `insert` and read by `get`, re-exported at the root beside `FileCx`): which descriptors' fonts have Latin characters, as only a reader of the fonts can say, each descriptor known by its number, else by where it was written, as the structure tree's content items are, and true where one said of twice has them by either; one not said of, or with nothing given, can't be told.
- **The model's predicates parsed once.** `FileCx::grammar` gives a `FileCx` the model its rows are of, and `required`, `holds`, `holds_fully`, `reference`, `required_value` and `ignored` then read a predicate of the model's rows through it: each text they parse from a row's cells, as the model splits them (its SinceVersion but a version, its Required and IndirectReference but `TRUE` and `FALSE`, each SpecialCase and each PossibleValues item), is parsed the first time a `FileCx` given the model asks, on whichever thread, kept with the model, and read from there by every file and thread after, with the first function in it `holds_fully` doesn't evaluate, where without the model each is parsed, and looked through for one, every time it's asked. Nothing's kept until it's asked for, and then only the texts asked, so a caller that gives no model pays nothing for it, and one that asks a few texts of it pays for those alone; the model keeps as many texts as it has rows, near enough, more than its rows' cells hold, and past that a text it hasn't is parsed as without it and not kept, so what's kept is bounded by the model. What's kept is every text asked through a `FileCx` given the model, first come, a caller's own as well as the rows', so a caller's texts take room from the rows' and are kept as long as the model is: `Grammar::embedded()`'s for the process, shared by every file and thread. A text is found among those kept by rustc's Fx hash, from the rustc-hash crate (MIT OR Apache-2.0, no `unsafe` code, no dependencies of its own, without its default features): the texts are the model's rows' and the caller's own, never a file's, and the search for one ends at the first free slot or the slots' count, whatever they are. The docs of `FileCx::grammar`, `Grammar` and `Grammar::embedded` say so; the README says a `FileCx` given the model keeps what it parses across files and threads, and its example gives its `FileCx` the model. `FileCx::since` reads a SinceVersion cell as `since` does, under the extensions the `FileCx` is checked under and through its model: a `Since` is a file's, as its extensions are.
