# Changelog

## 0.1.0 (unreleased)

- **Dates.** `date::Date` (ISO 32000-2, 7.9.4), its fields private so that it always writes as a date: `Date::read` reads one, or gives a `DateError` (`#[non_exhaustive]`, thiserror): `NoPrefix`, `NoYear`, or `OutOfRange` naming its `Field`. A field not written is none (`month`, `day`, `hour`, `minute`, `second`, `offset`), and `month_or_default` and the like give 7.9.4's default for it. `Offset` is `Utc`, `Ahead` or `Behind`. `Date::quirks` says what a reading read past, a `Quirk` (`#[non_exhaustive]`) each: hours without a sign, an offset before the fields it follows (whose fields then take their defaults), `Z` with an offset other than zero, an apostrophe where it doesn't belong or missing, 1.7's terminating apostrophe, a lone digit, what follows the date, and a day its month hasn't.
- **Dates written and built.** `Date::write` writes 7.9.4's form of the fields, never the bytes read, so reading it back gives the same fields and no quirk but a day its month hasn't, which is in the clause's range and is kept. `Date::new` and `with_month`, `with_day`, `with_hour`, `with_minute`, `with_second` and `with_offset` build one, each in its range and after the field before it (`DateError::OutOfOrder`), a day being one its month has.
- **The `clock` feature,** on by default, on chrono without its default features: `Date::from_unix`, a count of seconds as a date in UT, none before year 0 or past 9999, and `Date::now`. A crate that only reads and writes dates leaves it out, and chrono with it.
- **Text strings.** `text` is pdf-objects' module, re-exported.
- **Name and number trees.** `tree::names` and `tree::numbers` (ISO 32000-2, 7.9.6 and 7.9.7), iterators over a tree's entries in the order it's written, a node's own then its kids', each key and value borrowed from what the resolver keeps, the value as written, reading only what's asked for. Each node or array reached by reference is read once, so a loop ends and says so (`Fault::TreeRepeated`). `Names::whole` and `Numbers::whole` say whether anything was left unread: a node past `Limits::tree_depth` or `Limits::tree_nodes`, a kid that's no dictionary, an entry that isn't an array, a key unread or of another type, an odd last key, an object that doesn't read. `into_sink` gives the sink back.
- **Trees written.** `tree::write_names` and `tree::write_numbers`: one root holding every entry, sorted, a key given twice or a value that's a stream refused (`TreeError`, `#[non_exhaustive]`, thiserror).
- **Faults.** `Fault` (`#[non_exhaustive]`, thiserror), one enum for the crate, owning nothing, each variant naming its clause; `Place`, the object it's in and where it was written; `Sink`, with `()` dropping them and wanting none, so what only a checker wants isn't read: a tree's `/Limits` and the order of its keys are looked at only for a sink that wants faults, and what's read is the same whatever the sink.
- **Caps.** `Limits` (`#[non_exhaustive]`), `Limits::DEFAULT`: a tree's depth, 32 levels below its root, and nodes, 100,000.
- **`follow` and `catalog`.** `follow`, a value's references followed under 32 hops, null none, as far as the resolver says; `catalog`, a trailer's `/Root` followed. A walk reads through `Resolve::try_resolve`: an object past a cap the reader reads under, that takes a password, or whose bytes the source didn't give ends it with an `Unreadable`; a damaged one is `Fault::Damaged`, and the walk goes on. `Dict`, `Object`, `ObjectId`, `Resolve`, `Span`, `Unreadable` and `Why` are pdf-objects', re-exported.
- **Tests.** Unit tests for each field's range at its edges, every quirk, each error, the order fields are set in, the writer's forms, every short string of a date's pieces read, written and read back, and seconds read as a date at the ends of the years a date can hold; for trees, each fault and what it does to `whole`, loops and repeats, each cap at its edge, what's read and when, each kind of failure at each place in a tree, each over a closure, a reading in memory or by position and a document, and written trees read back through the writer and parser.
- **A fuzz body and target** (`just fuzz semantics`): any bytes as objects, each tree walked the same whatever the sink, what a plain recursive walk gives at any depth, within a cap of nodes, and written, read back; any bytes as a date; any bytes as a file, its trees the same over a reading and its document. Three stable unit tests run it.
