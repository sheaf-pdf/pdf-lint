# Changelog

## 0.1.0-alpha.1 (unreleased)

- **The objects.** `Object`, a `Value` (null, boolean, integer, real, name, string, array, dictionary, stream, reference) and where it was written, a `Span` of the file's bytes or of a stream's decoded data, an object stream's for an object in one, when the reader knows. `Value::Stream` holds a `Box<Stream>`, so that a value of any other kind isn't a stream's size. A `Dict` keeps its entries as written, in order, a key written twice and each key's span among them: lookups take a key's last entry, `duplicates` gives the others. A `Str` is its bytes; or text a reader decoded without saying from which encoding; or ciphertext it didn't decrypt. A string keeps its `Form`, literal or hex, beside its `Str` (`Value::String(Str, Option<Form>)`): none for one built without choosing (`Object::string`, `Object::bytes`; `Object::hex` chooses hex) or read by a reader that doesn't say. `dict!` builds a dictionary from keys and values. `Span` is `#[non_exhaustive]`, made by `Span::new`, so a field can come without a breaking release.
- **An id is a struct.** `ObjectId` is `struct ObjectId { number: u32, generation: u16 }` (ISO 32000-2, 7.3.10), where it was the pair `(u32, u16)`: `Copy`, ordered and hashed by number and then generation, as the pair was, so a set of ids iterates as it did; eight bytes, as the pair was; built by `ObjectId::new(n, g)`, a `const fn`, or a literal; written by `Display` as a file writes it, `12 0`, so `format!("{id} R")` is a reference and `format!("{id} obj")` a header, and `Debug` the derive's. A pair converts both ways through `From`, for an object model that spells its ids so. Code follows: `id.0` is `id.number`, `id.1` is `id.generation`, `(1, 0)` is `ObjectId::new(1, 0)`, a closure `|(n, g)|` is `|id|` reading `id.number` and `id.generation`, and `dict! { "Root" => (1, 0) }` is `dict! { "Root" => ObjectId::new(1, 0) }`.
- **Faults, told with where they are.** `fault`, a module, holds `Sink<F>` and `Place` for every reader of a file's objects that tells what it reads past: `Sink::fault(at, fault)` takes the reader's own fault type `F` and its `Place`, the numbered object it's in and where it was written (`#[non_exhaustive]`, made by `Place::new`, a `const fn`); `Sink::wants`, true unless a sink says otherwise, says whether faults are wanted at all. `()` drops them and wants none, so a reader asked for none looks for none; a sink borrowed, `&mut S` or `&mut dyn Sink<F>`, is one; a `Vec<(Place, F)>` keeps each with its place, in the order told. Generic over the fault, so one sink type takes several readers' faults by implementing `Sink<A>` and `Sink<B>`. pdf-semantics', pdf-color's and pdf-fonts' faults are told to it, where each crate had a `Sink` and a `Place` of its own, the same three times over. The parser keeps its own `parse::Sink`, its faults borrowing the data parsed, each at a `Span` alone. `fault` is reached as a module, not at the root, so that `fault::Sink` and `parse::Sink` each say which they are.
- **A stream's data, decoded.** `Streams`, at the root and in `streams`, is what gives a stream's data, decrypted and decoded through its filters, as a viewer takes it: `decoded(id, limit) -> Result<Cow<[u8]>, Unreadable>`, at most `limit` bytes, what decoded of a stream that decodes in part unless the limit stopped it, borrowed where the reader holds the data decoded and owned where it's decoded for the call; or why there's none, in a resolver's words. A reference to one is one (`&S`, `&dyn Streams`). `WithStreams`, at the root and in `streams`, a resolver and a function from a stream's number and a limit to its data, `Result<Vec<u8>, Unreadable>`, as one, `Resolve` by the first and `Streams` by the second, `Copy` where they are; what the function gives is given as it is, for the caller to hold to the limit. Both were pdf-fonts', where `Streams::decoded` gave a `Decoded`. `Why::Filter`, a stream whose filters the reader doesn't decode: through a filter it doesn't take, as an image's data may be (ISO 32000-2, 7.4.1), its data there as written, or with a `/Filter` or `/DecodeParms` it can't take as written; only a stream's data says it, never a resolver, and as `Why` is `#[non_exhaustive]` a match on it compiles as it did. `Why::Detached`, a stream's data that a reader doesn't hold and has nothing to read from, as a document read whole alone hasn't the file's bytes (below); only a stream's data says it too.
- **Editing.** An `Object`'s value is private: `value` reads it and `into_value` takes it; `value_mut`, `as_dict_mut`, `as_array_mut` and `as_stream_mut` change it, each an edit, which drops its span, and as a value inside another is reached through each value that holds it, theirs go too, while a value no edit reached keeps its own. `as_written_mut` changes it and keeps the span, for a reader that turns a value into what the same bytes stand for, as decrypting a string does. `as_bool`, `as_bytes` (a string's bytes), `as_array` and `as_stream` read by kind, beside `as_name`, `as_integer`, `as_number`, `as_dict` (a stream's dictionary too) and `as_reference`. An `Object` comes from an `ObjectId` (a reference), any integer type of 32 bits or fewer and `i64`, an `f32` (the f64 nearest its shortest decimal, so `0.1f32` is 0.1) and a `String` (a name), beside the rest. A `Dict` is changed by `set`, `push`, `get_mut` and `iter_mut` (a key's last entry) and `remove`, which keeps the other entries in order and gives the value of the last entry it removed, and `remove_duplicates`, which removes the entries a later one overrides; `has_type` and `type_name` read its `/Type`; it's collected from keys and values, each pushed, so a key given twice is kept twice; and a `for` over a `&Dict` is `iter`, whose iterator is `object::Iter`. Its lookups allocate nothing for a dictionary of up to 32 entries. A real's spelling is the bytes its span names.
- **A stream's data.** `Stream::data` is a `Data`, `#[non_exhaustive]`: `At`, where a reader read it; `Bytes`, in memory, as `Stream::new` and `set_bytes` give it, setting `/Length`; or `Unplaced`. `Data::at` and `Data::bytes` read it. An edit of the stream's dictionary leaves its data as it was. `Stream` is `#[non_exhaustive]` too, made outside the crate by `Stream::new`, `Object::stream` or from `Stream::default()`.
- **Text strings.** `text::decode` decodes a text string by its byte order mark, UTF-16BE, UTF-8 or none for PDFDocEncoding (Annex D, `text::pdf_doc_char`), and says each `Quirk`, where it departs from the spec: UTF-16LE's mark, read as PDFDocEncoding; an odd last byte, left out; a lone surrogate or bad UTF-8, read as U+FFFD; a byte PDFDocEncoding leaves undefined. `Quirk` is `#[non_exhaustive]`, so a quirk can come without a breaking release. `decode` doesn't take out language escapes (ISO 32000-2, 7.9.2.2.2). `text::decode_with` reads by `Rules`: ISO 32000-2's, which is `decode`; or PDFium's, as of chromium/8125, where `FF FE` is UTF-16LE's mark (`Encoding::Utf16Le`; `Encoding` is `#[non_exhaustive]` now, so that it could come), language escapes come out of UTF-16 and UTF-8, one with no close taking out the rest (`Quirk::UnclosedEscape`), bytes that aren't UTF-8 are left out, a sequence longer than it need be read as what it spells, and PDFDocEncoding's undefined bytes are U+0000; a surrogate alone, which a `String` can't hold, is U+FFFD by both. Each departure is said as `decode` says it.
- **Text strings written.** `text::encode` gives a text's bytes as a text string that reads back as that text, under `decode` whatever the text: as they are where PDFDocEncoding reads them back so, ASCII but for 0x18 to 0x1F and 0x7F, and otherwise UTF-16BE after its mark. `Object::text` is that string, literal as it is and hex as UTF-16BE, and what a literal must escape reads back. `text::encode_as` writes PDFDocEncoding through `pdf_doc_char`'s table, UTF-16BE, or UTF-8 after its mark, PDF 2.0's, as the caller asks, and refuses what wouldn't read back (`text::Unencodable`, `#[non_exhaustive]`, derived with thiserror): a character PDFDocEncoding hasn't; a text whose bytes there would start as a mark, `þÿ`, `ï»¿` or `ÿþ`; U+001B in the other two, where it starts a language escape; and UTF-16LE, which PDF hasn't. `encode` writes that U+001B all the same, as UTF-16BE, where a reader that takes escapes out takes it and what follows.
- **Versions.** `Version`, read from a header's or a catalog's text, displayed as `1.7`, and ordered.
- **The parser.** `parse::Parser`, on pdf-tokenizer, reads a value, or an indirect object, from a file's bytes or an object stream's decoded data (`in_stream`), from any offset, kept as given past the data's end; each value placed, each string with the form it was written in, strings read as ciphertext when asked (`ciphertext`). What it reads past is a `Fault`, borrowing the data, told to a `Sink` with where it is, which may keep it as it is; `()` is the sink that drops them, and a sink borrowed, `&mut dyn Sink` too, is one. What stops a value is an `Error`, with where, and leaves the parser where it was. An indirect object is read in steps, `header`, `body` and, for a stream, `stream`: `body` gives a stream's dictionary and both extents its data may have, `declared` by a `/Length` the caller resolves and `scanned` up to `endstream`, and the caller passes `stream` the one it chose. A window of a file (`Parser::window(base, last)`): the bytes a reader by position has read from an offset on, which the parser's spans, `offset()` and every error's place then count in the file, from `base`; where the window isn't the file's last, a call whose read reaches its end (a token reaching it, none before it where one was looked for, a stream's data or the extents it was given running to it) is `Error::Short`, as more of the file could change what it reads, and the caller reads again with more, the faults said before it said again. Read so, it reads as it would with the whole file. `Parser::at` reads its data as a whole file. `StreamHead` remembers when `declared` or `scanned` ran to a window's end, for `stream`. `Parser`, `StreamHead` and `Body` are `Send` and `Sync`. It reads under `Limits` (`Parser::limits`), `#[non_exhaustive]`, so set on a copy of `Limits::DEFAULT`: arrays and dictionaries nested at most `nesting` deep, `NESTING` (256) by default (`Error::Nested`), and at most `values` values in one call, keys among them, 2^25 by default (`Error::Values`). Only a value reaches them, and either error says where it starts; a token that can't start a value, where one should be, is the error it is under any limits. A name without `#`, which has nothing to decode and nothing to say, is its bytes after the `/`, read without walking its pieces. `Fault` and `Error` are `#[non_exhaustive]`, and both `std::error::Error`s, derived with thiserror.
- **ISO 32000-2's rules, or PDFium's.** `Parser::rules(Rules)` (`Rules`, pdf-tokenizer's, `pdf_objects::pdf_tokenizer::Rules` through the crate, below; pdf-tokenizer 0.2 required): ISO 32000-2's lexical rules by default, as before, or PDFium's, as of chromium/8125, a development snapshot of PDFium, any other rules read as ISO's. Each call reads by a tokenizer with the rules fixed in its type, chosen once a call, so ISO's path costs what it did. By PDFium's rules, tokens are cut where PDFium cuts them (0x80 and 0xFF white-space, a word of digits, signs and points a number, a hex string to its `>`), every tokenizer the parser makes following them, a stream's `endstream` after its declared data among them; and each token is read as PDFium's object parser reads it, held as this crate holds values: a number word as the integer PDFium holds (unsigned or signed in 32 bits, 0 outside them) or the decimal a real starts with, at 64 bits (`--5` 0, `1.2.3` 1.2, `4294967296` 0, `4294967295` itself); a name's `#` before any two bytes as an escape, a byte that's no hex digit as 0; a literal string's CR, and CR LF, as written; a hex string's digits paired over any other byte; a number or a name longer than 256 bytes as its first 256, a name's `/` among them. A reference's and a header's integers are their tokens' values, in this parser's grammar, `n g R` and `n g obj`, under either. Where ISO 32000-2 reads such a token otherwise, a fault, each naming its clause: `Fault::Number` (a number only by PDFium's rules, a keyword to ISO), `OutOfRange` (an integer outside PDFium's 32 bits, read as 0), `HexString` (a byte that's no hex digit), `StringCr` (a CR written in a literal string), `Long` (past 256 bytes); and `Fault::Name` where ISO's rules tell it, its doc now saying how PDFium reads such a `#`. 0x80 or 0xFF read as white-space isn't told. `Sink::wants`, true by default, `()` false and a borrowed sink forwarding it: a sink that wants no faults is told none, and the checks that read a token a second way to find one don't run for it.
- **On pdf-tokenizer's passes.** The parser passes white-space and comments with pdf-tokenizer's `next_significant`, which makes no token of them, and searches for a stream's `endstream` through `data_until`, now memchr's search: the same objects, faults and errors, read faster.
- **Each token read once where it can be.** An array's element is read from the token the array looked at for its `]`, where it was tokenized again; and after a number, `R` is looked for only where an integer follows it, where the token after that was read whatever came. The same values, faults and errors, but that a call in a window that isn't the file's last isn't `Error::Short` where only that token reached the window's end, as it can't change what's read.
- **The writer.** `serialize` writes a value as PDF syntax (`write`), or as an indirect object, `n g obj` to `endobj` (`indirect`), which the parser reads back as the same value, under limits that take in its count of values, and a stream as an indirect object: a real in its shortest form that reads back as the same f64, past i64's range too, never with an exponent, its magnitude clamped as Annex C has it (`real`); integers and references in decimal (`decimal`), names (`name`) and strings (`string`) byte by byte, a string in its `Form`, or literal when it has none; a dictionary's every entry, in order, a key written twice included, which ISO 32000-2 doesn't allow (`Dict::remove_duplicates` leaves each key's last); and a stream's bytes as they are, their length its `/Length`, in place of each `/Length` entry or after the others. `indirect_stream` writes a stream whose data is given apart, as it is. What it can't write as the value it refuses, writing nothing (`serialize::Error`, `#[non_exhaustive]`, derived with thiserror): a real that isn't finite, values nested deeper than the parser reads them under `Limits::DEFAULT`, a string read as text or still ciphertext, and a stream whose data isn't in memory.
- **Encrypted as it's written.** `serialize::Encrypt`, an encryptor that every string of an indirect object, a stream's dictionary's included, and a stream's data pass through as the writer writes them, given the object's number and generation: `clear`, asked once an object, leaves it whole in the clear; `clear_key`, asked once a dictionary, leaves an entry so; `string` and `stream` give what's written, as a `Cow`, a stream's data before its dictionary, so its `/Length` is the encrypted data's. `indirect_with` and `indirect_stream_with` write through one, refusing as the writer does or as the encryptor does, with nothing written (`Refused`, the two apart: `Write`, the writer's `Error`; `Encrypt`, the object and the encryptor's error; derived with thiserror, and exhaustive, as each side grows in its own error). `()` encrypts nothing (`Infallible`): `indirect` and `indirect_stream` keep their signatures and bytes, written as through it, by the walk compiled apart with nothing to encrypt, so they run the instructions they did. `write`, a direct object, never encrypts. `indirect_stream`'s data is plaintext, encoded by its dictionary's filters, which `indirect_stream_with` encrypts. No cipher here: pdf-structure implements the trait over pdf-crypt.
- **References resolved.** `Resolve<'o>`, at the root, is what gives the indirect object a reference names, `resolve(id) -> Option<&'o Object>`, none being null. The objects' lifetime is the trait's, not `&self`'s, so that a closure giving borrows of its own is one: every `Fn(ObjectId) -> Option<&Object>` is, by a blanket impl, a `dyn Fn` and a reference or a box of one among them; a type that holds the objects implements it for a reference to itself. A `&dyn Resolve` is one too, for what takes a resolver by value. `try_resolve(id) -> Result<Option<&'o Object>, Unreadable>`, by default what `resolve` gives, says why where the resolver can, as a reader's and a document's do: none when the file hasn't the object, or an `Unreadable` (`#[non_exhaustive]`, made by `Unreadable::new`, derived with thiserror): the object, its `Why` (`#[non_exhaustive]`: `Damaged`, `Limit`, `Locked` or `Source`, and for a stream's data `Filter`, below) and the reader's words. `resolve` itself is as it was.
- **References walked.** `Object::references` gives the ids of the objects a value's references name, nested ones too, in the order written: itself when it's a reference, an array's elements, a dictionary's every entry, a key written twice included, and a stream's dictionary, never its data. It walks with a stack of its own, not by recursion, so a value nested however deeply, as one built in memory may be, walks without overflowing the thread's.
- **References renumbered, and places dropped.** `Object::renumber(to)` names each reference in a value anew, as `to`, a function from the object a reference names to the one it's to name, gives it, or null where it gives none (§7.3.10), the references `references` gives, in its order, `to` asked once each; each it changes is an edit, dropping its place and every holder's, while what it changed nothing in keeps its own, a key and a stream's data theirs; it says whether it changed any. `Object::unplace` drops every place in a value, its own, each value's and key's, and a stream's data's where it was written (`Data::At` made `Data::Unplaced`; `Data::Bytes` kept), for an object of one file put among another's, whose places would be read as that file's; a stream's data is given first as its bytes. Both walk with a stack of their own. The writer names references through a renumbering too, without changing the value: `serialize::Renumber`, implemented by `()`, each as it is, and by any function from an `ObjectId` to an `Option<ObjectId>`, `None` written as `null`; `write_renumbered`, `indirect_renumbered` and `indirect_stream_renumbered` write through one, an indirect object at the number given, which its encryptor is given too, beside its dictionary as held, its references not renumbered, and a stream's `/Length` its data's whatever reference it holds. A renumbering is a function: asked of an id many times, on several threads at once, it gives the same answer, so a numbering made as it's asked is made first and given as a map. The writers without one write as through `()`, by the walk compiled for it, so their bytes and instructions are as they were.

- **A dictionary of more than 32 entries finds its keys written twice in a set made with room for them.** `Dict::iter`, `last_entries`, `duplicates`, `len`, `iter_mut` and `remove_duplicates` of a dictionary past 32 entries put each key in a set to find those written again later; the set is made with room for every key, where it grew as they went in, rehashing what it held each time it doubled. The same entries, in the same order.
- **An escaped name or string is read once.** The parser decoded each name or string that holds an escape twice, once to count its bytes and once into a buffer of that length; it reserves the buffer once, for as many bytes as were written (pdf-tokenizer's `size_hint`: a value is never longer than its bytes), and decodes once, so the buffer's capacity may exceed its length by what the escapes took. A name's faults (`Fault::Name`) are read off the set of its pieces' quirks (`Pieces::quirks`) in one pass, with nothing collected. The same values and faults.

- **The package, checked before a publish.** CI packages the crate as a publish would (`cargo publish --dry-run`, in a target directory of its own made fresh each time, so a stale build can't pass or fail it) and checks what the package holds: `src/`, the README, the CHANGELOG, the manifest and the lock, nothing else, no benchmark among them. The manifest names the crate's documentation (docs.rs) and a fifth keyword, `parser`.
- **pdf-tokenizer is re-exported whole, and `Rules` by name no longer.** `pdf_objects::pdf_tokenizer` is the pdf-tokenizer this crate is built with, so the `Rules` that `Parser::rules` and `text::decode_with` take is `pdf_objects::pdf_tokenizer::Rules`, at the version this crate takes; `pdf_objects::Rules` is gone. A crate whose API names another family crate's types re-exports that crate whole, and only its own types by name, so a type is never reached by two paths that can part at a version. Code that named `pdf_objects::Rules` names `pdf_objects::pdf_tokenizer::Rules`, or `pdf_tokenizer::Rules` where it depends on pdf-tokenizer 0.2 itself.
- **`With` is `WithStreams`.** The resolver and function joined as one, `pdf_objects::WithStreams` and `pdf_objects::streams::WithStreams`, is named for what it joins, objects with their streams' data by the function, as pdf-structure's `WithReading` is a document with its reading; `pdf_objects::With` and `streams::With` are gone. Its shape is as it was: `WithStreams::new(objects, |id, limit| ..)`, `Resolve` by the first and `Streams` by the second, `Copy` where they are. Code follows by the name alone.
- **`Why::Detached`, apart from `Why::Source`.** `Why::Source` said two things: that the source of the file's bytes didn't give them, which asked again may read, and that a reader has no source of bytes at all, as a document read whole alone hasn't, which asked again gives the same, so a caller that asked again on `Source` asked a document for ever. The second is `Why::Detached` now: a stream's data the reader doesn't hold and has nothing to read from, read beside what read the file; `Source` is the first alone. Only what gives a stream's data says `Detached` (`Streams::decoded`), never a resolver, as with `Filter`. `Why` is `#[non_exhaustive]`, so a match on it compiles as it did, its wildcard taking `Detached`: a reader of a `Why` that reads a document alone's answer as `Source` reads `Detached` beside it. pdf-structure's `Document` says it where it said `Source`.
- **Each walk is a type of its own.** `Object::references` gives an `object::References`, and `Dict::iter_mut`, `last_entries` and `duplicates` give `object::IterMut`, `LastEntries` and `Duplicates`, where each gave an `impl Iterator`, so a caller can hold one in a struct or name it in a signature; `Dict::entries_mut` gives the slice's own `std::slice::IterMut<Entry>`, the type it was. Each is fused, the dictionary's walk from either end too, as `Dict::iter`'s `Iter` does, and `Debug`; all but `IterMut` are `Clone`. Each method of theirs and of `Iter` is a hint to inline, as `core`'s own adapters' are, so that a consumer's loop over one is one loop, and `Iter` is fused now too. The same entries and references, in the same order; code that took them as iterators compiles as it did.
- **`Debug` of a parser says where it is, not what it reads.** `Parser`'s and `StreamHead`'s `Debug` are written by hand: where it is, the data's length and how it reads it (`Parser { offset: 12, data: 4000 bytes, base: 0, .. }`), where they were derived and printed the data, which may be a whole file, or an object stream's decrypted data. `Body`'s is derived over them. The values, `Object`, `Value`, `Dict`, `Stream` and `Data`, keep the derived `Debug`, which shows them whole.
- **`text::Text` is `#[non_exhaustive]`.** A decoder's account of a text string, which may say more, such as the languages a PDFium reading takes out with their escapes (ISO 32000-2, 7.9.2.2.2): read by its fields as before, it can't be built or matched without `..` outside the crate.
- **Exhaustive on purpose, and said.** `Value`, `Str`, `Form`, `parse::Body` and `serialize::Refused` are exhaustive, and so are `ObjectId`, `Entry` and `Version`, whose every field is public, each doc saying why: a match on every kind is checked by the compiler, so a new variant or field is a breaking release. What's found in files or may say more is `#[non_exhaustive]`, as the README lists.
