# Changelog

## 0.1.0 (unreleased)

- **The objects.** `Object`, a `Value` (null, boolean, integer, real, name, string, array, dictionary, stream, reference) and where it was written, a `Span` of the file's bytes or of an object stream's decoded data, when the reader knows. `Value::Stream` holds a `Box<Stream>`, so that a value of any other kind isn't a stream's size. A `Dict` keeps its entries as written, in order, a key written twice and each key's span among them: lookups take a key's last entry, `duplicates` gives the others. A `Str` is its bytes; or text a reader decoded without saying from which encoding; or ciphertext it didn't decrypt. A string keeps its `Form`, literal or hex, beside its `Str` (`Value::String(Str, Option<Form>)`): none for one built without choosing (`Object::string`, `Object::bytes`; `Object::hex` chooses hex) or read by a reader that doesn't say. `dict!` builds a dictionary from keys and values. `Span` is `#[non_exhaustive]`, made by `Span::new`, so a field can come without a breaking release.
- **Editing.** An `Object`'s value is private: `value` reads it and `into_value` takes it; `value_mut`, `as_dict_mut`, `as_array_mut` and `as_stream_mut` change it, each an edit, which drops its span, and as a value inside another is reached through each value that holds it, theirs go too, while a value no edit reached keeps its own. `as_written_mut` changes it and keeps the span, for a reader that turns a value into what the same bytes stand for, as decrypting a string does. `as_bool`, `as_bytes` (a string's bytes), `as_array` and `as_stream` read by kind, beside `as_name`, `as_integer`, `as_number`, `as_dict` (a stream's dictionary too) and `as_reference`. An `Object` comes from an `ObjectId` (a reference), any integer type of 32 bits or fewer and `i64`, an `f32` (the f64 nearest its shortest decimal, so `0.1f32` is 0.1) and a `String` (a name), beside the rest. A `Dict` is changed by `set`, `push`, `get_mut` and `iter_mut` (a key's last entry) and `remove`, which keeps the other entries in order and gives the value of the last entry it removed, and `remove_duplicates`, which removes the entries a later one overrides; `has_type` and `type_name` read its `/Type`; it's collected from keys and values, each pushed, so a key given twice is kept twice; and a `for` over a `&Dict` is `iter`, whose iterator is `object::Iter`. Its lookups allocate nothing for a dictionary of up to 32 entries. A real's spelling is the bytes its span names.
- **A stream's data.** `Stream::data` is a `Data`, `#[non_exhaustive]`: `At`, where a reader read it; `Bytes`, in memory, as `Stream::new` and `set_bytes` give it, setting `/Length`; or `Unplaced`. `Data::at` and `Data::bytes` read it. An edit of the stream's dictionary leaves its data as it was. `Stream` is `#[non_exhaustive]` too, made outside the crate by `Stream::new`, `Object::stream` or from `Stream::default()`.
- **Text strings.** `text::decode` decodes a text string by its byte order mark, UTF-16BE, UTF-8 or none for PDFDocEncoding (Annex D, `text::pdf_doc_char`), and says each `Quirk`, where it departs from the spec: UTF-16LE's mark, read as PDFDocEncoding; an odd last byte, left out; a lone surrogate or bad UTF-8, read as U+FFFD; a byte PDFDocEncoding leaves undefined. `Quirk` is `#[non_exhaustive]`, so a quirk can come without a breaking release.
- **Versions.** `Version`, read from a header's or a catalog's text, displayed as `1.7`, and ordered.
- **The parser.** `parse::Parser`, on pdf-tokenizer, reads a value, or an indirect object, from a file's bytes or an object stream's decoded data (`in_stream`), from any offset, kept as given past the data's end; each value placed, each string with the form it was written in, strings read as ciphertext when asked (`ciphertext`). What it reads past is a `Fault`, borrowing the data, told to a `Sink` with where it is, which may keep it as it is; `()` is the sink that drops them, and a sink borrowed, `&mut dyn Sink` too, is one. What stops a value is an `Error`, with where, and leaves the parser where it was. An indirect object is read in steps, `header`, `body` and, for a stream, `stream`: `body` gives a stream's dictionary and both extents its data may have, `declared` by a `/Length` the caller resolves and `scanned` up to `endstream`, and the caller passes `stream` the one it chose. A window of a file (`Parser::window(base, last)`): the bytes a reader by position has read from an offset on, which the parser's spans, `offset()` and every error's place then count in the file, from `base`; where the window isn't the file's last, a call whose read reaches its end (a token reaching it, none before it where one was looked for, a stream's data or the extents it was given running to it) is `Error::Short`, as more of the file could change what it reads, and the caller reads again with more, the faults said before it said again. Read so, it reads as it would with the whole file. `Parser::at` reads its data as a whole file. `StreamHead` remembers when `declared` or `scanned` ran to a window's end, for `stream`. `Parser`, `StreamHead` and `Body` are `Send` and `Sync`. It reads under `Limits` (`Parser::limits`), `#[non_exhaustive]`, so set on a copy of `Limits::DEFAULT`: arrays and dictionaries nested at most `nesting` deep, `NESTING` (256) by default (`Error::Nested`), and at most `values` values in one call, keys among them, 2^25 by default (`Error::Values`). Only a value reaches them, and either error says where it starts; a token that can't start a value, where one should be, is the error it is under any limits. A name without `#`, which has nothing to decode and nothing to say, is its bytes after the `/`, read without walking its pieces. `Fault` and `Error` are `#[non_exhaustive]`, and both `std::error::Error`s, derived with thiserror.
- **The writer.** `serialize` writes a value as PDF syntax (`write`), or as an indirect object, `n g obj` to `endobj` (`indirect`), which the parser reads back as the same value, under limits that take in its count of values, and a stream as an indirect object: a real in its shortest form that reads back as the same f64, past i64's range too, never with an exponent, its magnitude clamped as Annex C has it (`real`); integers and references in decimal (`decimal`), names (`name`) and strings (`string`) byte by byte, a string in its `Form`, or literal when it has none; a dictionary's every entry, in order, a key written twice included, which ISO 32000-2 doesn't allow (`Dict::remove_duplicates` leaves each key's last); and a stream's bytes as they are, their length its `/Length`, in place of each `/Length` entry or after the others. `indirect_stream` writes a stream whose data is given apart, as it is. What it can't write as the value it refuses, writing nothing (`serialize::Error`, `#[non_exhaustive]`, derived with thiserror): a real that isn't finite, values nested deeper than the parser reads them under `Limits::DEFAULT`, a string read as text or still ciphertext, and a stream whose data isn't in memory.
- **References resolved.** `Resolve<'o>`, at the root, is what gives the indirect object a reference names, `resolve(id) -> Option<&'o Object>`, none being null. The objects' lifetime is the trait's, not `&self`'s, so that a closure giving borrows of its own is one: every `Fn(ObjectId) -> Option<&Object>` is, by a blanket impl, a `dyn Fn` and a reference or a box of one among them; a type that holds the objects implements it for a reference to itself.
- **References walked.** `Object::references` gives the ids of the objects a value's references name, nested ones too, in the order written: itself when it's a reference, an array's elements, a dictionary's every entry, a key written twice included, and a stream's dictionary, never its data. It walks with a stack of its own, not by recursion, so a value nested however deeply, as one built in memory may be, walks without overflowing the thread's.
- **From pdf-lint.** These are pdf-lint 0.2.0's `object`, `text` and `version` modules, and its reader's object parser, what they do unchanged (but for `text::passwords`, which is pdf-crypt's `Password::encodings` now; a string's form, which stands in for the parser telling its sink where each hex string is; `Object`'s value, which is private, so that an edit drops its span; `Stream::data`, a `Data` where it was a span; `Value::Stream`, which holds a `Box<Stream>`; and `Dict::remove`, which gives what it removed), which pdf-lint re-exports where they were; each fault and error says what pdf-lint's warnings and errors said, word for word, but `Error::Values` and `Error::Short`, which are new, and a token nested past the limit that can't start a value, which is the error it is, where pdf-lint said it was nested too deep. Rust 1.85 builds it.
- **Tests.** Unit tests for dictionaries as written, values, edits and the spans they drop and keep, the types `Send` and `Sync`, a stream's data, each conversion and accessor, lookups with few entries and many, each text encoding and each quirk, the PDFDocEncoding table and versions; the parser's every fault and error, names without `#`, placing, strings' forms, ciphertext, its limits at the limit and one past, a stream's extents each way, and windows, each of the tests' inputs and random fragments cut at every byte and read from bytes 0 and 1,000,000 of a file, short or read as the whole; the writer's bytes for each kind of value, reals at f64, its round trips through the parser, for random values too (each reading back as the same value and writing as the same bytes again), a key written twice, a stream's data given apart, its every refusal, wherever in a value, and nesting as deep as the parser reads and no deeper; a closure resolving by reference, as a `dyn Fn` and boxed; a value's references in the order written, a key written twice and a stream's dictionary among them, not its data, and a value nested 10,000 deep walked on a thread of 64 KiB; the README's examples, and `Resolve`'s, as doctests; and a fuzz target (`just fuzz objects`), which reads under the default limits or small ones, in a window too, cut where the input chooses, walks what it read's references as a recursive walk does, and writes what it read, reading it back, whose body a unit test runs on random fragments of objects.
