# Changelog

## 0.1.0-alpha.1 (unreleased)

First release. Until `0.1.0` stabilizes, alpha releases may include breaking API changes documented here; depend on the exact version (`=0.1.0-alpha.1`).

### Added

- `Form`, `Form::read`, `Form::read_with`, and `Form::from_dict`: a catalog's `/AcroForm` with its field tree read under `Rules::Iso` or `Rules::Pdfium` (as of chromium/8152), with the form's `/DA`, `/Q`, `/NeedAppearances`, `/SigFlags`, `/XFA` presence, and default resources (`Form::resources`, `Form::font`, `Form::font_names`).
- `Field`, `FieldType`, `FieldKind`, `FieldFlags`, and `FieldValue`: each field with its effective (own or inherited) type, flags, value, default value, default appearance, quadding, and maximum length, and its kind by the rules read under (a button with both the push button and radio flags is PDFium's radio button, ISO 32000-2's push button); `Form::fields`, `Form::roots`, `Form::terminals`, `Form::full_name`, and `Form::find` (a scan that builds no name). A `/V` or `/DV` that reaches nothing (null, or a reference to no object or to null) is an absent one, and the parent's is inherited, as every other inherited entry is read.
- `Widget`, `Widget::annot`, and `Widget::annot_with`: a field's widgets, separate or merged with the field, each read as a `pdf_annots::Annot`.
- `Limits`, `Cap`, `Error`, and `Fault`: caps on the fields and widgets read, the tree's depth, reference hops, and a value's items; a field reached twice is left out, so a cycle through `/Kids` ends.
- `appearance::FieldFont` and `appearance::FieldLayoutFont` (`text-layout`): the font a field's text is drawn in, found by its `/DA` name in the default resources and read with `pdf-fonts` (`FieldFont::find`, `Form::field_font`, or `FieldFont::find_in_catalog`, which reads the default resources from the catalog and nothing else of the form), or a standard 14 font that name falls back to (`FieldFont::standard`), with the resource an appearance names it by (`FieldFont::res`), or the dictionary a caller writes as an object where none can name it (`FieldFont::direct`), and, for its layout, the heights of the face PDFium (as of chromium/8152) draws a standard 14 font in, and no box for a standard 14 Type 1 font that embeds no program.
- `appearance::text`, `appearance::TextField`, `appearance::WidgetLook`, `appearance::Appearance`, and `appearance::Unmade` (`text-layout`): a text field's appearance made from plain data as PDFium (as of chromium/8152) makes it, its background, border in each of the five styles, a comb field's dividers, `/Tx` sequence with its clip, and text (a single line, wrapped lines, comb cells, a password, an automatic size from PDFium's sizes), turned by `/MK /R` through its box and matrix, or why none could be made (a cap passed, no box, a number that isn't finite, the box inside the border among them, a size or box that sets the text further out than `1e35`, which a reader working in `f32` may not place, or a character the font has no code for, never a `?` drawn). The text's color is `/DA`'s nonstroking one alone, a size below `0.0001` is an automatic one, as PDFium takes it, and a color's components are written within `0..=1`.
- `appearance::widget_text`, `appearance::WidgetText`, `appearance::text_for_widget`, and `appearance::MadeText` (`text-layout`): a text widget's appearance from what `Form` reads, its `/DA` the widget's own else the field's, parsed once, and its font kept by the caller across widgets or read for one, with the name `/DA` gives the font (`MadeText::font_name`), which a fallback is added to the default resources under.
- `Limits::text` (the bytes of an appearance's text), `Limits::comb_cells` (a comb field's cells, 1,024 by default, which bound the dividers an empty field's appearance holds), `Limits::fonts`, and `Limits::font_budget`, with `Cap::Text`, `Cap::CombCells`, and `Cap::FontBudget`; `Fault::DefaultAppearance`, `Fault::MissingDefaultAppearance`, `Fault::FontNotInResources`, and `Fault::Font`.
- Features `programs` and `text-layout` (default), `predefined-cmaps`, and `tracing`, each forwarded to the crates beneath; `text-layout` adds the `appearance` module.

### Notes

- A text field's appearance is laid out as PDFium (as of chromium/8152) lays it out, its rules learnt from PDFium's sources (BSD-3-Clause) with no code copied, and held to the appearances PDFium makes for the same fields, recorded as cases. Where it differs, ISO 32000-2's or Acrobat's way is kept, as the README lists: the clip always written, an empty `/Tx BMC EMC`, `/MaxLen` cutting only comb text, a missing font's fallback by its name, the border read from `/BS` over `/Border` at its fractional width and dashed as given, a negative `/MK /R` clockwise, a beveled band over a CMYK background darkened, the last of two `Tf` or two colors in a `/DA`, and a null `/V` inherited.
- Re-exports `pdf-objects`, `pdf-content-streams`, `pdf-semantics`, `pdf-fonts`, `pdf-gfx`, and `pdf-annots` at the crate root. Requires Rust 1.92.
- Never panics on untrusted input, and `Debug` implementations and `tracing` spans never include a field's name or value, a font's name, or an appearance's content; the one exception is `appearance::Unmade::Unencodable`, which names the one character a font couldn't draw, and never one of a password's.
