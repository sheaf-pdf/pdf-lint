# Changelog

## 0.1.0 (unreleased)

- **The reader.** `bytes::read` reads a file from its bytes: the header, `startxref`, the cross-reference tables and streams along their `/Prev` chain, and each object at its offset through pdf-objects' parser, a stream's data by its `/Length` when that ends at `endstream`; where the sections don't read, the objects found by scanning, the trailer saying why. Cross-reference streams and object streams are decoded through pdf-filters, `/Filter` and `/DecodeParms` read as qpdf reads them, a stream to at most 256 MiB (`bytes::STREAM`) and a reading's streams to 1 GiB in all (`bytes::BUDGET`) by default, and the objects read from an object stream placed in its decoded data, which the `Document` keeps. `bytes::read_opened` opens an encrypted file with the passwords given, each a `Password` as typed, tried in each of its encodings in the empty password's place, through pdf-crypt's standard security handler, revisions 2 to 6; `bytes::read` with the empty password. `bytes::read_from` and `read_from_opened` read the file as of a cross-reference section, an update's revision before. What the reader had to choose how to read is a `Warning`, with its object and where.
- **A reading on demand.** `Reading` (`bytes::Reading`, at the root too) opens a file from a `ByteSource`, a slice, a `Vec<u8>` or an `Arc<[u8]>` (or a reference, a `Box` or an `Arc` of one, a `dyn ByteSource` among them), its header, sections and trailer read and an encrypted file's security handler opened by the empty password (`open`) or by the passwords given (`open_with`, every password's encodings that fit the file's revision tried before any password's others, a wrong one leaving it locked, or plain where its strings and streams aren't encrypted, as no password would), which aren't kept, or by another once it's open (`unlock`, given the `Encoded` bytes to try, without reading the file again: what it had read dropped, to be read again decrypted, and a reading no password given opens handed back as it was, with pdf-crypt's `Refused`); then reads each object when it's first asked for, kept (`get`) or not (`object_unkept`, which gives the object's `Record` with it), and decodes each object stream once, when an object in it is first read, whichever thread asks; `Send` and `Sync`. `warnings` gives what it warned of in what's read, in the order the whole read says it; `record`, `facts`, `entries`, `metadata`, `bytes` (the bytes at a span, an encrypted file's refused as written), `id` (a `SourceId`, its own, which each record it makes holds), `source` and `into_source` (the source it reads) and `into_document`, the rest read as the whole read reads it; and `to_document`, the same document with the reading kept beside it, what it kept cloned and the rest read without keeping it, its object streams decoded and kept, so that it hands out what the document doesn't hold, a stream's data among it, and a read the source fails keeps none of what it read unkept. `data` hands out a stream's data, read each time it's asked for and not kept, borrowed from bytes in memory where nothing's decrypted: in an encrypted file that opened, decrypted as an object stream's is, by the stream's own `/Crypt` filter, else as `/StmF` says, and an embedded file's without one of its own as the encryption dictionary's `/EFF` says, where it names a crypt filter (from `/V` 4, below which `/EFF` isn't read); but a cross-reference stream's, and the catalog's metadata stream's under `/EncryptMetadata false` unless its own `/Crypt` filter encrypts it, left as written; refused where it may be ciphertext the reader doesn't decrypt, in a file no password opened (but one whose streams aren't encrypted, where only a stream's own crypt filter or an embedded file's `/EFF` encrypts it) or whose security handler it can't open, a stream the encryption dictionary refers to, and an embedded file's without a crypt filter of its own where `/EFF` isn't a name. `decoded` gives it through its filters, read as an object stream's are, by pdf-filters, to at most the limit on a stream, neither kept nor counted against the budget. A source that doesn't hold its bytes in memory is read by position, a window at a time from where each read starts, from its `first_window` (4096 bytes by default), doubled while what's read runs to the window's end where more of the file could change it, through pdf-objects' `Parser::window`, so that each read reads what it would of the whole file: the header from the file's start, `startxref` and the last `%%EOF` back from its end, each section at its offset, and each object at its own, its first window reaching a byte past the next listed offset, so that an object as it should be is one read; a file whose sections don't read is read whole, to be scanned. `FileBytes` is a file read so (`pread`, on Unix and Windows), its length and `Identity` taken as it's made: the file itself, by a handle it holds open, its device and inode on Unix or its volume serial number and file index on Windows (same-file's `Handle`), and its length and modification time, so `FileBytes::unchanged` tells a file changed in place and `Identity::of` a path that holds another file now, one made where the first was removed among them; `Identity` is `Clone`, and `FileBytes::identity` gives a reference to it, a clone of which holds the file open after the `FileBytes` is dropped; `Identity::of` opens the file to read, without waiting, so it needs leave to read it, and refuses a path that's neither a file nor a folder (a FIFO, a socket, a device) without opening it. Elsewhere `Identity` is the length and modification time alone. Its calls fail with a `bytes::Error`: why the object doesn't read, kept with it; or the source not giving its bytes, never kept, so a call asked again reads again, an object's `/Length` by reference, an object stream's filters' values and its data, the metadata, the bytes at a span and a stream's data among them; or why a stream's data isn't handed out, or doesn't decrypt or decode cleanly, pdf-crypt's and pdf-filters' errors, which hold what did. Read in any order and made a `Document`, a reading is the whole read, so long as no stream it decodes reaches its budget, spent in the order streams are decoded; `bytes::read` and the rest read every object so, in order, by the same code. The limits are one value, `Limits`, in a reading's `Options` (with the section a file is read as of, and `flate`, the pdf-filters `Backend` its Flate streams inflate on: `MinizOxide` by default, which this crate's dependency on pdf-filters names, so every build has it, or `ZlibRs` with this crate's `zlib-rs` feature, which docs.rs builds its docs with), both `#[non_exhaustive]`, set on a copy of their `DEFAULT`; `bytes::SECTIONS`, `STREAM`, `BUDGET` and `NESTING` are the defaults' values.
- **What it reads into.** `Source`, the trait a reader of a file implements; `Document`, a `Source` read whole, `#[non_exhaustive]`, made outside the crate by `Document::new`; `Trailer`, `#[non_exhaustive]`, made outside the crate by `Trailer::new`; `Warning`, `#[non_exhaustive]`, made by `Warning::new`; `Update`, the file's newest incremental update, `#[non_exhaustive]`, made outside the crate by `Update::new`; and `Encryption`, `#[non_exhaustive]`, whether the file is encrypted and whether it opened, its `Opened` variant `#[non_exhaustive]` too, saying by the owner's password or the user's, and which of those given in which encoding (`by`), made outside the crate by `Encryption::opened(owner)` and given its `by` by `Encryption::by`, a setter for each field, so that a field the variant gains changes no constructor. Why an object doesn't read is an `Unread`, which `Source::get` and `Document::unread` give: it isn't in the file, doesn't parse (pdf-objects' `parse::Error`), or isn't the object at its offset; the object stream it's in doesn't decode (`bytes::Undecoded`, its filters `bytes::Unfiltered`), needs a password, doesn't read, isn't in the file, or doesn't say where it is (`bytes::Unindexed`); or it runs to where a fault cut the stream's data off; or, from another reader, that reader's words (`Unread::Other`). Each is `#[non_exhaustive]` and derives `Display` and `std::error::Error` with thiserror, its `Display` the whole reason, with no `source`. What a reader says of the file it read stays text, as any reader fills it: `Trailer::unwritten`, `Encryption::Unsupported` and each `Warning`. `bytes::XrefEntry`, what a cross-reference section says of an object number, is `#[non_exhaustive]`, and its `Free` variant too, so it can say more; a `Reading` gives each number's (`entries`). `Document::record` gives where the bytes reader read an object that reads, and `records` each object's, a `Record`: the reading it was read in (`source`, its `SourceId`; two records are equal when they say the same of where their objects were read, whichever readings they're of, so two readings of one file are equal), its `Origin` (at a section's offset, recovered by the scan, or in an object stream, by its number, and where in it), its bytes (`at`) from `n g obj` to past `endobj` and whether `endobj` follows it, and a stream's data's `DataExtent`, whether by its `/Length`, and whether that's a reference; and `Document::facts`, the `Facts` of the file as written: where `%PDF-` starts (`header_offset`), the newest section's offset and `XrefKind`, how many sections, whether one is a hybrid's, the largest cross-reference stream's number, and whether a linearization holds. Each is `#[non_exhaustive]`; another reader's `Document` has none and the defaults. A `Document`'s objects are private, each kept with its record while it's as read, so a record is always of the object beside it: read by `contains` (whether it's listed, read or not), `objects` (each that reads, by number), `range` (those in a range of ids) and `unread` (each that doesn't, with why), beside `Source`'s `ids` and `get`; and written by `set` (an object put in, with no record, giving back the one it replaces; one of another file put in unplaced, by pdf-objects' `Object::unplace`, a stream's data given first as its bytes, as its places would be read as this file's, by a check and by the writer), `insert` (`set` at generation 0), `set_unread` (what a reader outside the crate puts where an object doesn't read), `remove` (the object and its record) and `get_mut` (an object to edit, its record dropped, as a `&mut` can replace it whole without an edit's dropping its span). `Document::decoded` stays public: an object stream member's record names its bytes there, so it says where the object was read only while they're as read. pdf-objects, pdf-filters and pdf-crypt are re-exported as `pdf_objects`, `pdf_filters` and `pdf_crypt`, and pdf-crypt's `Password`, `Encoded` and `Encoding` at the root, so their types are named at the versions the reader gives (a reading's `bytes::Error` holds pdf-filters' error where a stream's data doesn't decode cleanly, and `unlock` pdf-crypt's `Refused`): each is a public dependency, whose version moves with this crate's. The root has `bytes::Error` (as `Error`), `SourceId`, `Reading` and the rest of what a reading takes and gives. `&Document` and `&Reading<S>` implement pdf-objects' `Resolve`, which what follows references reads through, from any thread: a reference resolves to its object, read and kept as `get` keeps it, or to none, null, where the file hasn't it, it doesn't read, or the source fails the read (which keeps nothing, so asked again it reads), without the `Unread` that `get` would clone to say why.
- **A document in memory.** A `Document`, built by `Document::new` or read whole, numbers new objects (`new_id`, and `add`, which puts one at it): past every number the file's cross-references list, in use, in an object stream or free, past its cross-reference streams' (`Facts::max_stream`) and the trailer's `/Size` less one, where that's a number below the largest (a `/Size` of 2^32 or more is passed over, so that alone never takes new ids past every number), or for one built, past its `/Size` less one, never 0; and past every number put in since, read or not, so each `new_id` gives another though none is set. Once they reach 4,294,967,295, the largest number, as a file that lists it or an object put there can, each is the next number above the last handed out that no entry holds (or, where an object put at the largest took them there, above where they'd have started), from 1 again after the largest, so it may be one the file lists free, and once they've gone round, one handed out before and not set since. `max_id` is the number they start after, and `set_max_id` sets it, never below a number held. Two documents are equal where their objects, records and fields are, and their new ids start at one number. `dereference` follows a chain of references to where it ends, as many as 128, giving the last id on the way, none where one names an object that isn't there or doesn't read, or the chain loops; `get_dict` gives an object's dictionary, or its stream's, through the references it is, and `get_dict_mut` to change, an edit of the object it ends at, dropping its record; `catalog` and `catalog_mut` the trailer's `/Root`'s; `Trailer::dict_mut` the trailer's dictionary, or its cross-reference stream's, to change, one that's neither made an empty dictionary first. `reachable` gives every id the trailer reaches, through the objects that read, each once, in the order found (the trailer's references, then each found object's in turn, each in the order written, every entry of a key written twice among them), an id of an object that isn't there or doesn't read found and not followed; `prune` removes every object it doesn't reach, read or not, with its record, and gives their ids by number: object streams and cross-reference streams go, as nothing refers to them, so `Trailer::stream` may name an object no longer held, and the encryption dictionary stays, as the trailer refers to it; `decoded` is left as it is.
- **Sections and object streams written.** `write` writes what a file's structure is written in, for a caller that lays the file out, its objects written by pdf-objects' writer, each where the output has got to. `Section` is a cross-reference section's entries by number, each an `Entry`, `#[non_exhaustive]`, in the reader's words (`InUse` at an `offset` and generation; `Free`, to be used next at a generation; or `Compressed`, the `index`th object in object `stream`): a whole file's (`Section::full`, one subsection from 0, every number it doesn't list written free, the free entries linked in a list from entry 0) or an update's (`Section::append`, runs of the numbers it lists, after a file whose header starts where it's given); built by `insert` (an entry for 0, the free list's head, passed over; one at or past `NUMBERS` refusing the section when it's written, `write::Error::Number`, as a whole file's `/Size` past it does, before a row is made), with `size`, its `/Size`, `lists`, and `get`, what it lists a number as, so where each object landed; written as a table (`table`, which refuses an object in an object stream, `write::Error::Packed`, and an offset past ten digits, `TooFar`) or as a stream (`stream`, listing itself, numbered neither 0 nor past `NUMBERS`, its `/W` as narrow as its widest field, a whole file's deflated under PNG's Up predictor, `/Predictor 12`, an update's as it is), then `startxref`. Positions are counted from the header, as PDFium, pdf.js and qpdf read them, where ISO 32000-2 and this crate's reader count them from the file's start (7.5.4), which differ only for an update of a file with bytes before its header; a position before the header is refused (`BeforeHeader`). `packable` says whether an object may go in an object stream (7.5.7): not a stream, an object whose generation isn't 0, an encryption dictionary (a `/Filter` name, `/O` and `/U`), the linearization dictionary, nor a signature dictionary (a `/Type`, or with none an `/FT`, of `/Sig` or `/DocTimeStamp`; with neither, `/ByteRange` and `/Contents`). `container` makes an object stream of objects written direct, borrowed or owned (`AsRef<[u8]>`), a header of each one's number and where it starts from `/First`, each followed by a newline, deflated, its `/Length` direct; refused for a member numbered 0 or past `NUMBERS` (`Number`) or a number given twice (`Twice`); none where it would have more than 65,536 members, or its data would be past `MAX_DATA`, `Limits::stream`'s default, 256 MiB, so the reader reads every container the writer makes whole (`fits`). `MEMBERS`, 100, is the most a container holds where a writer chooses, qpdf's default; `NUMBERS`, 8,388,607, the most objects a file may hold (ISO 32000-1, Annex C), below which a written file's numbers are, which also keeps any two from sharing an RC4 or AES-128 object key. Both deflate through pdf-filters' `encode`, by the backend and at the level a `Deflate` says, `#[non_exhaustive]` and set on a copy of `Deflate::DEFAULT`, miniz_oxide at 6, which every build has (zlib-rs with the `zlib-rs` feature). What can't be written is refused, with nothing written: `write::Error`, `#[non_exhaustive]`, deriving `Display` with thiserror, the whole message, and no `source`, holding pdf-objects' writer's refusal (`Serialize`), of a trailer that can't be written among them, and pdf-filters' (`Unencodable`).
- **Encrypted as it's written.** `write::Encryptor`, how a written file is encrypted, `Clone`, its `Debug` without the key: `Encryptor::of` a `Reading` (its handler, as a password opened it; its `/Encrypt` dictionary as the file stores it, which the reading now keeps, at its number or direct in the trailer, `at` and `direct`; its `/ID[0]`, `first_id`; and the list of what it leaves in the clear, as the reading decrypts by it), none for a file that isn't encrypted, refused for one no password opened (`write::Error::Locked`, a file whose strings and streams aren't encrypted among them) and one whose handler the reader can't open (`Unsupported`); `Encryptor::create`, a new file's of revision 6 for a prepared password, by pdf-crypt's `Handler::create`, its dictionary's crypt filter with `/Length 32` and `/AuthEvent /DocOpen`; `packs`, whether objects may go in object streams under it (not where streams are in the clear and strings aren't); `dictionary`; and, for a caller that lays a file out itself, what a whole file is written by: `whole`, the encryptor for a file whose one `/Encrypt` is at a given number (an earlier revision's dictionary's number then encrypted as any), `free` and `free_numbers` (below), and `dictionary_object`, whether an object is an encryption dictionary or what one refers to, never put in an object stream. `Encryptor::encrypting`, given the file's trailer and a resolver (`pdf_objects::Resolve`, `Sync`), gives an `Encrypting` (refused where `/EncryptMetadata false` leaves the metadata stream in the clear and the resolver doesn't give the catalog, `write::Error::Catalog`, rather than encrypt it), pdf-objects' `serialize::Encrypt`, which `indirect_with` and `indirect_stream_with` write through: every string and stream's data encrypted with its object's key, AES's IV from `n g obj` and the data (pdf-crypt's `encrypt_string` and `encrypt_stream`), but what the reader's list leaves in the clear, the one list both ways (`bytes`' "What's encrypted", each row now saying what the writer does, and held by its tests): the encryption dictionaries and what they refer to, by number; a cross-reference stream; a signature's `/Contents`; a stream whose crypt filter is `/Identity`; the document's metadata stream's data under `/EncryptMetadata false`, its dictionary's strings encrypted; an embedded file by `/EFF`, a stream by its own crypt filter. Its refusals, `write::Unencryptable` (`#[non_exhaustive]`: pdf-crypt's `Fault`, a stream an encryption dictionary refers to, an embedded file where `/EFF` isn't a name), are `write::Error::Encrypt` with the object, through `From<Refused<Unencryptable>>`. The RC4 keystream a changed object written again at its number and generation shares with its earlier version, what that leaks and when, and what a writer does instead (a whole file under `Encryptor::create`), said in `write`'s docs and the README.
- **Whole files and updates written.** `write::full` writes numbered objects (each a `write::Body`, `#[non_exhaustive]`: `New`, an object written anew from its value; or `Read`, below) as a whole file at the end of a caller's `Vec<u8>`, its positions counted from where it starts there: the header, at the version `write::Options` says, a comment of bytes past ASCII, each object at its number in the order given, the encryption dictionary (at `Options::encrypt_at`, else where its encryptor's file had it, else past every object; direct in the trailer where that file had it so), and one section, a table or a stream (`Options::kind`), with no `/Prev`; its trailer the caller's but for the keys a section writes itself (`/Prev`, `/XRefStm`, a cross-reference stream's own, `/Encrypt` and `/ID`), written as it is, never encrypted (ISO 32000-2, 7.6.2); its `/ID` the first string kept (the encryptor's, else the trailer's) and the second XXH3-128 of the bytes written before the section, through twox-hash, so the same objects write the same bytes; an encrypted file with no first string the hash twice. Packed (`Options::pack`, a `write::Pack`, only with a stream), what may go in an object stream goes in one, but an encryption dictionary and what one refers to: grouped by the caller (`Pack::groups`, a `write::Groups`) or by number, `MEMBERS` each, numbered from `Pack::reuse`, then past every object and `Options::xref_from`; built on up to `Options::threads` threads (as many as the machine runs, up to 8, by default; one where that isn't known; a part no thread can be had for on the calling thread), the same bytes on any number; each encrypted once, whole, under its number; its members on their own where it would be past `MAX_DATA`, or where no number is left for the cross-reference stream, and none under an encryption that leaves streams in the clear and strings not. `write::document` writes a `Document`'s objects so, but object streams, cross-reference streams and a linearization dictionary, and its encryption dictionary, which the writer writes from its encryptor, and what that refers to where it's written under another encryption. `write::update` writes an incremental update after a file a `write::Base` describes (`#[non_exhaustive]`: its length, whether its last line is ended, where its header starts, its last section and kind, where its new numbers start, its `/ID[0]`, its newest trailer, its encryption dictionary as stored where that's known, and the reading it's of): a newline first where its last line isn't ended, each object at its number, then a section of the file's kind listing only those, positions counted from the file's header, a stream's numbered at `Options::xref_from` or past every number, its trailer the file's newest trailer's entries but its sections' own, `/Root`, `/Prev`, `/Info`, `/Encrypt` and `/ID` first (7.5.6); none where there's nothing to write. `Base::of` describes a `Reading`'s file (its header at 0, as the reader counts positions from the file's start; its numbers past its `/Size`, every number listed and its cross-reference streams'), refused for one with bytes before its header, whose positions readers count from different places (`Prefixed`), one read by scanning, one without `/Root`, and a reading as of an earlier revision, which the reader now keeps (`Options::section`); `Base::new` one a caller read otherwise, its fields set after; `Base::holds` whether a file is still the one it describes, as long and ending in the same section. Each write gives back a `write::Written` (`#[non_exhaustive]`): its section (where each object landed), where it starts, its `/Size`, its `/ID` and the file as it now is, a `Base` for an update after it. A stream's data where the reader read it (`Data::At`) is read from the reading given (`write::ReadFrom`, sealed, a `Reading` as `&dyn ReadFrom`), only at its own number there, decrypted and encrypted again as the write is; elsewhere, or with no reading, refused (`write::Error::Placed`). An update is encrypted as its file is, by that file's encryptor, told by where its dictionary is, the dictionary as the file stores it where the base knows it (`Base::of`'s reading's; `Base::new`'s trailer's where it's direct) and the `/ID[0]` its key is made from (`Unmatched` otherwise, another file's whose `/Encrypt` is at the same number among them); where an encryptor's keys are made per object (RC4, AES-128, told by pdf-crypt's `Method`), `Encryptor::of` keeps the numbers its reading lists free, each with the generation its entry gives (`Encryptor::free`, `free_numbers`), and an object at one is refused in an update and a whole file alike (`Free`), and a whole file lists each free at that generation, `/Size` past it, so that a tool that follows its free list takes none at a deleted object's key. A whole file has one section, whose `/Encrypt` is the only one, so it encrypts what it's given at a number its reading named `/Encrypt` by in an earlier section, or where the write moves the dictionary from, as any object; and leaves what the dictionary refers to out of object streams, as a reader reads it before it has a key. The writer's own objects (object streams, a cross-reference stream, a new encryption dictionary) pass over the numbers what's written refers to and doesn't hold, so that a reference to no object, which reads as null, doesn't come to name one. Refused, with nothing written, beside those: a number 0 or past `NUMBERS` (`Number`), one given twice (`Twice`), an object at the encryption dictionary's number (`EncryptAt`), a table asked to pack (`PackedTable`), no number left for an update's stream (`NoNumber`), a base read by scanning, without `/Root` or of an earlier revision (`Unsound`, `Rootless`, `Earlier`), a catalog not given nor read where `/EncryptMetadata false` needs it to say which stream is the metadata (`Catalog`), a group naming a number not packed or one twice (`Group`), a write a flag stops (`Options::stop`, `Stopped`), a stream's data or a source's bytes that don't read (`Data`, the reading's error in words; `Io`, the I/O error's `kind` and its words). `Section::stream` now takes the section by `&mut`, listing itself in it after, and `Section` is `PartialEq`. Under RC4 an update encrypts a changed object with the keystream of its earlier version, still in the file: `write::update`'s docs say what that leaks, and what a writer does instead.
- **Copies as read.** `write::Body::Read` is an object as it was read, its value and its `Record`, which `write::bodies` gives a `Document`'s objects as (where they're as read; `New` where not), and `write::document` now writes: copied as the bytes it was read from, read again from the reading given, where those are right to copy, else written anew from its value, and so always with no reading given. Copied only of that reading (`Record::source`; another's refused, `write::Error::Elsewhere`), at its own number (`Record` now holds the id the object was read as, `Record::id`, in its equality; given at another, refused, `Elsewhere`, under any encryption, whether or not it would copy; an object at an offset starting `n g obj` for its id, one in an object stream at the place the reading's sections give its number; and the object the record's, as read: else refused, `Elsewhere`, but an object an edit changed, its place dropped, written anew), not found by scanning, `endobj` after it, a stream's `/Length` no reference and its data as long; read at an offset, under an `Encryptor` of that reading (`Encryptor::of`), where the list of what's in the clear says the same of it in the file written as in the file read (an earlier section's encryption dictionary, which a whole file no longer names so, and the document's metadata under `/EncryptMetadata false` where the catalog names another, are written anew), or with neither encrypted; read from an object stream, into an object stream of the write's, under any encryption or none, its bytes there plaintext, and written anew on its own. A copy's bytes, read again through the reading (an encrypted file's ciphertext among them, which `Reading::bytes` still refuses), are checked against a hash of them taken as the object was read: `Record` holds XXH3-64 of the bytes it names, through twox-hash's `xxhash3_64`, private, in its equality; bytes that hash otherwise refuse the write (`write::Error::Changed`). `ByteSource::unchanged` says whether a source's bytes are those it had: true by default, `FileBytes`' its own, forwarded through a reference, a `Box` and an `Arc`; a write given a reading asks it first, and refuses where they aren't (`Changed`). An update after a reading's file passes over each object as that reading read it at its own number (`Base::source`), which the file holds, and refuses one of that reading's given at another (`Elsewhere`), so `write::update` of a document's bodies writes what was built or changed since, and a second update after the first's `Written::base` does too.
- **Whole files renumbered.** `write::Options::renumber`, a renumbering (pdf-objects' `serialize::Renumber`, any function from an id to an `Option` of one, as `&(dyn Renumber + Sync)`), writes a whole file's objects at the numbers it gives, each reference in them and in the trailer named as it names it, `null` where it names none (ISO 32000-2, 7.3.10), the trailer's before the writer's own entries go in; `Options` has its own `Debug`, the renumbering said, not printed. What's given stays at its numbers, a document's ids, an object as read at the number it was read as, so `write::bodies` and `write::document` are as they were: a stream's data, a copy's record and what the encryptor resolves are found by them. What the file uses is checked in the numbers written: 0 and `NUMBERS` (`write::Error::Number`), two objects written at one number (`Twice`; under a renumbering, a number given twice too), the encryption dictionary's (`EncryptAt`), a number the encryptor's file lists free under keys made per object (`Free`), `Pack::reuse`, and the numbers the writer gives its own objects, which pass over a written number referred to and not written; `Pack::groups` is given the numbers the packed objects are given at. An object the renumbering gives no number is refused (`write::Error::Unnumbered`); one given past `NUMBERS` and written below it is written. Encrypted, each object is encrypted under the number it's written at: `Encryptor::renumbered` gives the encryptor in the numbers a renumbering writes, its list of what's left in the clear, its dictionary's place and references (a direct one's too) translated, its free numbers as they are, and the document's metadata stream is found in the numbers given and kept as its number written; `Options::encrypt_at` is a number written. Under RC4, an object written at a number another object had in the file read is encrypted with that one's keystream, which the docs say beside an update's case. An object as read is copied, its header and each reference that moves written anew in place (below). `write::Base::renumbered` says a whole file was written so, and an update after it refuses an object as read and a reading (`write::Error::Renumbered`), as their numbers aren't the file's any more; it's given objects at the numbers written, under `Encryptor::renumbered`'s encryptor. An update takes a renumbering too (below). `write::Error::Twice`'s words say both cases.
- **Copies renumbered in place.** Under a renumbering, an object as read (`write::Body::Read`) is copied as the bytes it was read from but its header, `n g obj`, where it's written at another number, and each reference the renumbering names otherwise, `n g R` or `null`, each written anew where its bytes had it: a comment between a changed reference's tokens goes with them, and every other byte, strings and stream data among them, is copied as it was. Each of its references is first checked to be placed among its bytes, past its header and before a stream's data, in the order walked, and each changed one to read there as itself, three tokens of their own, else the write is refused (`write::Error::Elsewhere`, whose doc says so). At another number than it was read as, it's copied only where neither file is encrypted or no method of the reading's encryptor makes a key per object (AES-256, whose key is the file's and whose IV is beside its ciphertext); under RC4 and AES-128 it's written anew there, and copied at its own number, its references rewritten. An object stream's member goes into one of the write's under any encryption, its references rewritten. `write::Body::Read`'s rules say so (rule 2's clause, and rule 9).
- **Updates renumbered.** `write::update` takes `Options::renumber` too: what it's given, its bodies, the references in them and the trailer it carries, is in the numbers of the file it goes after, and each object is written at the number the renumbering gives it, its section listing those, each reference named as it names it, `/Root`, `/Info` and the rest of the carried trailer too, `null` where it names none. An object as read of the base's reading is passed over only where the renumbering leaves its number and every reference in it where they are; one that moves, or names one that does, is written, copied where the rules for a copy hold, its header and the references that move written anew in place, and nothing else is written at the number of one passed over, nor given there again (`write::Error::Twice`). Encrypted, an update encrypts by its encryptor's list of what's left in the clear as it is, in its file's numbers, each object under the number it's written at, and the document's metadata stream is found in the numbers given and kept as its number written, as a whole file's is. It doesn't write the encryption dictionary again, so the file's `/Encrypt` names the dictionary and what it refers to where they are, and its reader reads what's at those numbers in the clear: a renumbering that moves one, names one none, or writes another object at one's number is refused (`write::Error::Moved`, new). An update frees nothing, so an object it moves is still at its old number too, and what it doesn't write still names it there: a caller gives every object a reference in which moves. What it wrote says it was renumbered (`Base::renumbered`, whose doc and `write::Error::Renumbered`'s words now say "written under a renumbering", whole or as an update), and an update after it is given objects at the numbers it wrote, built or edited, and refuses an object as read and a reading. `update`'s docs, `Options::renumber`'s, `Written::base`'s, `Body::Read`'s and the module's say so, and RC4's leak where an update puts an object at a number another had.
- **A document taken by another reading.** `Reading::adopt(&mut doc)` takes a document's objects as read as the reading's own, so that a document read whole (`bytes::read`, `read_opened`, `Reading::into_document`), whose reading is gone, is written from a reading of its file opened again as one made by `Reading::to_document` is: its streams' data read from it, its objects copied as the bytes they were read from where the rules for a copy hold, and passed over by an update after the file. Each object with a record is compared with the reading's own record of its number, kept, or read without keeping it, a parse each, the object streams they're in decoded and kept: alike where it's the same record but the reading's (read as that number, where and how, and its bytes' hash). An encrypted file's encryption is the document's where the encryption dictionary it was opened by, as stored, is the one the document's trailer names, at the same number or alike in the trailer, and its first `/ID` element is the document's: what a password's key is made of, the key itself not compared, so a reading by the owner's password takes a document read by the user's. Where every one is alike, each record then names the reading; an object without one, built or edited, is left as it is. All or none: where an object isn't alike, or the encryption isn't, the document is left as it was and it's refused (`bytes::Error::Unlike`, new: the object, or none for the encryption), another file, the file changed since, a reading as of another revision whose object at a number isn't the document's, and the same objects' bytes under another `/ID` among it; and so it is where the source doesn't give its bytes (`bytes::Error::Io`), which asked again it reads again.
