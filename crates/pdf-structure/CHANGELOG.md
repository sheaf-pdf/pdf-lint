# Changelog

## 0.1.0 (unreleased)

- **The reader.** `bytes::read` reads a file from its bytes: the header, `startxref`, the cross-reference tables and streams along their `/Prev` chain, and each object at its offset through pdf-objects' parser, a stream's data by its `/Length` when that ends at `endstream`; where the sections don't read, the objects found by scanning, the trailer saying why. Cross-reference streams and object streams are decoded through pdf-filters, `/Filter` and `/DecodeParms` read as qpdf reads them, a stream to at most 256 MiB (`bytes::STREAM`) and a reading's streams to 1 GiB in all (`bytes::BUDGET`), and the objects read from an object stream placed in its decoded data, which the `Document` keeps. `bytes::read_opened` opens an encrypted file with the passwords given, through pdf-crypt's standard security handler, revisions 2 to 6; `bytes::read` with the empty password. `bytes::read_from` and `read_from_opened` read the file as of a cross-reference section, an update's revision before. What the reader had to choose how to read is a `Warning`, with its object and where.
- **What it reads into.** `Source`, the trait a reader of a file implements; `Document`, a `Source` read whole, `#[non_exhaustive]`, made outside the crate by `Document::new`; `Trailer`; `Warning`, `#[non_exhaustive]`, made by `Warning::new`; `Update`, the file's newest incremental update; and `Encryption`, `#[non_exhaustive]`, whether the file is encrypted and whether it opened. pdf-objects is re-exported as `pdf_objects`, so its types are named at the version the reader gives.
- **For tests** (the `fixtures` feature, hidden): files written from objects, whole with a cross-reference table or stream or assembled from bytes written by hand, and encrypted by pdf-crypt's `writer`; and qpdf, the program `PDF_LINT_QPDF` names or `qpdf` on the `PATH`, run as a second reader of a file and as a decoder to set the reader's decoding beside. For this workspace's tests and fuzz targets, not for a user: without it, nothing runs a program or reads `PDF_LINT_QPDF`.
- **From pdf-lint.** These are pdf-lint 0.2.0's reader, its `bytes` and `source` modules and the `/Filter` reading under them, what they do unchanged (but that each object is read through pdf-objects' parser and is pdf-objects' `Object`, whose value an edit changes, dropping its span; that each string keeps the `Form` it was written in, which stands in for `Source::hex` and `Document::hex`, gone; that a stream's data is a `Data`, `Data::At` where it was a span; and that `Value::Stream` holds a `Box<Stream>`), which pdf-lint re-exports where they were. Each warning and error says what pdf-lint 0.2.0's said, word for word, but that an object of more than 2^25 values is an error, which is new, and a token nested past `bytes::NESTING` that can't start a value is the error it is, where pdf-lint said it was nested too deep. Rust 1.85 builds it.
- **Tests.** Unit tests for each part of a file the reader reads, and each it recovers from: the header, tables and streams along `/Prev`, updates, scanning, object streams, every filter and its parameters, the limits, decrypting each revision, and a reading that never panics, whatever the bytes; the comparisons with qpdf, a second reader and decoder, on files qpdf wrote (committed in `tests/files`) and files written by hand, ignored but by `just test-qpdf`; the types `Send` and `Sync`; the README's examples as doctests; and a fuzz target (`just fuzz structure`), which reads a file, its revision before an update and, as the input chooses, the file opened by an owner's password, each the same twice and every place inside what was read, whose body a unit test runs on mutated files.
