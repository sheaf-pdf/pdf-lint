# Changelog

## 0.1.0 (unreleased)

- **The reader.** `bytes::read` reads a file from its bytes: the header, `startxref`, the cross-reference tables and streams along their `/Prev` chain, and each object at its offset through pdf-objects' parser, a stream's data by its `/Length` when that ends at `endstream`; where the sections don't read, the objects found by scanning, the trailer saying why. Cross-reference streams and object streams are decoded through pdf-filters, `/Filter` and `/DecodeParms` read as qpdf reads them, a stream to at most 256 MiB (`bytes::STREAM`) and a reading's streams to 1 GiB in all (`bytes::BUDGET`) by default, and the objects read from an object stream placed in its decoded data, which the `Document` keeps. `bytes::read_opened` opens an encrypted file with the passwords given, through pdf-crypt's standard security handler, revisions 2 to 6; `bytes::read` with the empty password. `bytes::read_from` and `read_from_opened` read the file as of a cross-reference section, an update's revision before. What the reader had to choose how to read is a `Warning`, with its object and where.
- **A reading on demand.** `Reading` (`bytes::Reading`, at the root too) opens a file from a `ByteSource`, a slice, a `Vec<u8>` or an `Arc<[u8]>` (or a reference to one), its header, sections and trailer read and an encrypted file's security handler opened with the passwords given, which aren't kept; then reads each object when it's first asked for, kept (`get`) or not (`object_unkept`, which gives the object's `Record` with it), and decodes each object stream once, when an object in it is first read, whichever thread asks; `Send` and `Sync`. `warnings` gives what it warned of in what's read, in the order the whole read says it; `record`, `facts`, `entries`, `metadata`, `bytes` (the bytes at a span, an encrypted file's refused as written), `source` (a `SourceId`, its own) and `into_document`, the rest read as the whole read reads it. Its calls fail with a `bytes::Error`: why the object doesn't read, kept with it; or the source not giving its bytes, never kept. Read in any order and made a `Document`, a reading is the whole read, so long as no stream it decodes reaches its budget, spent in the order streams are decoded; `bytes::read` and the rest read every object so, in order, by the same code. The limits are one value, `Limits`, in a reading's `Options` (with the section a file is read as of), both `#[non_exhaustive]`, set on a copy of their `DEFAULT`; `bytes::SECTIONS`, `STREAM`, `BUDGET` and `NESTING` are the defaults' values.
- **What it reads into.** `Source`, the trait a reader of a file implements; `Document`, a `Source` read whole, `#[non_exhaustive]`, made outside the crate by `Document::new`; `Trailer`, `#[non_exhaustive]`, made outside the crate by `Trailer::new`; `Warning`, `#[non_exhaustive]`, made by `Warning::new`; `Update`, the file's newest incremental update, `#[non_exhaustive]`; and `Encryption`, `#[non_exhaustive]`, whether the file is encrypted and whether it opened, its `Opened` variant `#[non_exhaustive]` too. Why an object doesn't read is an `Unread`, which `Source::get` gives and `Document::objects` holds: it isn't in the file, doesn't parse (pdf-objects' `parse::Error`), or isn't the object at its offset; the object stream it's in doesn't decode (`bytes::Undecoded`, its filters `bytes::Unfiltered`), needs a password, doesn't read, isn't in the file, or doesn't say where it is (`bytes::Unlisted`); or it runs to where a fault cut the stream's data off; or, from another reader, that reader's words (`Unread::Other`). Each is `#[non_exhaustive]` and derives `Display` and `std::error::Error` with thiserror, its `Display` the whole reason, with no `source`. What a reader says of the file it read stays text, as any reader fills it: `Trailer::unwritten`, `Encryption::Unsupported` and each `Warning`. `bytes::XrefEntry`, what a cross-reference section says of an object number, is `#[non_exhaustive]`, and its `Free` variant too, so it can say more; a `Reading` gives each number's (`entries`). `Document::records` holds where the bytes reader read each object that reads, a `Record`: its `Origin` (at a section's offset, recovered by the scan, or in an object stream, which and where in it), its bytes from `n g obj` to past `endobj` and whether `endobj` follows it, and a stream's data's `Extent`, whether by its `/Length`, and whether that's a reference; and `Document::facts`, the `Facts` of the file as written: where `%PDF-` starts, the newest section's offset and `XrefKind`, how many sections, whether one is a hybrid's, the largest cross-reference stream's number, and whether a linearization holds. Each is `#[non_exhaustive]`; another reader's `Document` has none and the defaults. pdf-objects is re-exported as `pdf_objects`, so its types are named at the version the reader gives.
- **For tests** (the `fixtures` feature, hidden): files written from objects, whole with a cross-reference table or stream or assembled from bytes written by hand, and encrypted by pdf-crypt's `writer`; and qpdf, the program `PDF_LINT_QPDF` names or `qpdf` on the `PATH`, run as a second reader of a file and as a decoder to set the reader's decoding beside. For this workspace's tests and fuzz targets, not for a user: without it, nothing runs a program or reads `PDF_LINT_QPDF`.
- **From pdf-lint.** These are pdf-lint 0.2.0's reader, its `bytes` and `source` modules and the `/Filter` reading under them, what they do unchanged (but that each object is read through pdf-objects' parser and is pdf-objects' `Object`, whose value an edit changes, dropping its span; that each string keeps the `Form` it was written in, which stands in for `Source::hex` and `Document::hex`, gone; that a stream's data is a `Data`, `Data::At` where it was a span; and that `Value::Stream` holds a `Box<Stream>`), which pdf-lint re-exports where they were. Each warning and error says what pdf-lint 0.2.0's said, word for word (why an object doesn't read is an `Unread`, where pdf-lint's was a `String`, and `Trailer`, `Update`, `XrefEntry` and `Encryption::Opened` are `#[non_exhaustive]`, where pdf-lint's weren't), but that an object of more than 2^25 values is an error, which is new, and that the reader's limits are the same in a build under cargo-fuzz (`--cfg fuzzing`), where pdf-lint's were smaller, so a dependant's fuzz build reads as any other, and a token nested past `bytes::NESTING` that can't start a value is the error it is, where pdf-lint said it was nested too deep. Rust 1.85 builds it.
- **Tests.** Unit tests for each part of a file the reader reads, and each it recovers from: the header, tables and streams along `/Prev`, updates, scanning, object streams, every filter and its parameters, the limits, decrypting each revision, and a reading that never panics, whatever the bytes; each message it gives, word for word, from a file made to give it, and each error's text beside the format string pdf-lint made it by; the comparisons with qpdf, a second reader and decoder, on files qpdf wrote (committed in `tests/files`) and files written by hand, ignored but by `just test-qpdf`; the types `Send` and `Sync`; the README's examples as doctests; a reading on demand, every test file and qpdf's fixtures read by number, from the last back and on eight threads, the whole read each time, what it keeps of what it reads, the budget spent in the order streams are decoded and never wrapped by threads decoding at once, an object stream and a cross-reference stream that inflate far past their caps read quickly, and whether a linearization holds; and a fuzz target (`just fuzz structure`), which reads a file under small limits, its revision before an update and, as the input chooses, the file opened by an owner's password, each the same twice and every place inside what was read, and read on demand in an order the input chooses the whole read, where neither's decoding reached the budget, whose body a unit test runs on mutated files.
