# Changelog

## 0.1.0-alpha.3 (unreleased)

Decode as PDFium does where its reading parts from qpdf's: its LZW decoder's reading of a code past the table, and what it refuses. The default reading is unchanged. Depend on this alpha exactly, `=0.1.0-alpha.3`.

### Added

- `Reading`: how filters read data where the standard leaves a reading open. `Reading::Qpdf` is the default, the reading `decode`, `decode_into` and `decode_prefix_into` keep. `Reading::Pdfium` reads as PDFium's LZW decoder and predictors do, as of chromium/8125.
- `decode_into_as` and `decode_prefix_into_as`: `decode_into` and `decode_prefix_into` with a `Reading` before the buffer.
- `Fault::AsNext { at }`: under `Reading::Pdfium`, an LZW code past the table's next entry read as that entry, and the codes after it read on as PDFium reads them.
- `Fault::Refused`: under `Reading::Pdfium`, data PDFium refuses, its output cut away. That's LZW data whose first code since a clear code is past the table, LZW data that decodes to nothing, a predictor whose rows would be no bits, and PNG's predictor on nothing.
- `Prefix::decoded`: what the decoder gave before its predictor, refused or not, so a caller can count what decoding cost.

## 0.1.0-alpha.2 (2026-11-07)

- **Rust 1.89.** The minimum Rust is 1.89, from 1.85: the family's, moved for the RustCrypto releases pdf-crypt wants (its CHANGELOG says which), nothing of this crate's own needing it. A dependent names an alpha exactly, so it takes this one by naming it.

## 0.1.0-alpha.1 (2026-11-06)

The first release, and an alpha: until a release says it's stable, any alpha may change the API, each saying here what changed and how code follows. A crate that depends on an alpha names it exactly, `=0.1.0-alpha.1`: cargo's default, `0.1.0-alpha.1`, takes any later alpha of 0.1.0 too.

- **The filters.** `decode` decodes data by a list of `Filter`s, as a stream's `/Filter` lists them: `AsciiHex`, `Ascii85`, `Lzw` (with `/EarlyChange`), `Flate` (zlib, on the `Backend` the call names) and `RunLength`, each given what the one before gave, no filter's output over the caller's limit (before a PNG predictor, its tags besides).
- **Two Flate backends, named at each call.** `Backend::MinizOxide`, with the `miniz_oxide` feature (on by default), and `Backend::ZlibRs`, with the `zlib-rs` feature (zlib-rs through its safe API, on Rust's allocator): each variant exists only with its feature, both with both, and `decode`, `decode_into`, `decode_prefix_into` and `encode` each take the one they use, so no feature another crate turns on changes what a call gives; with neither feature the crate doesn't build, and docs.rs builds the docs with both. On clean data the two decode alike; on damaged data where each stops, how much it gave first and a `Corrupt` fault's place can differ.
- **LZW, a decoder of its own, read on past a full table.** `LZWDecode` is the crate's own decoder, not weezl's, which says nothing of a full table and gives no place for a code that isn't in the table, both of which a checker reports. A table that fills, 4,096 entries, with no clear code to empty it is read past, the codes after it against the table as it is, 12 bits wide, until a clear code or the end, the same bytes as PDFium, pdf.js and poppler give (qpdf stops there): `Fault::TableFull` says where it filled and doesn't stop the filter, so a predictor after it reads its last row as it reads a short one. Codes are read from a 64-bit buffer filled eight bytes at a time, and a table entry's bytes are copied at once: 4 MB of text, encoded by weezl to 107,565 bytes, decodes in about 1 ms, where weezl 0.1 takes about 8, measured, not promised.
- **Into the caller's buffer.** `decode_into` appends what it decodes to a `Vec` the caller gives, what it held kept, the limit counting only what's added, the last filter decoding straight into it (grown with zeros, cut to what was written, a predictor undone in place); on faults it keeps what decoded and gives `Faults`, the `(filter, fault)` list an `Error` has, displayed alike. `decode` is `decode_into` an empty `Vec`, cut to its length.
- **What a filter read, where its data runs on.** `decode_prefix_into` decodes data that may run on into other bytes (an inline image's, in a content stream) by one `Filter`, appended to the caller's buffer under the limit with the same bytes and faults as `decode_into` gives by a list of that filter alone, and gives a `Prefix` (`#[non_exhaustive]`): `read`, how many bytes from the data's start the filter read, and `ended`, whether its data ended within them at its end-of-data marker (Flate's checksum, matching or not). Bytes after those it read change nothing it gives, and cost nothing: Flate's output is first given room for no more than 4 KiB of what's given, and grows as it fills, so decoding many small images, each given all the content after it, costs what each reads and gives. Flate's bytes are counted as zlib's `total_in` counts them, on either backend, a header it refuses as zlib counts it (none where it asks for a preset dictionary and four bytes name one); LZW's to the last bit of the last code read, rounded up to a byte, not the bytes its buffer took ahead; the others' to the last byte the decoder took. Held to PDFium's: on hand-made inline images, its Flate and LZW decoders at chromium/7881, 8076 and 8125 took their data to end where these counts say, but where PDFium's LZW decoder reads on past a code that isn't in the table, which stops this one; miniz_oxide refuses at once a dynamic block whose code-length code has no lengths, which zlib-rs, as zlib, reads on into.
- **Encoding, for a writer.** `encode` appends `data` encoded by a list of `Encoder`s, listed as a stream's `/Filter` lists them (the last applied first), to a `Vec` the caller gives. `Encoder::Flate` takes a `Level` (0, stored, to 9; `Level::DEFAULT` 6, `Level::BEST` 9) and a `Prediction`: none, or PNG's with a `Layout` and a `Row` filter for every row (`None`, `Sub`, `Up`, `Average`, `Paeth`). Each backend deflates as flate2's `ZlibEncoder` does on it (a 32 KiB window, memory level 8, the default strategy; zlib-rs given 32 KiB to write into at a call, as flate2 gives it, since what it writes depends on where that room runs out), so with flate2 1.1 on the same backend versions the bytes were found the same at levels 6 and 9, as measured, not promised. `Encoder::filter` is the `Filter` that decodes it, and `Prediction::predictor` the `/Predictor` a writer writes for it, which the `Filter` doesn't hold (10 plus `Row::tag`, 12 for Up). Data that can't be encoded, a layout that isn't one or data that isn't whole rows, is `Unencodable`, and the buffer is left as it was.
- **Predictors.** An LZW or Flate filter's `Predictor`: TIFF's (`/Predictor 2`), at 1, 2, 4, 8 or 16 bits a sample, and PNG's (10 to 15), each row by its own tag, undone in place, a short last row read with zeros and a row a fault cut off left out; a `Layout` says `/Colors`, `/BitsPerComponent` and `/Columns`.
- **Faults.** An `Error` has what decoded, through every filter, and each `Fault` with its filter's index, the first of each kind a filter: a byte a filter doesn't take, no end-of-data marker, a broken `~>`, a `z` inside a group, a group over 2³² − 1, a last group of one character, an LZW code not in the table, a full table, no zlib header, corrupt or truncated deflate data, a checksum that doesn't match, a PNG row tag that isn't one, a short last row, a layout that isn't one, the limit. Where the spec leaves a reading open it's qpdf's, but for a full LZW table, read past as PDFium and pdf.js read it; where a fault stops a filter what decoded before it is kept. `Fault`, `Error`, `Faults` and `Unencodable` are `std::error::Error`s, derived with thiserror; an `Error`, as `Faults`, displays each fault after its filter's index (`filter 0: no zlib header`), joined by `; `.
- **An error's `Debug` without what decoded.** `Error`'s `Debug` gives the length of its `data`, not its bytes, which may be a whole stream's, decrypted before it was decoded: `Error { data: 23 bytes, faults: [(0, Checksum)] }`, so a log or a failed assertion never prints a stream. The field is public, for a caller that wants the bytes. Two errors whose data are the same length have the same `Debug`, whatever their bytes, so a test compares errors by `==`, never by their `Debug` text, and shows `data` itself where it needs the bytes.
- **The limit, said.** `Fault::Limit` is a filter's output past the limit the call was given (before a PNG predictor, that limit and a tag a row), the filter stopping with as much as the limit allows, behind a predictor the whole rows that fit under it. The crate has no cap of its own, so the limit it says is always the caller's. With no filters, `decode` and `decode_into` give the data whole, past the limit or not, as the limit bounds what filters give.
- **Its backends and thiserror alone.** The crate depends on no other PDF crate: the white-space `ASCIIHexDecode` and `ASCII85Decode` ignore is its own, the six bytes ISO 32000-2 names (7.2.3), NUL, tab, line feed, form feed, carriage return and space, vertical tab not among them, which a unit test holds over all 256 bytes. Its dependencies are miniz_oxide and zlib-rs, each optional, by its feature, and thiserror.
- **Exhaustive on purpose, or not, and said.** `Filter`, `Predictor`, `Layout`, `Error` and `Faults` are exhaustive, each doc saying why: `Filter` is ISO 32000-2's filters for data of any kind, each with every parameter it reads, so a match on every filter is checked by the compiler, and a new standard filter would be a breaking release; `Predictor` is `/Predictor`'s three readings; `Layout`, `Error` and `Faults` are built by literals and taken apart by their public fields. `Fault`, `Backend`, `Prefix`, `Encoder`, `Prediction`, `Row` and `Unencodable` are `#[non_exhaustive]`, so a fault, a backend, a field of what a filter read, an encoder or a reason can join them in a minor release, a match on one needing a wildcard. `Row` is PNG's five filters, and non-exhaustive all the same: making it exhaustive later is a minor release, where the other way round would be a breaking one. An `Encoder` variant's fields are each public, so an encoder is built by a literal, and a field more would be a breaking release.
- **Hashed, marked, and `const` where it can be.** Every type but `Error`, which holds what decoded, a whole stream's perhaps, is `Hash`, so a caller can key a map by a stream's filters, or by how they faulted (`Faults`). `#[must_use]` is on every function whose result dropped is a mistake and whose type doesn't say so itself: `Encoder::filter`, `Level::new` and `get`, `Prediction::predictor` and `Row::tag`; none is on what gives a `Result`, or a pair holding one. `Encoder::filter`, `Level::new` and `get`, `Prediction::predictor` and `Row::tag` are `const fn`s, so a filter is had from an encoder in a constant. `decode`, `decode_into`, `decode_prefix_into` and `encode` say what fails them and when, under `# Errors`.
- **Benchmarks.** `cargo bench -p pdf-filters --features zlib-rs` times the decoders, the predictors and the encoder on each backend, on inputs the benchmarks make as they run, the same on every run: a page's content, about 1 MiB of text, decoded through `ASCIIHexDecode` (wrapped every 64 digits, and with a space after each byte's digits), `ASCII85Decode` (wrapped every 75 characters), `RunLengthDecode` and `LZWDecode`, and through `FlateDecode` beside incompressible bytes; cross-reference rows under PNG's Up predictor and an RGB image's rows under Paeth's, inflated; the image under TIFF's predictor; the text deflated then written in hex, through both filters; 1,000 small inline images, deflated and LZW-encoded, each decoded by `decode_prefix_into` from its start, given all the content after it; and the text deflated at levels 1, 6 and 9, and the cross-reference rows under PNG's Up predictor. Each backend's benchmarks exist with its feature, so they build with either or both. Throughput is in bytes of the data decoded or encoded. So a change is judged before and after it. The harness is criterion, a dev-dependency never built for a user of the crate, and `benches/` is outside the package.
- **The package, checked before a publish.** CI packages the crate as a publish would (`cargo publish --dry-run`, in a target directory of its own made fresh each time, so a stale build can't pass or fail it) and checks what the package holds: `src/`, the README, the CHANGELOG, the manifest and the lock, nothing else, no benchmark among them. CI tests and lints the crate with its default feature alone, the build a dependent that names no feature gets, as well as with zlib-rs alone and with both, and tests it on Rust 1.85, its `rust-version`, with both. The manifest names the crate's documentation (docs.rs). The README's licence links are the repository's URLs, which reach the files from crates.io and docs.rs, and a test holds them so.
- **Where it comes from.** Written for pdf-lint, a PDF checker, which decodes a file's streams through it, and an inline image's data in a content stream to find where it ends; no release before this one had it, pdf-lint 0.1.0's included.
- **Tests.** Unit tests for each filter and fault, every Flate test on each backend compiled in, the spec's LZW example, a test LZW encoder over every code width, round trips of Flate at every level under every row filter and layout, decoded on each backend, what each filter read of data that runs on (ended, not ended, corrupt, cut short, followed by other bytes, at the limit, the two backends side by side), and a fuzz target (`just fuzz filters`) whose body decodes on each backend, and encodes and decodes back, by one encoder or two (a second Flate listed before the first, so applied last, what the pair writes held byte for byte to the first's output encoded by the second alone), and holds what a filter read to the input (never past it; what it read, decoded alone, the same, but a missing end's fault; bytes after an end changing nothing), which three unit tests run on random and damaged inputs.
