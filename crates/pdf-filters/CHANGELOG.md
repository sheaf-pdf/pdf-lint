# Changelog

## 0.1.0 (unreleased)

- **The filters.** `decode` decodes data by a list of `Filter`s, as a stream's `/Filter` lists them: `AsciiHex`, `Ascii85`, `Lzw` (with `/EarlyChange`), `Flate` (zlib, on the `Backend` the call names) and `RunLength`, each given what the one before gave, no filter's output over the caller's limit (before a PNG predictor, its tags besides).
- **Two Flate backends, named at each call.** `Backend::MinizOxide`, with the `miniz_oxide` feature (on by default), and `Backend::ZlibRs`, with the `zlib-rs` feature (zlib-rs through its safe API, on Rust's allocator): each variant exists only with its feature, both with both, and `decode`, `decode_into` and `encode` each take the one they use, so no feature another crate turns on changes what a call gives; with neither feature the crate doesn't build, and docs.rs builds the docs with both. On clean data the two decode alike; on damaged data where each stops, how much it gave first and a `Corrupt` fault's place can differ. LZW stays this crate's own decoder, not weezl's, which reads on past a full table and says no place for a code that isn't in it.
- **Into the caller's buffer.** `decode_into` appends what it decodes to a `Vec` the caller gives, what it held kept, the limit counting only what's added, the last filter decoding straight into it (grown with zeros, cut to what was written, a predictor undone in place); on faults it keeps what decoded and gives `Faults`, the `(filter, fault)` list an `Error` has, displayed alike. `decode` is `decode_into` an empty `Vec`, cut to its length.
- **Encoding, for a writer.** `encode` appends `data` encoded by a list of `Encoder`s, listed as a stream's `/Filter` lists them (the last applied first), to a `Vec` the caller gives. `Encoder::Flate` takes a `Level` (0, stored, to 9; `Level::DEFAULT` 6, `Level::BEST` 9) and a `Prediction`: none, or PNG's with a `Layout` and a `Row` filter for every row (`None`, `Sub`, `Up`, `Average`, `Paeth`). Each backend deflates as flate2's `ZlibEncoder` does on it (a 32 KiB window, memory level 8, the default strategy; zlib-rs given 32 KiB to write into at a call, as flate2 gives it, since what it writes depends on where that room runs out), so the bytes are flate2's at the same level. `Encoder::filter` is the `Filter` that decodes it, and `Prediction::predictor` the `/Predictor` a writer writes for it, which the `Filter` doesn't hold (10 plus `Row::tag`, 12 for Up). Data that can't be encoded, a layout that isn't one or data that isn't whole rows, is `Unencodable`, and the buffer is left as it was. `Encoder`, `Prediction`, `Row` and `Unencodable` are `#[non_exhaustive]`.
- **Predictors.** An LZW or Flate filter's `Predictor`: TIFF's (`/Predictor 2`), at 1, 2, 4, 8 or 16 bits a sample, and PNG's (10 to 15), each row by its own tag, undone in place, a short last row read with zeros and a row a fault cut off left out; a `Layout` says `/Colors`, `/BitsPerComponent` and `/Columns`.
- **Faults.** An `Error` has what decoded, through every filter, and each `Fault` with its filter's index, the first of each kind a filter: a byte a filter doesn't take, no end-of-data marker, a broken `~>`, a `z` inside a group, a group over 2³² − 1, a last group of one character, an LZW code not in the table, a full table, no zlib header, corrupt or truncated deflate data, a checksum that doesn't match, a PNG row tag that isn't one, a short last row, a layout that isn't one, the limit. Where the spec leaves a reading open it's qpdf's; where a fault stops a filter what decoded before it is kept. `Fault` and `Error` are `std::error::Error`s, derived with thiserror; an `Error` displays each fault after its filter's index (`filter 0: no zlib header`), joined by `; `.
- **Tests.** Unit tests for each filter and fault, every Flate test on each backend compiled in, the spec's LZW example, a test LZW encoder over every code width, round trips of Flate at every level under every row filter and layout, decoded on each backend, and a fuzz target (`just fuzz filters`) whose body decodes on each backend, and encodes and decodes back, which three unit tests run on random and damaged inputs.
