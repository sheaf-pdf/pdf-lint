# Changelog

## 0.1.0-alpha.1 (unreleased)

First release. Until `0.1.0` stabilizes, alpha releases may include breaking API changes documented here; depend on the exact version (`=0.1.0-alpha.1`).

### Added

- `Point`, `Rect`, `Quad`, `Matrix`, `Rotation`, `PageSize`, and `PageGeom`: 2D PDF geometry, affine matrix composition and inversion, axis-aligned rectangle placement (`Matrix::onto`), and closed-form transforms between PDF PageSpace and viewer ViewSpace (`PageGeom::to_view`, `PageGeom::from_view`, `PageGeom::from_page`).
- `interpret` and `interpret_with`: bounded zero-I/O graphics and text state interpreter over `Concat` and `Resolve + Streams`, matching PDFium's content interpretation rules as of chromium/8152 (`Forms::Descend` and `Forms::Skip`, `Opts`, `Wants`, `Summary`).
- `State` and `TextState`: thread-safe (`Send + Sync`) graphics state tracking across `q`/`Q`/`cm`, line style, `DashPattern`, `RenderingIntent` (re-exported from `pdf-color`), `ActiveColorSpace`, `ColorValues`, `BlendState`, `SoftMask`, `SoftMaskParams` (`State::soft_mask_params` for `/BC` backdrop and `/TR` transfer functions), and `ExtGState` (`gs`) dictionaries, resetting `CA`, `ca`, `BM`, and `SMask` upon entering transparency-group Form XObjects (ISO 32000-2 §11.6.6).
- `PathDrawn`, `Seg`, `Clip`, `ClipPart`, and `ClipParts`: path construction (exposing both CTM-transformed `PathDrawn::segments` and pre-CTM `PathDrawn::user_segments`), fill/stroke bounds, `W`/`W*` path clips (including PDFium's single-point clip and auto-merge rules), text rendering modes `4..=7` (`Tr`) clipping, and Form XObject `/BBox` clips.
- `TextShow`, `Glyphs`, and `Glyph`: lazy glyph placement over `pdf-fonts` across `Tj`, `TJ`, `'`, and `"` (a string's bytes, or for `Tj`, `'`, and `"` a name's or `true` or `false` as written, as PDFium's `GetString` takes them; a `TJ` array's strings alone), with horizontal and vertical writing modes, `char_box` outline union, pen anchors, glyph matrices (`Glyph::tm`), and decoded Unicode text (`Glyph::text`).
- `FormUse`, `TransparencyGroup`, `UseId`, `Refused`, `ImageDrawn`, `ImageOf`, `ShadingDrawn`, and `At::{resources, page_resources}`: nested Form XObject entry/exit/refusal events with `/Group << /S /Transparency >>` metadata (`TransparencyGroup::from_dict`, `FormUse::group`), active vs. top-level `/Resources` accessors, placed XObject and inline image metadata with effective horizontal/vertical DPI (`ImageDrawn::dpi`, `ImageDrawn::dpi_with_unit`), and `sh` shading bounds.
- `Mark`, `MarkProps`, `Marks`, and `MarksIter`: marked-content sequence (`BMC`/`BDC`/`EMC`) and point (`MP`/`DP`) tracking across Form XObject boundaries with `/MCID`, `/ActualText`, `/OC`, and `/Artifact` helpers.
- `encode`, `encode_with`, and `EncodedPage`: content-stream and Form XObject re-encoder that rewrites relative line-moving text operators (`Td`, `TD`, `T*`, `'`, `"`) into position-independent `Tm` + `Td` pairs while preserving exact glyph, path, clip, and mark geometry.
- `Canvas` and `TextPiece`: high-level vector, inset border, rounded-rectangle, circle/ellipse, clip, placed image/Form XObject, marked-content, and `TJ`-kerned text builder over `ContentWriter`.
- `BoxBorderStyle`, `BoxBorder`, and `Canvas::box_border`: a rectangle's border drawn strictly inside it, in one balanced `q`..`Q` scope, in the five border styles of ISO 32000-2 §12.5.4 Table 168: `Solid` and `Dashed` (the frame inset by half the width; `[3]` where the dash array is empty, negative, non-finite, or all zeros), `Underline` (one segment along the bottom), and `Beveled` and `Inset` (the frame, then two mitered bands of the border's width inside it, shaded light and dark from an optional fill hint). `BoxBorder` borrows its dash array and is `Copy`; `BoxBorder::inset` says how far the border reaches into its box (twice the width for the two bevels). `Canvas::box_bands` draws a beveled or inset border's two bands alone, without the frame, in a scope of their own: the same operators `box_border` writes inside its frame, for a box whose edge is shaded where no color strokes its frame, and nothing for the other styles or where `box_border` would draw no bands. Every style sets its own dash inside its scope (a solid line for all but `Dashed`), so a dash the caller left set never shows in a border; the line cap, join and miter limit are the caller's. Nothing is drawn for a width that isn't finite and above `0`, a box that isn't finite (or that, grown by five times the width, isn't: a stroke whose extent `interpret` couldn't bound), or a box too small for the style.
- `Canvas::box_bands_in`: a beveled or inset border's bands as `Canvas::box_bands` draws them, in shades the caller gives, for a box whose shades change places (a button's down appearance); `box_bands` is it in the style's shades, its bytes as before.
- `DefaultAppearance`: bounded `/DA` default-appearance parsing (`parse`, under `pdf-content-streams`' `Limits`) and deterministic serialization (`to_bytes`) of the font resource name and size (`Tf`), device colors as `pdf-content-streams` `Color`s (the nonstroking `g`, `rg`, `k` as `color`, the text's, and the stroking `G`, `RG`, `K` as `stroke_color`, which filled text is never drawn in), and the text-state scalars `Tc`, `Tw`, `Tz`, `TL`, `Tr`, and `Ts` (ISO 32000-2 §12.7.4.3), with `size` (the fixed size a `Tf` above `0` gives), `auto_sized` (a `Tf` size of exactly `0`) and, under `text-layout`, `text_box_style` (auto-sized for exactly `0`; the default style's `12` where `Tf` is absent or its size is negative). `to_bytes` writes each color's components clamped to `0..=1`, as `parse` reads them, leaves out a size that has no font name, and writes `/Helv` for a name holding a NUL byte, which no name can. `parse_with` reads the same, whatever its `fault::Sink<Fault>`, and tells it what departs from §12.7.4.3, each at its byte offset into the string: `Fault::DefaultAppearanceUnreadable` (a string that fails to lex or passes a cap, its `pdf-content-streams` error's kind telling which; `None` is returned), `Fault::DefaultAppearanceOperand` (an operator ignored, or `Tf` read in part, for an operand missing or not finite, or a font that isn't a name), `Fault::DefaultAppearanceTextMode` (a `Tr` outside `0..=7`), and `Fault::DefaultAppearanceNoFont` (no `Tf` names a font); a sink that wants none, `&mut ()` among them, is told nothing, and `parse` is `parse_with` with `&mut ()`.
- `TextPage`, `TextPageOpts`, `PageChar`, `TextLine`, `SearchOpts`, and `TextMatch` (`text-layout` feature): `CPDF_TextPage`-compatible reading-order assembly with synthetic spaces/newlines, faux-bold deduplication, `/ActualText` replacement, `unicode-bidi` RTL reordering, soft-hyphen wrap detection, hit-testing, rectangular text extraction, merged selection quads, and search.
- `layout_text`, `Canvas::draw_layout`, `Canvas::text_box`, `LayoutFont`, `FontEncoder`, `TextBoxStyle`, `TextAlign`, `VerticalAlign`, `WrapMode`, `LaidOutText`, `LaidOutLine`, and `UnencodableChar` (`text-layout` feature): word/character wrapping, alignment, justification, automatic font sizing (the maximum size itself where the text fits at it), and comb-cell layout over `Std14` and `Font`. Two `TextBoxStyle` flags, both off by default, where off lays out as before: `line_end_spaces` keeps the spaces a wrapped line is broken at, finding words as PDFium's line breaking (as of chromium/8152) finds them (a line breaks before the last word begun on it where its next character, a space among them, would pass the box's width, so the spaces before that word end the line, in its codes, its range and the width it's aligned by; no space is trimmed or passed over; a word begins after a space or punctuation that doesn't join, an apostrophe, comma, hyphen, full stop and solidus joining, at an opening bracket, at a currency sign, and at or after an ideograph; and a line's width is each advance times the size and then `0.001`, summed in `f32`, the line passing the width where the sum is above it at all, so a line its glyphs fill exactly breaks where PDFium breaks it), and `font_heights_as_given` measures lines by the font's ascent and descent as `LayoutFont::font_metrics` gives them, without the floors (`0.70` and `-0.15` em, a height of `0.85`) that otherwise apply, which still do where the heights aren't finite or the ascent isn't above the descent. In Symbol, `Std14` also lays out the Greek letters Δ (U+0394), Ω (U+03A9) and μ (U+03BC) and the angle brackets U+3008 and U+3009, at the codes of the signs ∆ (U+2206), Ω (U+2126) and µ (U+00B5) and of U+2329 and U+232A, so text composed (NFC) keeps its omega sign and angle brackets.
- `pdf_fonts::embed::Program` as a `LayoutFont` and `ProgramFont` (`embed` and `text-layout` features): a TrueType program embedded in a document lays text out as pdf-fonts' `embed::write` writes it, its metrics, each character's advance its glyph's width and its code its glyph's number in the program, two bytes, high byte first; a character its `cmap` doesn't map is refused, never drawn as `.notdef`. The program records nothing. `ProgramFont::new(program, glyphs)` lays text out in it as it does and records each glyph it encodes in a shared `std::sync::Mutex<Glyphs>`, for a caller that draws through `Canvas::text_box` and embeds what was drawn; a lock a thread panicked holding is taken as it is. A layout refused part-way has recorded the glyphs before the refusal, and justified text in it is flush left, as `Tw` applies to no two-byte code. Its `Debug` gives counts alone.
- `FontSet`, `WithFallback`, `face_for`, `LaidOutCell`, `LaidOutRun`, `Canvas::draw_layout_in`, `Canvas::text_box_in`, `TextBoxError` and `TextBoxStyle::clusters` (`text-layout` feature): text laid out in more than one font. A `FontSet` is faces in order of preference (`faces`, and each face's `face_metrics`, `face_advance`, `face_encode`, and the `face_resource` it's drawn under, `None` by default); every `LayoutFont` is a set of one face, so `layout_text`, whose bound is now `FontSet`, takes every font it took, a `&dyn LayoutFont` among them, and lays it out as before. `WithFallback::new(first, second, second_res)` is two sets one after the other, the second's first face drawn under `second_res`, and nests for three fonts or more; its `Debug` gives the count of faces alone. Each unit of the text is drawn in the first face that has an advance and a code for every character of it, which `face_for` gives and the layout asks; a unit no face has is refused at the character the first face lacks (its first without an advance, else its first without a code), so a layout in one font refuses what it did. A unit is a character, or with `TextBoxStyle::clusters` (off by default) an extended grapheme cluster of Unicode Standard Annex #29, by unicode-segmentation: a character and its marks drawn in one face, one comb cell (its codes one string, centred by their advances together, `comb` counting clusters), and never split across lines. `LaidOutLine` gains `runs` (each run's face, the bytes of the line's codes it draws, its text, and its place from the line's origin, the advances before it and the word spacing of the spaces among them), `cells` of `LaidOutCell` (each comb cell's `origin`, `codes`, `face`, and `text` byte range, its `Debug` reporting `codes_len`), and the line's `ascent` and `descent` in points: the largest and smallest of the faces on it, from `0`, an empty line's the first face's, as PDFium sets a line of two fonts as of chromium/8152, and a comb line's the first face's widened by its cells'; the step from a line to the next runs from the one's descent to the other's ascent, times the leading factor, or is the line height given. Text the first face has every unit of, those past a comb's cells among them, is laid out as in that face alone, and lines all in one face, outside comb cells, as in that face alone, the same arithmetic in the same order. `Canvas::draw_layout_in(fonts, layout)` draws each comb cell and each string of a line under its face's resource, a `Tf` first and where the face changes and a `Tm` and `Tj` each: a line all in one face is its `codes` whole, as they are when it's drawn, and a line in several a string for each of its `runs`, so a caller that changes such a line's `codes` keeps its `runs` in step. `Canvas::draw_layout(font, layout)` is it with one font, its bytes as before. Both now return whether the layout was drawn: `false`, with nothing written, where a face something is drawn in has no resource among those given or a run names bytes its line's `codes` don't have, never a part of the text. `Canvas::text_box_in` is `Canvas::text_box` for a set, its first face under the resource it's given and every other under the set's own; where a face past the first that some of the text is drawn in has none it's `TextBoxError::NoResource` with the face, and a unit no face draws `TextBoxError::Unencodable`, the canvas untouched either way. `Canvas::text_box` itself takes one `LayoutFont` and refuses with `UnencodableChar`, as it did. A font is named only where something is drawn in it, so text a set's first face draws whole is drawn as that font alone draws it, byte for byte.
- `Limits`, `Cap`, `Error`, `Unwritable`, and `Fault`: per-page interpretation budgets and non-fatal diagnostics reported via `pdf-objects`' `fault::Sink`.
- Cargo features `programs` (default, forwarding `pdf-fonts/programs`), `text-layout` (default, enabling `TextPage` and multiline `Canvas` layout; it brings in unicode-bidi and unicode-segmentation), `predefined-cmaps` (forwarding `pdf-fonts/predefined-cmaps`), `embed` (forwarding `pdf-fonts/embed`, which brings in subsetter; with `text-layout`, a program embedded as a `LayoutFont` and `ProgramFont`; it doesn't turn `text-layout` on), and `tracing` (numeric phase spans).

### Notes

- Re-exports `pdf-objects`, `pdf-color`, `pdf-content-streams`, `pdf-semantics`, and `pdf-fonts` at the crate root. Requires Rust 1.92.
- Never panics on untrusted input, and `Debug` implementations and `tracing` spans never include file plaintext, resource names, tag names, or stream bytes.
- `Point`, `Rect`, `Quad`, `Matrix`, `Rotation`, `Seg`, `Forms`, `MarkProps`, and `TextPiece` are exhaustive on purpose; other public enums and configuration/metadata structs are `#[non_exhaustive]` so new variants and fields can be added without breaking callers. `TextBoxStyle` is exhaustive too, so that it can be built with a struct literal; build it with `..TextBoxStyle::default()` after the fields set, as a field added later breaks only a literal that leaves that out.
