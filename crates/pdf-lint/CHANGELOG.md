# Changelog

## Unreleased

- **The objects are pdf-objects'.** `object`, `text` and `version`, and `dict!`, are the new pdf-objects crate's, re-exported at the same paths and at the root as before; what they are is unchanged, but for a string's form and an edit (below), and that `text::Quirk` is `#[non_exhaustive]`, and a `Span` is made by `Span::new` as in 0.2.0. pdf-objects is MIT OR Apache-2.0 and builds with Rust 1.85, so a reader of its own can use the types without pdf-lint.
- **The object parser is pdf-objects'.** `bytes::read` reads each value and indirect object through pdf-objects' parser, whose faults and errors say what the reader's warnings and errors said, word for word, in the same order; which of a stream's extents is its data, by its `/Length` when that ends at `endstream`, and the warning when it doesn't, stay the reader's. `bytes::NESTING` is the parser's, re-exported. An object holds at most 2^25 values, keys among them (pdf-objects' `Limits::DEFAULT`), where the reader read one of any size: one with more is an error, as one nested deeper than `bytes::NESTING` is. Only a value reaches either: a token where a value should be that can't start one, `>>` or `endobj`, say, is the error it is, where the reader said it was nested too deep when it was past `bytes::NESTING`.
- **Breaking, the library: a string keeps its form.** `Value::String` holds the string's `Form`, `Literal` or `Hex`, beside its `Str`: `Value::String(Str, Option<Form>)`, so a pattern `Value::String(s)` is `Value::String(s, _)` now. `bytes::read` gives each string the form it was written in, a decrypted one too; a string built by `Object::string` or `Object::bytes` has none, and `Object::hex` makes a hex one. `Form` is re-exported at the root. `fn:IsHexString` reads it, unknown for a string without one, so it answers as before; the `hex` method of `Source` and the `hex` fields of `Document` and `Cx`, which gave it by a string's place, are gone.
- **Breaking, the library: an edit drops a value's span.** `Object`'s value is private, read by `value()` and taken by `into_value()`; `value_mut()`, `as_dict_mut()`, `as_array_mut()` and `as_stream_mut()` change it, each an edit, which drops its span, and the span of each value that holds it, so a span says where a value was written only while no edit has changed it. `as_written_mut()` keeps the span, for changing a value into what the same bytes stand for, as the reader does when it decrypts a string. A `Stream`'s `data` is a `Data`, where it was a span: `bytes::read` gives `Data::At(span)`, which `data.at()` reads; `Data::Bytes` holds a stream's bytes in memory (`Stream::new`, `set_bytes`). `Data` is re-exported at the root. `Stream` is `#[non_exhaustive]`, made outside the crate by `Stream::new` or `Object::stream`, a pattern that names its fields ending in `..`; `Value::Stream` holds a `Box<Stream>`, which a pattern can't see through, so `Value::Stream(Stream { dict, .. })` is `Value::Stream(s)` and `s.dict` now. `Dict::remove` gives the value it removed, so a closure that calls it and returns its value no longer returns `()`. And new: `as_bool`, `as_bytes`, `as_array` and `as_stream`; an `Object` from an `ObjectId`, an `f32`, a `String` (a name) and the smaller integers; `Dict::get_mut`, `iter_mut`, `has_type`, `type_name`, `remove_duplicates`, `collect` into a `Dict`, and `for` over a `&Dict`. A dictionary's lookups allocate nothing for up to 32 entries.
- **The model, its tables and predicates are pdf-arlington's.** `grammar`, `predicate`, `COMMIT` and the embedded model are the new pdf-arlington crate's, re-exported at the same paths and at the root as before, and `extension::ISO` too; what they are is unchanged, and `--version` names the same model and hash, but that `predicate::SUPPORTED` and `extension::ISO` are `&[...]`, not arrays of a fixed length, and `predicate::Expr` is `#[non_exhaustive]`, so a function or an extension can come without a breaking release. `extension::declared(&dyn Source)` stays, over pdf-arlington's, which takes the trailer's `/Root`, the metadata and a closure that resolves references, so pdf-arlington depends on pdf-objects' types alone. `predicate::TOLERANCE` is public there. Which model every check reads stays this crate's: `grammar()`, `use_model`, `grammar::NAMED` and `extension::named` are its own, at the same paths and saying the same, over pdf-arlington's `Grammar::embedded()` and `Grammar::extensions()`, as pdf-arlington chooses no model; `Grammar::embedded()` gives the embedded model as a `&'static Grammar`, read once, where it gave an owned `Result<Grammar>` read anew at each call. pdf-arlington is Apache-2.0, as the model is, and builds with Rust 1.85. This package no longer holds the model's files, nor licence files: upstream's LICENSE and NOTICE.txt, which the parts of the checker adapted from TestGrammar are under too, are in pdf-arlington's `model/`, and `src/check.rs`'s header carries the NOTICE's copyright and DARPA notices for those parts.
- **Breaking, the library: typed errors.** `Allowances::read` gives an `allowance::ReadError`, `Allowances::parse` an `AllowanceError`, `Hold::parse` a `HoldError`, `Exempt::parse` an `ExemptError` and `use_model` a `grammar::Refused`, where each gave an `anyhow::Error`; and pdf-arlington's `Grammar::load` and `predicate::parse`, re-exported here, a `grammar::Error` and a `predicate::Error`. Each derives `Display` and `std::error::Error` with thiserror, `#[non_exhaustive]`, a variant for each thing that can be wrong, with its line or path. Its `Display` is the whole message, word for word what `{:#}` printed before, so the command line says the same; and none has a `source`: a std error under one, reading a file or a number that doesn't parse, is a field, said after `: `. `AllowanceError`, `HoldError` and `ExemptError` are at the root too. anyhow is the command line's alone.
- **Breaking, the library: a `Cx` is made from a `FileCx`.** pdf-arlington's `predicate::FileCx`, re-exported here and at the root, is what every row of a file is evaluated in: `FileCx::new(trailer, version, &resolve)`, then `.size(..)` and `.extensions(..)`, once a file; `file.at(container, at)` makes a row's `Cx`, which `.parents(..)` and `.defaults(..)` complete, each giving a new one (`#[must_use]`), and whose `container()` and `at()` read it. `Cx`'s fields are private, so a literal of it no longer builds, and it has two lifetimes where it had one, `Cx<'c, 'a>`, the row's borrow and the file's: `&Cx` in a signature elides both, as before, but `Cx<'a>` written out no longer builds. The resolver `FileCx::new` borrows must outlive the `FileCx` and what holds it, so a walk that holds one declares its resolver before it. `FileCx` is generic over its resolver, `FileCx<'a, R>`, any of pdf-objects' `Resolve` (a closure among them, by value or by reference, or a `&Document` or `&Reading`), and `FileCx<'a>`, the default, names one over any resolver, a `dyn Resolve`, as a `Cx` reads through it: `&FileCx` in a signature takes a reference to one over any resolver, and one kept is kept by its resolver's type, or boxed (`Box<FileCx>`), as a closure's type can't be named. pdf-objects' `Resolve` is re-exported at the root, so a resolver of a type of its own, or a function over any, names it at the version pdf-lint takes. An object the resolver gives none for is null, whatever the reason: over a reading by position, one whose bytes the source failed to give, in that row and in any tree read then. It's `Send` and `Sync` when its resolver is, as `&Document` and `&Reading` are, so one a file can be shared across threads. The `FileCx` keeps what the predicates read of the file as a whole once read, the name trees' keys, the structure tree's content items and the form's fields' names, which the caller held in `predicate::{Fields, Structure, Trees}`, now gone; a name tree is kept by where its root was written and the number of the object its entry names, not by where its root is in memory, and one known by neither is read each time. `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems` know the objects the structure tree's content items name, and a row's container, by their numbers (`Cx::id` gives the container's), and one without a number by where it was written, not by where it is in memory: a container that can't be told apart from an item that could be it, as one built without its number, is unknown where it was false. `check` makes one `FileCx` a file, and gives each row the number of the indirect object its container is, when it's one. Every report is unchanged, but for a file whose object stream starts an object inside another's bytes, and whose structure tree names it: a page or image written directly at those bytes is now known as that object, where their places in memory told the two apart.
- **Breaking, the library: passwords as typed.** `bytes::read_opened` and `read_from_opened` take pdf-crypt's `Password`, a password as typed, where they took bytes, and try each in each of its encodings, the forms `text::passwords` gave, in the same order but that those that fit the file's revision come first (pdf-crypt's `Password::encodings` and `Handler::open`), in the empty password's place, as before: a wrong one leaves a file locked. `text::passwords` is gone, and `text` is pdf-objects' alone; pdf-crypt is re-exported as `pdf_crypt`, as pdf-structure re-exports it, for `Password`, `Encoded` and `Encoding`. `Encryption::Opened` says which password opened the file, and in which encoding (`by`, none for the empty password tried as none was given), and `Encryption::opened` takes it. The command line holds `--password` in zeroize's `Zeroizing`, wiped when it's dropped, from the moment clap gives it; its reports are unchanged. A test holds the PDFDocEncoding table pdf-crypt encodes by to the one `text::decode` reads with, character by character, as before.
- **A password in its SASLprep form.** `--password`, and each password `read_opened` and `read_from_opened` are given, is tried first in its SASLprep form (RFC 4013), as revisions 5 and 6 take a password (ISO 32000-2, 7.6.4.3.3), where that isn't the password as typed, then as before; and its single-byte forms are of the password composed (NFC). So a file whose password was set as the spec has it opens by the password as it was typed (Ⅸ, for one set as `IX`; an accent typed apart from its letter, for one set with them composed) and is checked, where before it was unread ("the password --password gives doesn't open it"). A password SASLprep refuses is tried as before, and every file a password opened, it opens still.
- **The reader is pdf-structure's.** `bytes` and `source` (`Source`, `Document`, `Trailer`, `Warning`, `Update`, `Encryption`) are the new pdf-structure crate's, re-exported at the same paths and at the root as before; what they read, and every warning and error they give, are unchanged. pdf-structure is MIT OR Apache-2.0 and builds with Rust 1.85. This package no longer depends on pdf-filters itself.
- **Breaking, the library: why an object doesn't read is typed.** `Source::get` gives a `source::Unread` where it gave a `String`, and `Document::unread` one for each object that doesn't read: pdf-structure's error, `#[non_exhaustive]`, derived with thiserror, a variant for each reason, whose `Display` is the text the `String` was, word for word, so every report says the same. A `Source` of its own says why in its own words with `Unread::Other`. `Trailer`, `Update` and `bytes::XrefEntry` are `#[non_exhaustive]`, and so are `XrefEntry::Free` and `Encryption::Opened`, so each can grow without a breaking release. None of the four can be written as a literal outside pdf-structure any longer, `Encryption::Opened { owner, by }` and `Update { objects, previous }` among them: a reader outside the crate makes its trailer by `Trailer::new`, setting `stream` and `unwritten` on it after, its update by `Update::new(objects, previous)` and an opened file's encryption by `Encryption::opened(owner, by)`; and a pattern that names `Opened`'s or `Update`'s fields ends in `..`.
- **A reading on demand.** `bytes::Reading`, pdf-structure's, re-exported with the rest of `bytes`, opens a file and reads each object when it's first asked for, from any thread, from bytes in memory or a file read by position, a window at a time (`bytes::FileBytes`, whose `bytes::Identity` tells whether it's changed), and read whole is what `bytes::read` gives, the reading taken or kept beside it (`into_document`, `to_document`), which reads every object so, by the same code; every report is unchanged. It hands out any stream's data when it's asked for (`data`), decrypted in an encrypted file that opened as an object stream's is, refused where it may be ciphertext the reader doesn't decrypt, and decoded through its filters (`decoded`), its error holding pdf-filters' where the data doesn't decode cleanly, which is re-exported as `pdf_filters` for it. Its limits are a value a caller sets (`bytes::Limits`, in `bytes::Options`), and they're the same in a build under cargo-fuzz (`--cfg fuzzing`), where the reader's were smaller: the fuzz target sets small ones itself. `Document` has where the bytes reader read each object (`record`, `records`) and a new field, `facts`, what the file says of itself as written, which a `Document` built by `Document::new` has none and the defaults of.
- **Mature crates in place of the tool's own code.** The model's hash is computed by twox-hash, the same XXH64 of the same bytes, so `--version` and every report's `model` are unchanged. `bytes::Identity` holds the file it's of open, through same-file, which knows it by its device and inode on Unix and its volume serial number and file index on Windows, so another file made at its path once it's removed isn't taken for it, by an inode reused or by the creation time NTFS gives such a file; it's `Clone`, and `bytes::FileBytes::identity` gives a reference to it. `bytes::Identity::of` opens the file to read, without waiting, so it needs leave to read it where its length and time needed none, and refuses a path that's neither a file nor a folder, a FIFO, a socket or a device, without opening it. The JSON reports are written by serde_json, byte for byte as before: the same keys in the same order, and the same escapes, backspace and form feed still `\u0008` and `\u000c`. The command line is parsed by clap. What stays: each option's meaning, its name, its value and its default, `-h` and `-V`; an option's value is the next word whatever it begins with (`--password -x`, `--hold -`), and the last of an option given twice wins; files go anywhere among the options, `-` once; an empty word is a file that can't be read, the others still checked; the exit codes; `--version`'s two lines; and every error that isn't about the command line, word for word. What changes: `--help` is in clap's layout, the same for `-h`, within 80 columns, and the README shows it as `cargo install --locked` builds it, with the lock's clap; an argument error is clap's, `error: ...` then `For more information, try '--help'.`, with the usage line between where clap gives one, where it was `pdf-lint: ...` and, for an unknown option or no file, the whole usage. A refused value keeps its reason after clap's words (`invalid value '0' for '--jobs <N>': not a number above 0`), as `- -` and the options that can't go together keep theirs (`error: --hold and --built: ...`); a missing value is `a value is required for '--hold <FILE>' but none was supplied`; an unknown option is `unexpected argument '--bogus' found`, with a tip; a value that isn't UTF-8, for an option that takes text, a number or a word, is `invalid UTF-8 was detected in one or more arguments`; and no arguments at all print the help on standard error, exit 2. Taken now: `--option=VALUE` beside `--option VALUE` (`--password=PW` was an unknown option, and its error printed the password), and `--` ending the options so that a file beginning with `-` can follow. `-h` and `-V` each stand alone, as before: a word that begins with one and goes on, `-hV` or `-hold`, is an unexpected argument, which clap alone would take for the flag, printing the help and exiting 0. A word beginning with `-` that isn't UTF-8 is an unexpected argument, where it was a file; after `--` it's a file still. clap, serde and serde_json, and anyhow, are the binary's alone, under the `cli` feature, which is on by default: a crate that uses the library alone leaves them out with `default-features = false`. An archive's `THIRD-PARTY-NOTICES.txt` lists twox-hash (MIT), same-file (Unlicense/MIT), serde, serde_core, serde_json, itoa, clap, clap_builder, clap_lex and anstyle (MIT OR Apache-2.0), memchr (Unlicense OR MIT), and zmij and strsim (MIT); Linux's libc (MIT OR Apache-2.0) too, which macOS's listed already; and Windows' winapi-util (Unlicense OR MIT), windows-sys and windows-link (MIT OR Apache-2.0), which same-file reads a file's index through. It gives each one's licence files, and says each crate is under the licence it names, no longer that each offers the Apache License 2.0.
- **Breaking, the library: a document's objects through methods.** `Document`'s `objects` field, a public map, is private, each object kept with where the reader read it while it's as read, so a record is always of the object beside it. `contains(id)` says whether an object is listed, read or not, where `objects.contains_key(&id)` did; `objects()` gives each that reads, by number, `range(..)` those in a range of ids, and `unread()` each that doesn't, with why; `Source`'s `ids` and `get` read as before. `set(id, object)` puts one in, with no record, giving back the one it replaces; `insert(n, object)` is as before, `set` at generation 0; `set_unread(id, why)` puts why one doesn't read, where a reader outside the crate inserted an `Err`; `remove(id)` takes one out, its record with it; and `get_mut(id)` gives one to edit, dropping its record, where `objects.get_mut` or `values_mut` did. `--last-update` asks the revision before by `contains`, so its reports are unchanged. A document numbers new objects past every number the file lists (`new_id`, `add`, `max_id`, `set_max_id`), follows references (`dereference`, `get_dict`, `get_dict_mut`, `catalog`, `catalog_mut`), changes its trailer's dictionary (`Trailer::dict_mut`), and walks what its trailer reaches (`reachable`) and removes the rest (`prune`); two documents are equal only where their new ids start at one number too.

## 0.2.0 (unreleased)

- **Breaking, the library: qpdf is gone from it.** `Qpdf`, the `Decode` trait, `Written`, `read_with` and `qpdf::OLDEST` are no longer public (the tests keep them, to set the reader beside qpdf), and nothing shipped reads `PDF_LINT_QPDF`. `bytes::read_from(file, section)` takes no decoder; `read` and `read_from` open an encrypted file with the empty password, `read_opened` and `read_from_opened` with the passwords given. `Encryption` is `#[non_exhaustive]`. `Str::Text` stays, for a `Source` that reads through another tool.
- **Breaking, the library: room to grow.** `Document`, `Finding`, `Warning`, `Report` and `Span` are `#[non_exhaustive]`, so a field can come without a breaking release, and `Rule`, so a rule can: outside the crate, a reader starts a `Document` by `Document::new` and makes a `Span` by `Span::new` and a `Warning` by `Warning::new`, a `Report` starts from `Report::default()`, a `Finding` is only the checker's to make, a pattern that names their fields ends in `..`, and a match on `Rule` needs `_`. `Document::encryption` is a new field (below), which a 0.1 reader building a `Document` whole has to fill.
- **The reader decodes for itself.** `bytes::read` decodes cross-reference streams and object streams through the new pdf-filters crate: ASCIIHex, ASCII85, LZW, Flate and RunLength, with their predictors, `/Filter` and `/DecodeParms` read as qpdf reads them (abbreviations, `/Crypt` as no filter, one parameters dictionary for every filter, `/Filter null` or `[]` as none, a reference to no object as null). So such a file needs no qpdf. A stream decodes to at most 256 MiB, and the streams of a reading of a file to 1 GiB in all (`bytes::STREAM`, `bytes::BUDGET`); a cross-reference stream's predictor rows are read whole; and no more cross-reference entries are read than the file has bytes, or 2²⁰ if that's more, so a small stream can't list hundreds of millions of objects (objects may still be numbered sparsely).
- **The reader decrypts for itself.** `bytes::read_opened` and `read_from_opened` open an encrypted file with the passwords they're given through the new pdf-crypt crate's standard security handler (revisions 2 to 6, the owner's password or the user's): object streams are decrypted before they're decoded, and strings decrypted where they are, so their bytes are exact, where qpdf gave text whose encoding it didn't say; a signature's `/Contents` isn't decrypted, as it isn't encrypted, nor the encryption dictionary's strings, an earlier update's too. `Document::encryption` says whether a file is encrypted and whether it opened, is locked, or has a handler the reader can't open (then, as before, its strings stay ciphertext and its object streams aren't read, said as a warning). A string or stream that doesn't decrypt cleanly is a warning, once an object and a fault, and so is `/Perms` that doesn't match or doesn't confirm the key. A file no password opens, or whose handler the reader can't open, whose strings and streams are `/Identity`, as one that encrypts only its embedded files has, reads whole all the same (`Encryption::Plain`), but for an object stream whose own `/Crypt` filter encrypts it. An encryption dictionary's values are followed where they're references, a crypt filter's in `/CF` too, and what they refer to isn't decrypted; its `/EncryptMetadata false` puts the metadata in plain view whether the file opens or not.
- **The command line runs no qpdf.** It reads every file itself, an encrypted one by `--password`, tried as typed (UTF-8, which revisions 5 and 6 take) and then in PDFDocEncoding, WinAnsiEncoding and MacRomanEncoding where they have every character of it (`text::passwords`), as qpdf tries it. An encrypted file is unread only when no password opens it and it encrypts its strings or streams; one whose handler the reader can't open is checked, its strings ciphertext and its object streams unread, as 0.1 checked one qpdf couldn't open. `--qpdf` is gone, and `--version` no longer names a qpdf; a script that passes `--qpdf` now exits 2 for an unknown option. Fixed with it: an encrypted file qpdf stopped on, as on a damaged page tree, was taken as one that opens and checked with nothing decrypted; now it's unread when no password opens it.
- **The archives hold no qpdf.** A release archive is `pdf-lint` and the Arlington model's notices, its layout otherwise as before; the Linux binaries are static and need nothing of the system (0.1's bundled qpdf needed glibc 2.34). `cargo install` needs no qpdf either.
- **The archives' notices** of what's compiled in: `THIRD-PARTY-NOTICES.txt`, each crate and its licence, with its package's licence files, written per platform from `Cargo.lock`; `RUST-NOTICES.html`, the Rust standard library's; `MUSL-COPYRIGHT` on Linux. The Windows binary links the C runtime statically, so it needs no Visual C++ Redistributable.
- **A scanned file's trailer.** When no cross-reference section reads and the file is scanned, its last trailer takes the `/Root`, `/Encrypt`, `/ID` and `/Info` it lacks from earlier trailers, as a linearized file's first-page trailer has them, saying so: such a file is read from its root, and an encrypted one's key made with its `/ID`.
- **What reads that didn't.** Data a fault stopped, which qpdf gives back undecoded, is read as far as it decoded, so the objects in it that it reaches are checked; one the cut ends that nothing closes, a number, a name, a keyword, isn't read, as it may be cut short. An object stream filtered with RunLength, which qpdf's default decode level leaves alone, decodes. With `--last-update`, the revision before decodes its streams from its own bytes, as the reader finds them there.
- **Faults in a stream's data are findings.** Each fault pdf-filters meets in a stream the reader decodes, the first of each kind a filter, is a `reader` finding on the stream: at the byte where the first filter met it, else at the stream's data. So a file qpdf reads without a word can be found for one, and a file clean before can exit 1: a missing end-of-data marker (`>`, `~>`, LZW's 257, run-length's 128), an Adler-32 checksum that doesn't match, a truncated or corrupt Flate stream, an unknown PNG row tag, a short last row. A cross-reference stream whose data runs past its rows isn't one, as unfiltered data that does isn't.
- **Messages.** A stream that doesn't decode says why in the reader's words (`its filter /JBIG2Decode isn't one the reader decodes`, `its /DecodeParms has 2 entries for 1 filters`), where it said qpdf didn't decode it or that nothing did.
- **Faster object streams.** An object read from an object stream no longer copies the stream's whole data first.
- **A FILE of `-` is standard input,** so a file can be piped in without writing it first. It's named `-` in the report and in an allowance, and can be given once.
- **Fixed: `--version` or `--help` piped to a reader that stops,** as `head`, panicked when the pipe closed. Now it stops quietly and exits 0, as a report already did.

## 0.1.0 (2026-10-25)

- **The model.** The Arlington PDF Model's `tsv/latest` at `d148fee`, embedded by `build.rs`; `grammar()` reads it once, `Grammar::load` a newer checkout.
- **The checker.** `check` walks a file from its trailer as TestGrammar does and holds what `Hold` names to the tables it's reached as, with the predicates of `predicate`, `Report::beyond` and `Allowances` (six columns: table, key, rule, file, version, reason). Every finding says where its bytes are (`Finding::at`); a key written twice is a finding (`duplicate`), and so is what the reader had to choose how to read (`reader`); a string whose bytes the reader didn't give is checked where it can be and counted as not checked where it can't; `Options` takes a writer's exempt keys and a version to check at.
- **Readers.** The `Source` trait and `Document`; the object model, every value and key with its `Span`, dictionaries as written, `Str::Bytes`, `Text` and `Encrypted`; `bytes::read`, a reader of a file's bytes on pdf-tokenizer; a `text` module for text strings, from the spec, saying where one departs from it.
- **Decoding.** `bytes::read_with` and the `Decode` trait, asked twice at most, for the compressed cross-reference streams and then the object streams that are compressed or in a file that encrypts (another's are in plain view); objects read from an object stream are placed in its decoded data, which `Document::decoded` keeps. `Qpdf` decodes through qpdf's JSON, decrypting in an encrypted file, with a timeout; a lenient JSON reader and base64 come with it, so there's no new dependency.
- **Plaintext, and decoding from bytes.** In an encrypted file, `bytes::read_with` asks the decoder (`Decode::plaintext`) for the objects whose strings are in plain view, and places each string's plaintext on its ciphertext. A cross-reference stream whose decoded rows aren't the size its `/W` and `/Index` make, as when a later update gives its number to another object, is decoded again from its own bytes (`Decode::decode_written`, through a file of its own for `Qpdf`), and so is an object stream the decoder can't decode, in a file that isn't encrypted.
- **A reader through qpdf alone.** `Qpdf::read`, a `Source` from qpdf's JSON, without spans; its trailer's cross-reference stream found by its dictionary, qpdf's warnings read with their objects, and a reconstructed file's trailer marked so. An ignored test sets the two readers side by side across a folder of PDFs (`PDF_LINT_CORPUS`) and counts each kind of difference.
- **Fixed, found by setting them side by side:** a table's row with a number out of range lost the whole table, where now it's read as free and the rest read; `/Encrypt null`, or a reference to no object, was taken as encrypted; an in-use entry for object 0 was listed.
- **Values, as a summary.** A finding's value has a dictionary's keys in order and leaves out a stream's encoding, so that it's the same after a rewrite that sorts keys or encodes streams anew; an object nothing reaches is alike by the object alone, whichever reference to it is named.
- **Predicates: arithmetic and defaults.** `+`, `-`, `*` and `mod` are evaluated, `*` and `mod` first, integers kept integers, and an overflow, a `mod` of a fraction or of 0 not checked. A SpecialCase's or PossibleValues' `@Key` the object lacks or has null takes the key's DefaultValue, as INTERNAL_GRAMMAR.md's "Parameters to predicates" has it and as readers take it; Required's doesn't, as the model's author asks (upstream issue #30).
- **Predicates: ten more functions.** `fn:RequiredValue` (a value that must be one value when its condition holds, whatever else is listed, as INTERNAL_GRAMMAR.md says), `fn:StringLength`, `fn:FileSize` (`Source::size`), `fn:ArraySortAscending`, `fn:Contains`, `fn:IsHexString` (`Source::hex`, from the bytes reader), `fn:AlwaysUnencrypted` and `fn:IsPDFTagged`. `fn:Ignore` and `fn:IsMeaningful` are notes to readers that ask nothing of a value: a key they say readers ignore is counted in the report's `ignored`, in `--full` and the JSON. They find, among others: a font's 12-byte `/Panose` written as 6, AES-256 `/O` and `/U` of 127 bytes where 48 are due, signatures' `/Contents` as literal strings, cross-reference streams' `/Index` out of order, and `/R 6` before PDF 2.0.
- **Predicates: name trees, key maps, `parent::` past arrays.** `fn:InNameTree` (each name tree's keys read once a file, through its `/Kids`) and `fn:InKeyMap`; a row that's absent isn't in the tree, and one that isn't a string (or name) can't be told. A key after `parent::` goes past an array to what holds it, so that an object or marked-content reference in a `/K` array reads its structure element's `/Pg`; an index stays in the array. `fn:IsFieldName` is left unevaluated: the model asks a partial field name of a hide action's `/T`, which ISO 32000-2 makes fully qualified (since corrected, below). They find GoTo actions naming destinations their file's tree doesn't have, and object and marked-content references whose page nothing gives.
- **Predicates: structure content items.** `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems`, from the structure tree, read once a file (ISO 32000-2, 14.7.5: content items are its leaves): an image is one when an object reference points at it, and a page has them when an element puts marked content on it, by an MCID on the element's `/Pg` or a marked-content reference's own `/Pg`, not in a form XObject's stream. Where an item's page can't be told, a page it isn't found on can't be either. They find pages the structure tree puts content on without their `/StructParents`.
- **Two tables at once.** A field and its widget merged in one dictionary (ISO 32000-2 12.5.6.19), which the model splits between `AnnotWidget` and a field's table, is checked as both: a widget with `/T` or a key only fields have as the field table its `/FT` and `/Ff` say, its own or inherited, and a field whose `/Subtype` is `/Widget` as the widget's; and so is what both link a key of theirs to, as the triggers of its `/AA`. Each key is checked against each table that lists it, a finding both make made once, and unlisted only if neither lists it (`Report::two_tables`). A key of an object reached again as another table is unlisted only if that table doesn't list it either. `--one-table` (`Options::one_table`) checks as TestGrammar does, the first table alone; the JSON says which as `one_table`, and counts `two_tables`. So a merged field's keys aren't unlisted, the field tables' own rules are checked, and what's under fields' keys is reached: signatures' dictionaries, value streams, choice options, field triggers' scripts.
- **Corrections to the embedded model.** `model/corrections.tsv` lists cells where the model contradicts ISO 32000-2, which `build.rs` corrects in the embedded copy only, stopping the build when upstream's cell has changed (`grammar::corrections`); the files in `model/tsv/latest` stay upstream's byte for byte, and `--model` reads a checkout as it is. The first: the button field tables require `/DA`, which ISO 32000-2 Table 228 requires only of fields containing variable text, as the model's own signature field table has it. The second: a hide action's `/T` string, and each in `ArrayOfActionHideAnnots`, asks `fn:IsFieldName`, a partial name, where ISO 32000-2 asks the fully qualified name of a field; corrected to `fn:IsFullyQualifiedFieldName`, which pdf-lint defines: the name of a field of the file's form, its partial names joined by periods, a field without `/T` named as its parent (the names read once a file). So a hide action naming no field is found. The embedded model's hash is now of the corrected tables (and the added ones, below), `fc22d1fadc1fd269`, where upstream's at the same commit is `c2bdcab22f823d8d`; `--version` says how many cells are corrected, and a release archive carries the list as `ARLINGTON-CORRECTIONS.tsv`.
- **Deprecations counted, found when asked.** What the version checked at deprecates, a key, a type or a value, is counted by table and key (`Report::deprecated`, in `--full` and the JSON's `deprecated`), and a finding only with `--deprecations` (`Options::deprecations`), with which what a file is set against is checked too; the JSON says which as `deprecations`. Most deprecations are a writer's legacy, as Acrobat's `/DR` on every field, one per field.
- **Extensions a file declares.** A file is checked under the extensions it declares, as the model names them (`extension::declared`, `Report::extensions`): Adobe's level 3 or later at 1.7 and ETSI's, from the catalog's extensions dictionary, ISO's by the number under `/ISO_`, and PDF/A-3 and PDF/VT-2 from its XMP metadata, which the bytes reader keeps where it's unfiltered and unencrypted (`Source::metadata`). Under them, `fn:Extension` holds, a key, type, value or link under one is the model's from the extension's version, and a key under one isn't unlisted. `--extensions` names more (`Options::extensions`), as TestGrammar's does: the model's names, a comma between, a name the model hasn't refused (`extension::named`), and, unlike TestGrammar's, no `*` for all, as each is a claim about the file; a baseline and the revision before an update are checked under them too. So, among others, a page's `/Tabs /W` in a 1.7 file at Adobe's level, a PAdES signature's `ETSI.CAdES.detached` where ETSI's is declared, and a PDF/A-3 file's associated files are no findings, and what's under them, as rich media annotations, is reached and checked. `--full` and the JSON (`extensions`) say which.
- **More corrections: `/DecodeParms` and `SMaskInData`.** The 36 stream tables' `/Filter` SpecialCase, that `/DecodeParms` be as long as `/Filter`, asks it only when `/DecodeParms` is there, which ISO 32000-2 lets a stream leave out (7.3.8.2); and an image's `SMaskInData` defaults to 0 (8.9.5).
- **A file that won't open with the password given is unread.** An encrypted file that qpdf can't open, with no password or a wrong one (`Qpdf::locked`, its `--requires-password`), is a file that can't be read, exit 2, saying it needs a password or that `--password`'s doesn't open it; and so is such a baseline. Before, nothing in it decoded: what its object streams held was found unresolved or unreached, and a file without object streams could look clean.
- **A file that needs qpdf without one is unread.** A file with anything compressed or encrypted, when the qpdf it would run isn't found, doesn't run, or is older than 11.9 (`Qpdf::ready`), is a file that can't be read, exit 2, in a line saying why and to install qpdf 11.9 or later or name one with `--qpdf`; before 11.9, qpdf writes a name that isn't UTF-8 into its JSON as the name's bytes, which isn't JSON, and nothing of that run reads; and so is such a baseline. A file all in plain view is checked without qpdf. `--version` says why there's no qpdf to decode with, when there isn't.
- **The JSON says which pdf-lint wrote it, and against which model,** as `pdf_lint` and `model`, in every line, a file's that couldn't be read too.
- **Additions to the embedded model.** `model/additions` holds tables in upstream's format that `build.rs` adds to the embedded copy, a table upstream lacks whole and one it has row by row, each row's Note saying why, stopping the build when upstream has an added row's key or table itself (`grammar::additions`, `Addition`); `--version` says how many rows are added. The first: a variable-text field's own `/DR` (PDF Reference 1.4, Table 8.51), on the text and choice field tables, obsolete from 1.5 (PDF Reference 1.7, implementation note 118); and `EncodingMap`, the PDF 1.0 `Encoding` resource as a dictionary of named encodings, which a correction links `Resource/Encoding` to in place of the one encoding the model checked it as. So a text field's `/DR` and an `Encoding` resource's names aren't unlisted, and what they reference is reached. From PDF 1.5 on, a field's `/DR` is deprecated (counted only, unless `--deprecations` makes it a finding, below), and so is the `/Encoding` in it, which the model has deprecated since 1.2. The embedded model's hash is now `fc22d1fadc1fd269`.
- **`--unlisted built|all|never`** (`Options::unlisted`, `UnlistedIn`): which held objects a key the model doesn't list is a finding in. `built`, the default, as before; `all`, merged objects too, where with `--baseline` or `--last-update` what the earlier file had is carried (each checked with the same setting); `never`, none. `--exempt` takes `--unlisted all` in place of a built object, and refuses `never`; the JSON says which as `unlisted_in`.
- **Three more syntax faults, as the reader's findings.** A name with a `#` that two hex digits don't follow, or with `#00`, NUL (ISO 32000-2, 7.3.5), which readers read each their own way, on the object it's in; a cross-reference table whose rows aren't 20 bytes, ten digits, a space, five digits, a space, `n` or `f` and a two-byte end of line (7.5.4), once a table, with how many and the first; and a file whose last line isn't `%%EOF` alone (7.5.5): bytes after it, on a line with something else, none in the last 1024 bytes, where readers look, or none at all. The end is asked of the file read whole, not of a previous revision.
- **Fuzzing.** `pdf_lint::fuzz::check_file`, the body of a cargo-fuzz target (`just fuzz check`): a file read from its bytes and checked, held and checked as its first two bytes choose, asserting no panic, the same report twice, and every finding's bytes inside what was read, and, for a file with an incremental update, set against its previous revision. `pdf_lint::fuzz::seeds` makes files for it to begin from, and a unit test checks thousands of their mutations on stable Rust.
- **Release archives.** A workflow builds, on a version tag, an archive for Linux (x86_64 and aarch64, the binary static), macOS (arm64 and x86_64) and Windows (x64), each with qpdf 12.4.2 from its official zips, pinned by SHA-256, and the notices and licenses that go with it, and the Arlington model's NOTICE.txt; checks each runs as it's unpacked; and drafts a GitHub release with them. The command line finds the qpdf beside it, after `--qpdf` and `PDF_LINT_QPDF`, and `--version` says which it found. CI tests against the same qpdf, and builds and checks the Linux x86_64 archive.
- **The command line.** `pdf-lint FILE...` with `--hold`, `--built`, `--exempt`, `--last-update`, `--pdf-version`, `--model`, `--one-table`, `--unlisted`, `--deprecations`, `--extensions`, `--allow`, `--full`, `--qpdf`, `--password`, `--jobs` and `--format`, each finding printed with its bytes, from the decoded data for one in an object stream. `--jobs` checks files at once, as many as there are CPUs by default, and reports them in the order given; a panic is reported as that file's, and the rest are checked. A report no one reads any more, piped to `head`, stops it without a panic. `--last-update` holds what the newest incremental update wrote, rewritten objects as merged and new ones as built, and leaves out what a rewritten object or the trailer already had in the revision before (`Document::update`, `bytes::read_from`, `Report::since`). `--format json` writes a line of JSON for each file. `--exempt` names the keys a writer writes on purpose that the model doesn't list, or the beginnings of keys (`Exempt::parse`). `--pdf-version` checks a file as another version, and a baseline, the revision before an update and the allowances' versions as that too; the JSON says it as `checked_as`. `--model` checks against a checkout of the model's `tsv/latest` in place of the embedded one (`use_model`), refusing one that doesn't read whole or lacks a table the checker reads by name; the JSON report's `model` says which model, by its hash: XXH64 of its tables' files (`Grammar::hash`), the same for the same tables wherever they're read from, which `--version` prints for the embedded one. `--baseline` leaves out what the file each was written from already had: by object for an incremental update of it (`Report::since`), by path for a rewrite, and anywhere where it has nothing at that path (`Report::by_path`, `Options::paths`).
