# Changelog

## Unreleased

- **Rust 1.89.** The minimum Rust is 1.89, from 1.88: the family's, moved for the RustCrypto releases pdf-crypt wants (its CHANGELOG says which).
- **The fuzz target counts the metadata a locked file leaves in plain view as read.** Its check that every finding's bytes are within what was read knew the file and a stream's decoded data; a file encrypted by a security handler the reader can't open, whose encryption dictionary says its metadata isn't encrypted, has its XMP read all the same (`Source::metadata`, in plain view), and a finding in that packet's bytes failed the check. The check knows the packet's stream now, and a seed (`locked-plain-metadata`) holds the shape.
- **The objects are pdf-objects'.** `object`, `text` and `version`, and `dict!`, are the new pdf-objects crate's, re-exported at the same paths and at the root as before; what they are is unchanged, but for a string's form and an edit (below), and that `text::Text`, `text::Quirk` and `text::Encoding` are `#[non_exhaustive]`, so a `Text` is read by its fields and isn't built or matched without `..` outside pdf-objects, a match on `Encoding` wants a wildcard, and it has `Utf16Le` more, and a `Span` is made by `Span::new` as in 0.2.0. New there, as pdf-objects writes text strings and reads them by PDFium's rules too: `text::encode`, `text::encode_as` and its `Unencodable`, `text::decode_with`, with `Rules` at the root to give it, and `Object::text`. pdf-objects is MIT OR Apache-2.0 and builds with Rust 1.89, so a reader of its own can use the types without pdf-lint.
- **Breaking, the library: ids are pdf-objects' struct.** `ObjectId`, re-exported at the root, is pdf-objects' `struct ObjectId { number, generation }`, where it was the pair `(u32, u16)`: `Finding::object`, `Hold::Only`'s map, `Span::stream` and `Warning::object` hold it, and a library user's `(1, 0)` is `ObjectId::new(1, 0)`, `id.0` `id.number`. The reports don't move: the JSON's `[n, g]` and the text's `n g R` are written as they were.
- **Breaking, the library: a `Source` is a `Streams`, and a reading is one.** pdf-structure's `Source`, which `check` takes, is pdf-objects' `Streams` too (`trait Source: Streams`): a stream's data as a viewer takes it, beside `decoded_within`, the reader's own account, which the checks read as before. Its `warnings` give a `Cow<[Warning]>` and its `metadata` an `Option<Cow<[u8]>>`, which a document lends (`&source.warnings()` or `.iter()` where a slice was, `.as_deref()` where an `Option<&[u8]>` was); and a read the source of the file's bytes failed is `source::Unread::Source`. A `Source` of one's own implements `Streams::decoded` and the two shapes; `Streams` is re-exported at the root, as `Resolve` is, so it names the trait at the version pdf-lint takes. `bytes::Reading` is a `Source` now, answering of what it has read when it's asked; what the tool checks is a file read whole beside its reading (`bytes::WithReading`), as before, and the reports don't move. `check` given a `Document` alone reads a font whose streams are all object streams the document holds decoded whole, as a document gives their data now, where it left every font that asked for a stream's data unread; a font with any other stream is left unread, as before.
- **The object parser is pdf-objects'.** `bytes::read` reads each value and indirect object through pdf-objects' parser, whose faults and errors say what the reader's warnings and errors said, word for word, in the same order; which of a stream's extents is its data, by its `/Length` when that ends at `endstream`, and the warning when it doesn't, stay the reader's. `bytes::NESTING` is the parser's, re-exported. An object holds at most 2^25 values, keys among them (pdf-objects' `Limits::DEFAULT`), where the reader read one of any size: one with more is an error, as one nested deeper than `bytes::NESTING` is. Only a value reaches either: a token where a value should be that can't start one, `>>` or `endobj`, say, is the error it is, where the reader said it was nested too deep when it was past `bytes::NESTING`.
- **Breaking, the library: a string keeps its form.** `Value::String` holds the string's `Form`, `Literal` or `Hex`, beside its `Str`: `Value::String(Str, Option<Form>)`, so a pattern `Value::String(s)` is `Value::String(s, _)` now. `bytes::read` gives each string the form it was written in, a decrypted one too; a string built by `Object::bytes` has none, and `Object::hex` makes a hex one. `Form` is re-exported at the root. `fn:IsHexString` reads it, unknown for a string without one, so it answers as before; the `hex` method of `Source` and the `hex` fields of `Document` and `Cx`, which gave it by a string's place, are gone.
- **Breaking, the library: `Object::string` is gone.** It kept a Rust string's UTF-8 bytes as a byte string, which read back as a text string (ISO 32000-2, 7.9.2.2) only when the text was ASCII: `é` read back as `Ã©`. `Object::text` writes a text string that reads back as given, as it did, literal where PDFDocEncoding holds it and hex as UTF-16BE; `Object::bytes` is a string of bytes as they are. For ASCII, `Object::text` writes the bytes `Object::string` wrote.
- **A font with a stream past a cap the reader reads under is said so, not as past the budget.** pdf-objects' `Why` tells a stream past the limit a caller asked for (`Why::Limit`) from one past a cap the reader reads under (`Why::Capped`, new: an object nested deeper or of more values than the reader parses, a stream's data longer or through more filters than it decodes, a chain of references longer than it follows), where one answer said both; pdf-lint told the filters' cap by asking the reader's own account again, and reads every cap from the answer now. A font whose stream is an object past the reader's parse caps was said to be past the file's budget, and is said to be past a cap it's read under; every other report is as it was.
- **Breaking, the library: an edit drops a value's span.** `Object`'s value is private, read by `value()` and taken by `into_value()`; `value_mut()`, `as_dict_mut()`, `as_array_mut()` and `as_stream_mut()` change it, each an edit, which drops its span, and the span of each value that holds it, so a span says where a value was written only while no edit has changed it. `as_written_mut()` keeps the span, for changing a value into what the same bytes stand for, as the reader does when it decrypts a string. A `Stream`'s `data` is a `Data`, where it was a span: `bytes::read` gives `Data::At(span)`, which `data.at()` reads; `Data::Bytes` holds a stream's bytes in memory (`Stream::new`, `set_bytes`). `Data` is re-exported at the root. `Stream` is `#[non_exhaustive]`, made outside the crate by `Stream::new` or `Object::stream`, a pattern that names its fields ending in `..`; `Value::Stream` holds a `Box<Stream>`, which a pattern can't see through, so `Value::Stream(Stream { dict, .. })` is `Value::Stream(s)` and `s.dict` now. `Dict::remove` gives the value it removed, so a closure that calls it and returns its value no longer returns `()`. And new: `as_bool`, `as_bytes`, `as_array` and `as_stream`; an `Object` from an `ObjectId`, an `f32`, a `String` (a name) and the smaller integers; `Dict::get_mut`, `iter_mut`, `has_type`, `type_name`, `remove_duplicates`, `collect` into a `Dict`, and `for` over a `&Dict`. A dictionary's lookups allocate nothing for up to 32 entries.
- **The model, its tables and predicates are pdf-arlington's.** `grammar`, `predicate`, `COMMIT` and the embedded model are the new pdf-arlington crate's, re-exported at the same paths and at the root as before, and `extension::ISO` too; what they are is unchanged, and `--version` names the same model and hash, but that `predicate::SUPPORTED` and `extension::ISO` are `&[...]`, not arrays of a fixed length, and `predicate::Expr` is `#[non_exhaustive]`, so a function or an extension can come without a breaking release. `extension::declared(&dyn Source)` stays, over pdf-arlington's, which takes the trailer's `/Root`, the metadata and a closure that resolves references, so pdf-arlington depends on pdf-objects' types alone. `predicate::TOLERANCE` is public there. Which model every check reads stays this crate's: `grammar()`, `use_model`, `grammar::NAMED` and `extension::named` are its own, at the same paths and saying the same, over pdf-arlington's `Grammar::embedded()` and `Grammar::extensions()`, as pdf-arlington chooses no model; `Grammar::embedded()` gives the embedded model as a `&'static Grammar`, read once, where it gave an owned `Result<Grammar>` read anew at each call. pdf-arlington is Apache-2.0, as the model is, and builds with Rust 1.89. This package no longer holds the model's files, nor licence files: upstream's LICENSE and NOTICE.txt, which the parts of the checker adapted from TestGrammar are under too, are in pdf-arlington's `model/`, and `src/check.rs`'s header carries the NOTICE's copyright and DARPA notices for those parts.
- **Breaking, the library: typed errors.** `Allowances::read` gives an `allowance::ReadError`, `Allowances::parse` an `AllowanceError`, `Hold::parse` a `HoldError`, `Exempt::parse` an `ExemptError` and `use_model` a `grammar::Refused`, where each gave an `anyhow::Error`; and pdf-arlington's `Grammar::load` and `predicate::parse`, re-exported here, a `grammar::Error` and a `predicate::Error`. Each derives `Display` and `std::error::Error` with thiserror, `#[non_exhaustive]`, a variant for each thing that can be wrong, with its line or path. Its `Display` is the whole message, word for word what `{:#}` printed before, so the command line says the same; and none has a `source`: a std error under one, reading a file or a number that doesn't parse, is a field, said after `: `. `AllowanceError`, `HoldError` and `ExemptError` are at the root too. anyhow is the command line's alone.
- **Breaking, the library: a `Cx` is made from a `FileCx`.** pdf-arlington's `predicate::FileCx`, re-exported here and at the root, is what every row of a file is evaluated in: `FileCx::new(trailer, version, &resolve)`, then `.size(..)` and `.extensions(..)`, once a file; `file.at(container, at)` makes a row's `Cx`, which `.parents(..)` and `.defaults(..)` complete, each giving a new one (`#[must_use]`), and whose `container()` and `at()` read it. `Cx`'s fields are private, so a literal of it no longer builds, and it has two lifetimes where it had one, `Cx<'c, 'a>`, the row's borrow and the file's: `&Cx` in a signature elides both, as before, but `Cx<'a>` written out no longer builds. The resolver `FileCx::new` borrows must outlive the `FileCx` and what holds it, so a walk that holds one declares its resolver before it. `FileCx` is generic over its resolver, `FileCx<'a, R>`, any of pdf-objects' `Resolve` (a closure among them, by value or by reference, or a `&Document` or `&Reading`), and `FileCx<'a>`, the default, names one over any resolver, a `dyn Resolve`, as a `Cx` reads through it: `&FileCx` in a signature takes a reference to one over any resolver, and one kept is kept by its resolver's type, or boxed (`Box<FileCx>`), as a closure's type can't be named. pdf-objects' `Resolve` is re-exported at the root, so a resolver of a type of its own, or a function over any, names it at the version pdf-lint takes, as it does `Unreadable` and `Why`, what `Resolve::try_resolve` says of an object that doesn't read. An object the resolver gives none for is null, whatever the reason: over a reading by position, one whose bytes the source failed to give, in that row and in any tree read then. pdf-structure's `Reading::failed_resolves` counts those, for a caller to learn that some were. It's `Send` and `Sync` when its resolver is, as `&Document` and `&Reading` are, so one a file can be shared across threads. The `FileCx` keeps what the predicates read of the file as a whole once read, the name trees' keys, the structure tree's content items and the form's fields' names, which the caller held in `predicate::{Fields, Structure, Trees}`, now gone; a name tree is kept by where its root was written and the number of the object its entry names, not by where its root is in memory, and one known by neither is read each time. `fn:ImageIsStructContentItem` and `fn:PageContainsStructContentItems` know the objects the structure tree's content items name, and a row's container, by their numbers (`Cx::id` gives the container's), and one without a number by where it was written, not by where it is in memory: a container that can't be told apart from an item that could be it, as one built without its number, is unknown where it was false. `check` makes one `FileCx` a file, and gives each row the number of the indirect object its container is, when it's one. Every report is unchanged, but for a file whose object stream starts an object inside another's bytes, and whose structure tree names it: a page or image written directly at those bytes is now known as that object, where their places in memory told the two apart.
- **Breaking, the library: passwords as typed.** `bytes::read_opened` and `read_from_opened` take pdf-crypt's `Password`, a password as typed, where they took bytes, and try each in each of its encodings, the forms `text::passwords` gave, in the same order but that those that fit the file's revision come first, every password's before any password's others (pdf-crypt's `Password::encodings` and `Handler::open`), in the empty password's place, as before: a wrong one leaves a file locked, or plain where its strings and streams aren't encrypted, as no password would. `text::passwords` is gone, and `text` is pdf-objects' alone; pdf-crypt is re-exported as `pdf_crypt`, as pdf-structure re-exports it, for `Password`, `Encoded` and `Encoding`. `Encryption::Opened` says which password opened the file, and in which encoding (`by`, none for the empty password tried as none was given), which `Encryption::by` sets on what `Encryption::opened(owner)` makes, as before. The command line holds `--password` in zeroize's `Zeroizing`, wiped when it's dropped, from the moment clap gives it; its reports are unchanged. A test holds the PDFDocEncoding table pdf-crypt encodes by to the one `text::decode` reads with, character by character, as before.
- **A password in its SASLprep form.** `--password`, and each password `read_opened` and `read_from_opened` are given, is tried first in its SASLprep form (RFC 4013), as revisions 5 and 6 take a password (ISO 32000-2, 7.6.4.3.3), where that isn't the password as typed, then as before; and its single-byte forms are of the password composed (NFC). So a file whose password was set as the spec has it opens by the password as it was typed (Ⅸ, for one set as `IX`; an accent typed apart from its letter, for one set with them composed) and is checked, where before it was unread ("the password --password gives doesn't open it"). A password SASLprep refuses is tried as before, and every file a password opened, it opens still. The SASLprep form tried first is as of Unicode 3.2, which SASLprep is of, then, where that's another, its form by a later Unicode, as most SASLprep libraries make it: so a file whose password a writer set with a character Unicode 4.0 remapped (U+2F874, say), or a sequence Unicode 4.1 composes otherwise, opens by the password as typed whichever Unicode its writer prepared it by, where before it opened only by a later Unicode's.
- **An LZW stream read past a full table.** An LZW stream whose table fills, 4,096 entries, with no clear code is decoded on, against the table as it is, as PDFium, pdf.js and poppler read it, where it stopped there, as qpdf does: what's past that point is read and checked, and the finding that the table is full is reported where it was, at the same byte. LZW decodes faster too, its codes read from a 64-bit buffer, not a bit at a time.
- **The reader is pdf-structure's.** `bytes` and `source` (`Source`, `Document`, `Trailer`, `Warning`, `Update`, `Encryption`) are the new pdf-structure crate's, re-exported at the same paths and at the root as before; what they read, and every warning and error they give, are unchanged. pdf-structure is MIT OR Apache-2.0 and builds with Rust 1.89. This package no longer depends on pdf-filters itself.
- **Breaking, the library: why an object doesn't read is typed.** `Source::get` gives a `source::Unread` where it gave a `String`, and `Document::unread` one for each object that doesn't read: pdf-structure's error, `#[non_exhaustive]`, derived with thiserror, a variant for each reason, whose `Display` is the text the `String` was, word for word, so every report says the same. A `Source` of its own says why in its own words with `Unread::Other`. `Trailer`, `Update` and `bytes::XrefEntry` are `#[non_exhaustive]`, and so are `XrefEntry::Free` and `Encryption::Opened`, so each can grow without a breaking release. None of the four can be written as a literal outside pdf-structure any longer, `Encryption::Opened { owner, by }` and `Update { objects, previous }` among them: a reader outside the crate makes its trailer by `Trailer::new`, setting `stream` and `unwritten` on it after, its update by `Update::new(objects, previous)` and an opened file's encryption by `Encryption::opened(owner)`, with `.by(..)` for which password opened it; and a pattern that names `Opened`'s or `Update`'s fields ends in `..`.
- **Breaking, the library: `Encryption::Opened` says how the file is encrypted.** It says the methods of strings, streams and embedded files, the revision, whether metadata is encrypted, and what pdf-crypt's handler found wrong with the encryption dictionary (`faults`, kept with faults off too). Every reading sets them. `Encryption::protection` gives a new file's protection like the reading's. So an `Opened` a reading gives isn't `==` to one built by `Encryption::opened(owner).by(..).permitting(..)` alone. **Migrating:** match the fields you need (`Encryption::Opened { owner, permissions, .. }`), or build the value with every setter (`encrypting_strings`, `encrypting_streams`, `encrypting_files`, `of_revision`, `encrypting_metadata`, `finding`).
- **A reading on demand.** `bytes::Reading`, pdf-structure's, re-exported with the rest of `bytes`, opens a file, an encrypted one by the empty password (`Reading::open(source, options)`) or by the passwords given (`open_with`, as `read_opened` tries them), and one no password opened by others after (`unlock`, given the bytes to try), and reads each object when it's first asked for, from any thread, from bytes in memory or a file read by position, a window at a time (`bytes::FileBytes`, whose `bytes::Identity` tells whether it's changed), and read whole is what `bytes::read` gives, the reading taken or kept beside it (`into_document`, `to_document`), which reads every object so, by the same code; every report is unchanged. It hands out any stream's data when it's asked for (`data`), decrypted in an encrypted file that opened as an object stream's is, a metadata stream by its own `/Crypt` filter and an embedded file without one by the crypt filter `/EFF` names (from `/V` 4), refused where it may be ciphertext the reader doesn't decrypt, and decoded through its filters (`decoded`), its error holding pdf-filters' where the data doesn't decode cleanly, which is re-exported as `pdf_filters` for it. Its options say which Flate backend its streams inflate on (`Options::flate`, pdf-filters' miniz_oxide by default, the one pdf-lint builds with; zlib-rs with pdf-structure's `zlib-rs` feature), and its limits are a value a caller sets (`bytes::Limits`, in `bytes::Options`), and they're the same in a build under cargo-fuzz (`--cfg fuzzing`), where the reader's were smaller: the fuzz target sets small ones itself. `Document` has where the bytes reader read each object (`record`, `records`) and a new field, `facts`, what the file says of itself as written, which a `Document` built by `Document::new` has none and the defaults of.
- **Mature crates in place of the tool's own code.** The model's hash is computed by twox-hash, the same XXH64 of the same bytes, so `--version` and every report's `model` are unchanged. `bytes::Identity` holds the file it's of open, through same-file, which knows it by its device and inode on Unix and its volume serial number and file index on Windows, so another file made at its path once it's removed isn't taken for it, by an inode reused or by the creation time NTFS gives such a file; it's `Clone`, and `bytes::FileBytes::identity` gives a reference to it. `bytes::Identity::of` opens the file to read, without waiting, so it needs leave to read it where its length and time needed none, and refuses a path that's neither a file nor a folder, a FIFO, a socket or a device, without opening it. The JSON reports are written by serde_json, byte for byte as before: the same keys in the same order, and the same escapes, backspace and form feed still `\u0008` and `\u000c`. The command line is parsed by clap. What stays: each option's meaning, its name, its value and its default, `-h` and `-V`; an option's value is the next word whatever it begins with (`--password -x`, `--hold -`), and the last of an option given twice wins; files go anywhere among the options, `-` once; an empty word is a file that can't be read, the others still checked; the exit codes; `--version`'s two lines; and every error that isn't about the command line, word for word. What changes: `--help` is in clap's layout, the same for `-h`, within 80 columns, and the README shows it as `cargo install --locked` builds it, with the lock's clap; an argument error is clap's, `error: ...` then `For more information, try '--help'.`, with the usage line between where clap gives one, where it was `pdf-lint: ...` and, for an unknown option or no file, the whole usage. A refused value keeps its reason after clap's words (`invalid value '0' for '--jobs <N>': not a number above 0`), as `- -` and the options that can't go together keep theirs (`error: --hold and --built: ...`); a missing value is `a value is required for '--hold <FILE>' but none was supplied`; an unknown option is `unexpected argument '--bogus' found`, with a tip; a value that isn't UTF-8, for an option that takes text, a number or a word, is `invalid UTF-8 was detected in one or more arguments`; and no arguments at all print the help on standard error, exit 2. Taken now: `--option=VALUE` beside `--option VALUE` (`--password=PW` was an unknown option, and its error printed the password), and `--` ending the options so that a file beginning with `-` can follow. `-h` and `-V` each stand alone, as before: a word that begins with one and goes on, `-hV` or `-hold`, is an unexpected argument, which clap alone would take for the flag, printing the help and exiting 0. A word beginning with `-` that isn't UTF-8 is an unexpected argument, where it was a file; after `--` it's a file still. clap, serde and serde_json, and anyhow, are the binary's alone, under the `cli` feature, which is on by default: a crate that uses the library alone leaves them out with `default-features = false`. An archive's `THIRD-PARTY-NOTICES.txt` lists twox-hash (MIT), same-file (Unlicense/MIT), serde, serde_core, serde_json, itoa, clap, clap_builder, clap_lex and anstyle (MIT OR Apache-2.0), memchr (Unlicense OR MIT), and zmij and strsim (MIT); Linux's libc (MIT OR Apache-2.0) too, which macOS's listed already; and Windows' winapi-util (Unlicense OR MIT), windows-sys and windows-link (MIT OR Apache-2.0), which same-file reads a file's index through. It gives each one's licence files, and says each crate is under the licence it names, no longer that each offers the Apache License 2.0.
- **Breaking, the library: a document's objects through methods.** `Document`'s `objects` field, a public map, is private, each object kept with where the reader read it while it's as read, so a record is always of the object beside it. `contains(id)` says whether an object is listed, read or not, where `objects.contains_key(&id)` did; `objects()` gives each that reads, by number, `range(..)` those in a range of ids, and `unread()` each that doesn't, with why; `Source`'s `ids` and `get` read as before. `set(id, object)` puts one in, with no record, giving back the one it replaces; `insert(n, object)` is as before, `set` at generation 0; `set_unread(id, why)` puts why one doesn't read, where a reader outside the crate inserted an `Err`; `remove(id)` takes one out, its record with it; and `get_mut(id)` gives one to edit, dropping its record, where `objects.get_mut` or `values_mut` did. `--last-update` asks the revision before by `contains`, so its reports are unchanged. A document numbers new objects past every number the file lists (`new_id`, `add`, `max_id`, `set_max_id`), follows references (`dereference`, `get_dict`, `get_dict_mut`, `catalog`, `catalog_mut`), changes its trailer's dictionary (`Trailer::dict_mut`), and walks what its trailer reaches (`reachable`) and removes the rest (`prune`); two documents are equal only where their new ids start at one number too.
- **What a check of a file's structure reads.** `Revision`, pdf-structure's, is re-exported at the root with the rest of `source`: one of a file's revisions, with its trailer, which `Document::revisions` and `bytes::Reading::revisions` give. `Source` has `record`, `held` (an object stream's decoded data), `revisions`, `facts` and `in_the_clear`, each defaulting to nothing; `Document::in_the_clear` holds the object streams an encrypted file leaves in the clear while it encrypts its strings. pdf-arlington evaluates `fn:NoCycle`, which the model asks of an object stream's `/Extends`.
- **An object over another's bytes found.** The reader warns of an object an object stream's header starts inside the bytes of another read from it, two at one offset or one inside another's value (ISO 32000-2, 7.5.7), so a check finds it, a `reader` finding held as that object is, at its bytes in the stream's decoded data: `it starts at byte 8 of object stream 10 0 R's data, inside 3 0 R, which runs from byte 8 to 80`. Reports move only for a file with such an object, by that finding; what's read of each object is unchanged.
- **Every object stream checked.** An object stream's dictionary (ISO 32000-2, 7.5.7) is held to the model's `ObjectStream` table, whether or not anything reaches it, where it was left out: nothing in the model links to one but another's `/Extends`. After the walk from the trailer, so that what that reaches is the table it was, each is visited from its number, the path of its findings (`12 0 R`, `12 0 R/DecodeParms`), their object it, and held as any object is, by a hold file, by `--last-update` when the update wrote it, and by default. What it refers to is reached through it, as through any object: an indirect `/Length`, a `/Filter` or `/DecodeParms` by reference, `/F`, and `/Extends`, which `fn:NoCycle` is evaluated on; so such an object is no longer unreached. One the walk reached first as another table stays that, counted in two contexts. A path from a number is no place a rewrite keeps, as it renumbers: `--baseline` of a rewrite (`Report::by_path`) carries a finding from an object stream's number, or an earlier cross-reference stream's (below), by a like one anywhere in the baseline. A stream whose `/Type` isn't the name `/ObjStm` is none, to the reader or the check, as before. Reports move for a file with object streams: the summary's objects, and the keys, count them; each key of one in a file below PDF 1.5 is `too-new`, as a cross-reference stream's keys already are there; and a fault in one is a finding, as a `/Filter` abbreviated (`/AHx`, an inline image's abbreviation, which the reader reads as qpdf does) or a key the table doesn't list in a built one. `grammar::NAMED` has `ObjectStream`, so `use_model` refuses a model without that table (below).
- **Earlier revisions' trailers checked.** Each earlier revision's trailer (ISO 32000-2, 7.5.6), as an incremental update left it, is held to `FileTrailer`, or to `XRefStream` when it's a cross-reference stream, as the newest is, where only the newest was: after the object streams, the newest first, a table's from `trailer K`, K its revision counted from the first (`trailer 1`, `trailer 1/ID`), its findings in no object, and a cross-reference stream's from its number (`7 0 R`), its findings' object it. It's held with every object, as merged, as the newest trailer is; under a hold file, a cross-reference stream's when the file names its number, and a table's never, so `--last-update` holds none, but a stream at a number the update writes again. Most deprecations are a writer's legacy, as Acrobat's `/DR` on every field, one per field.
- **Extensions a file declares.** A file is checked under the extensions it declares, as the model names them (`extension::declared`, `Report::extensions`): Adobe's level 3 or later at 1.7 and ETSI's, from the catalog's extensions dictionary, ISO's by the number under `/ISO_`, and PDF/A-3 and PDF/VT-2 from its XMP metadata, which the bytes reader keeps where it's unfiltered and unencrypted (`Source::metadata`). Under them, `fn:Extension` holds, a key, type, value or link under one is the model's from the extension's version, and a key under one isn't unlisted. `--extensions` names more (`Options::extensions`), as TestGrammar's does: the model's names, a comma between, a name the model hasn't refused (`extension::named`), and, unlike TestGrammar's, no `*` for all, as each is a claim about the file; a baseline and the revision before an update are checked under them too. So, among others, a page's `/Tabs /W` in a 1.7 file at Adobe's level, a PAdES signature's `ETSI.CAdES.detached` where ETSI's is declared, and a PDF/A-3 file's associated files are no findings, and what's under them, as rich media annotations, is reached and checked. `--full` and the JSON (`extensions`) say which.
- **More corrections: `/DecodeParms` and `SMaskInData`.** The 36 stream tables' `/Filter` SpecialCase, that `/DecodeParms` be as long as `/Filter`, asks it only when `/DecodeParms` is there, which ISO 32000-2 lets a stream leave out (7.3.8.2); and an image's `SMaskInData` defaults to 0 (8.9.5).
- **A file that won't open with the password given is unread.** An encrypted file that qpdf can't open, with no password or a wrong one (`Qpdf::locked`, its `--requires-password`), is a file that can't be read, exit 2, saying it needs a password or that `--password`'s doesn't open it; and so is such a baseline. Before, nothing in it decoded: what its object streams held was found unresolved or unreached, and a file without object streams could look clean.
- **A file that needs qpdf without one is unread.** A file with anything compressed or encrypted, when the qpdf it would run isn't found, doesn't run, or is older than 11.9 (`Qpdf::ready`), is a file that can't be read, exit 2, in a line saying why and to install qpdf 11.9 or later or name one with `--qpdf`; before 11.9, qpdf writes a name that isn't UTF-8 into its JSON as the name's bytes, which isn't JSON, and nothing of that run reads; and so is such a baseline. A file all in plain view is checked without qpdf. `--version` says why there's no qpdf to decode with, when there isn't.
- **The JSON says which pdf-lint wrote it, and against which model,** as `pdf_lint` and `model`, in every line, a file's that couldn't be read too.
- **Additions to the embedded model.** `model/additions` holds tables in upstream's format that `build.rs` adds to the embedded copy, a table upstream lacks whole and one it has row by row, each row's Note saying why, stopping the build when upstream has an added row's key or table itself (`grammar::additions`, `Addition`); `--version` says how many rows are added. The first: a variable-text field's own `/DR` (PDF Reference 1.4, Table 8.51), on the text and choice field tables, obsolete from 1.5 (PDF Reference 1.7, implementation note 118); and `EncodingMap`, the PDF 1.0 `Encoding` resource as a dictionary of named encodings, which a correction links `Resource/Encoding` to in place of the one encoding the model checked it as. So a text field's `/DR` and an `Encoding` resource's names aren't unlisted, and what they reference is reached. From PDF 1.5 on, a field's `/DR` is deprecated (counted only, unless `--deprecations` makes it a finding, below), and so is the `/Encoding` in it, which the model has deprecated since 1.2. The embedded model's hash is now `fc22d1fadc1fd269`.
- **`--unlisted built|all|never`** (`Options::unlisted`, `UnlistedIn`): which held objects a key the model doesn't list is a finding in. `built`, the default, as before; `all`, merged objects too, where with `--baseline` or `--last-update` what the earlier file had is carried (each checked with the same setting); `never`, none. `--exempt` takes `--unlisted all` in place of a built object, and refuses `never`; the JSON says which as `unlisted_in`.
- **Three more syntax faults, as the reader's findings.** A name with a `#` that two hex digits don't follow, or with `#00`, NUL (ISO 32000-2, 7.3.5), which readers read each their own way, on the object it's in; a cross-reference table whose rows aren't 20 bytes, ten digits, a space, five digits, a space, `n` or `f` and a two-byte end of line (7.5.4), once a table, with how many and the first; and a file whose last line isn't `%%EOF` alone (7.5.5): bytes after it, on a line with something else, none in the last 1024 bytes, where readers look, or none at all. The end is asked of the file read whole, not of a previous revision.
- **Fuzzing.** `pdf_lint::fuzz::check_file`, the body of a cargo-fuzz target (`just fuzz check`): a file read from its bytes and checked, held and checked as its first two bytes choose, asserting no panic, the same report twice, and every finding's bytes inside what was read, and, for a file with an incremental update, set against its previous revision. `pdf_lint::fuzz::seeds` makes files for it to begin from, and a unit test checks thousands of their mutations on stable Rust.
- **Release archives.** A workflow builds, on a version tag, an archive for Linux (x86_64 and aarch64, the binary static), macOS (arm64 and x86_64) and Windows (x64), each with qpdf 12.4.2 from its official zips, pinned by SHA-256, and the notices and licenses that go with it, and the Arlington model's NOTICE.txt; checks each runs as it's unpacked; and drafts a GitHub release with them. The command line finds the qpdf beside it, after `--qpdf` and `PDF_LINT_QPDF`, and `--version` says which it found. CI tests against the same qpdf, and builds and checks the Linux x86_64 archive.
- **The command line.** `pdf-lint FILE...` with `--hold`, `--built`, `--exempt`, `--last-update`, `--pdf-version`, `--model`, `--one-table`, `--unlisted`, `--deprecations`, `--extensions`, `--allow`, `--full`, `--qpdf`, `--password`, `--jobs` and `--format`, each finding printed with its bytes, from the decoded data for one in an object stream. `--jobs` checks files at once, as many as there are CPUs by default, and reports them in the order given; a panic is reported as that file's, and the rest are checked. A report no one reads any more, piped to `head`, stops it without a panic. `--last-update` holds what the newest incremental update wrote, rewritten objects as merged and new ones as built, and leaves out what a rewritten object or the trailer already had in the revision before (`Document::update`, `bytes::read_from`, `Report::since`). `--format json` writes a line of JSON for each file. `--exempt` names the keys a writer writes on purpose that the model doesn't list, or the beginnings of keys (`Exempt::parse`). `--pdf-version` checks a file as another version, and a baseline, the revision before an update and the allowances' versions as that too; the JSON says it as `checked_as`. `--model` checks against a checkout of the model's `tsv/latest` in place of the embedded one (`use_model`), refusing one that doesn't read whole or lacks a table the checker reads by name; the JSON report's `model` says which model, by its hash: XXH64 of its tables' files (`Grammar::hash`), the same for the same tables wherever they're read from, which `--version` prints for the embedded one. `--baseline` leaves out what the file each was written from already had: by object for an incremental update of it (`Report::since`), by path for a rewrite, and anywhere where it has nothing at that path (`Report::by_path`, `Options::paths`).
