# PDFium Oracle (`oracle/`)

Several crates emulate PDFium's forgiving behavior when reading real-world PDFs—behavior that is not specified in ISO 32000-2 and can change across Chromium releases:

- `pdf-tokenizer` (`Rules::Pdfium`, `decode::pdfium`)
- `pdf-objects` (`Parser::rules`, `text::decode_with`)
- `pdf-structure` (`Recovery::Pdfium`)
- `pdf-content-streams` (content stream lexing, inline images, `/Contents` joining)
- `pdf-semantics` (`pages::pages`, `dest::DestTable`, `action`, `outlines`, `labels`, `files`, and `viewer` under `Rules::Pdfium`)
- `pdf-color` (`components`, §7.10 `Function` & `PreparedSpace` evaluation, and the unprofiled CMYK LUT checked by `oracle/cmyk_lut.py`)
- `pdf-images` (`decode_xobject`, `decode_inline`, codecs, and masks under `Rules::Pdfium`, verified live in `crates/pdf-raster-oracle`)
- `pdf-fonts` (`Font`, `shown`)
- `pdf-gfx` (`PageGeom`, `interpret`, `encode`, `TextPage`)
- `pdf-annots` (`page_annots`, `TypedAnnot`, `plan_flatten`)
- `pdf-forms` (`Form::read`: field types, flags, names, and values; `FormKind::read`: the kind of form a document holds; the appearances PDFium makes for a text, button, or choice field that has none, recorded for the appearance makers; the text PDFium's text page reads back of appearances made in a fallback font, `fonts`; and a button group's states and value after a press, for `group`'s rules)
- `pdf-raster` (`render_page`, `render_content`, and `PdfiumBackend`, verified live against `chromium/8152` in `crates/pdf-raster-oracle`)
- `pdf-linearize` (checked against PDFium's `FPDFAvail_*` incremental-loading API)

To keep behavior reproducible without linking PDFium into any crate, each crate stores small synthetic test cases alongside recorded answers from a pinned PDFium build in `crates/<crate>/tests/pdfium/`.

- **`cargo test`** checks each Rust crate against the committed answers offline (no PDFium binary needed).
- **`just test-pdfium`** regenerates cases in memory, checks doc build pins across every crate, verifies `pdf-color`'s CMYK grid via `oracle/cmyk_lut.py`, runs every recorded case against `libpdfium` via `ctypes`, and runs `pdf-raster-oracle`'s live comparison suites.

## Pinned Build

- **Version:** PDFium as of **`chromium/8152`** (`bblanchon/pdfium-binaries`)
- **Archive (Linux x86_64):** `pdfium-linux-x64.tgz`
- **SHA-256:** `384ab5c51882408a143a21f9c14dcd2caf1f75280ae41c554d0489b46c3dba9f`

`just _pdfium` downloads this archive into `target/pdfium-8152/`, verifies its SHA-256 checksum (and GitHub build provenance attestation when `gh` is authenticated), and unpacks `libpdfium.so`. On other platforms, set `PDF_LINT_PDFIUM=/path/to/libpdfium` instead (the runtime `PdfiumBackend` adapter in `pdf-raster` reads `PDF_RASTER_PDFIUM` or `PDFIUM_LIB_DIR`).

Note: `pdfium-binaries` builds with PDFium's default `pdf_enable_rust_jpeg = false` (using `libjpeg-turbo`), which reports exact end-of-image offsets for inline DCT images.

## Commands

```sh
# Verify committed cases, doc pins, and live PDFium answers
just test-pdfium

# Regenerate case files from cases.py and re-record chromium-8152.txt
just pdfium-answers

# Run directly against any PDFium shared library (uses Python 3 stdlib only)
python3 -I -B oracle/pdfium.py run /path/to/libpdfium.so crates/pdf-tokenizer/tests/pdfium
```

## Layout of a `tests/pdfium/` Set

Each crate's `tests/pdfium/` directory (excluded from published crates.io packages) contains:

- **`cases.py`** — Deterministic generator script using only Python's standard library (stored-block zlib compression, unique case-insensitive filenames). `pdf-fonts` additionally reads binary font programs generated by its `the_programs_are_written` test in `programs/`, and files of fonts its writer embeds, generated by its `the_written_cases_are_written` test (with `embed`) in `written/`. `pdf-forms` reads `pdf-fonts`' TrueType program from there for its embedded-font cases, and files its `the_written_cases_are_written` test writes (with `embed`) in its own `written/`: `forms-ap` cases of a TrueType program embedded as a Type 0 font in `/DR`, and appearances made in Helvetica and a fallback program, drawn on the page as well, which the `fonts` kind reads back.
- **`cases/` & `cases.tsv`** — Generated test inputs and manifest (`name`, `kind`, `files`).
- **`chromium-8152.txt`** — Recorded one-line PDFium output per case. `oracle/pdfium.py cases` verifies that the crate's `README.md` explicitly states `as of chromium/8152` and that no file in `README.md` or `src/` names a different build.
- **`differ.tsv`** — Documented, intentional differences between the Rust crate and PDFium (with an optional mode column such as `all`, `default`, `image-ends`, `verified`, or `pdfium`; for `pdf-forms`' `forms-ap` and `forms-ap-all` cases, the part of the record that differs, `made`, `bbox`, `matrix`, `paint`, `clip`, or `text`, and for a button's `states`, `as`, or `mark` too, and for its `forms-press` cases `as`, a widget's `/AS`, or `v`, a field's `/V`, each written `part@N` for annotation `N` alone, every other part held, and a line under the kind's name a rule held on every case it applies to). Rust tests assert that listed cases still differ so fixed divergences don't go stale.
- **`chromium-N.differs`** *(optional, during bumps)* — Known upstream PDFium regressions at build `N` where the crate intentionally preserves the prior answer.

## Case Kinds

`oracle/pdfium.py` wraps fragments in minimal one-page PDFs (or loads `.pdf` files directly) depending on the case kind:

- **`content`:** Page `.content` stream + optional `.res` dictionary -> extracted page objects (paths, matrices, segments, dashes, images, text objects, `/MCID` marks).
- **`contents`:** Raw `/Contents` value (`.contents`) + indirect objects from ID 4 upward (`.objects`) -> extracted page objects showing which streams PDFium joined.
- **`number`, `hex`, `literal`, `name`:** Single token (`.word`) placed into an operator operand -> parsed float, shown text, or font lookup result.
- **`mediabox`:** Page `/MediaBox` (`.obj`) -> page width and height.
- **`info`:** Trailer `/Info` dictionary (`.obj`) + key (`.tag`) -> decoded metadata string.
- **`kids`:** Page tree `/Kids` array (`.obj`) -> page dimensions or `no-page`.
- **`pages`, `outlines`, `labels`, `attachments`, `viewer`:** Complete `.pdf` -> `FPDF_GetPageCount` plus width, height, and rotation for up to 64 pages (`pages`); bookmark hierarchy (`FPDFBookmark_*`) (`outlines`); per-page `FPDF_GetPageLabel` strings (`labels`); `/Names /EmbeddedFiles` attachments (`FPDFDoc_GetAttachment*` / `FPDFAttachment_*`) (`attachments`); and `FPDF_VIEWERREF_*` + `FPDFCatalog_GetLanguage` (`viewer`).
- **`avail`:** Complete `.pdf` (+ optional `.password`) fed incrementally to `FPDFAvail_*` starting from the first 1,024 bytes -> linearization status, bytes fetched per stage, and per-page availability.
- **`spaces`:** Complete `.pdf` drawing 8x1 unfiltered inline images in named `/ColorSpace`s -> inferred component count from raw image byte length.
- **`fonts`, `fonts-heights`, `fonts-boxes`:** Complete `.pdf` showing a test string at 1000 pt -> `FPDFText_GetUnicode`, character origins, loose boxes, and outline boxes.
- **`gfx-geom`, `gfx`, `gfx-text`:** Complete `.pdf` -> page view dimensions, quarter-turn rotation, and `FPDF_PageToDevice` probes (`gfx-geom`); flattened page and Form XObject leaf objects in PageSpace (paths with stroke styles/dashes, placed image quads, shadings, text render modes, top-level clip paths, nested marked-content stacks) plus non-generated `FPDFText_GetCharOrigin` positions (`gfx`); and `CPDF_TextPage` reading-order characters, generated spaces/newlines, soft-wrapped hyphens, `FPDFText_CountRects` merged selection count, and `FPDFText_FindStart` search matches (`gfx-text`).
- **`annots`, `annots-flatten-display`, `annots-flatten-print`:** Complete `.pdf` -> page 0 annotation slots (`FPDFAnnot_*`), legacy borders, decoded text strings, `QuadPoints`, line/polygon/ink geometry, link destinations (`FPDFLink_GetDest`), and actions (`FPDFAction_*`) (`annots`); and `FPDFPage_Flatten` (`FLAT_NORMALDISPLAY` vs. `FLAT_PRINT`) status, remaining `/Annots` count, and flattened PageSpace path segments (`annots-flatten-*`).
- **`forms`:** Complete `.pdf` -> page 0's widgets under a form-fill environment (`FPDFDOC_InitFormFillEnvironment`): each one's field type (`FPDFAnnot_GetFormFieldType`), flags, fully qualified name, and a text field's value, or `none` where PDFium finds no field for the annotation.
- **`forms-kind`:** Complete `.pdf` -> `kind N`, the kind of form the document holds as `FPDF_GetFormType` numbers it (`0` none, `1` an AcroForm, `2` XFA that is the whole form, `3` XFA beside an AcroForm), or `no-document` where the file doesn't load.
- **`forms-ap`:** Complete `.pdf` whose text fields have a value and no `/AP` -> the normal appearance PDFium makes for each of page 0's widgets under the same form-fill environment, read back from the file `FPDF_SaveAsCopy` writes (and held to `FPDFAnnot_GetAP`'s content where it is ASCII), in five parts: `bbox` and `matrix` (the stream's `/BBox` and `/Matrix`); `paint`, each path painted before `/Tx BMC` with its fill or stroke color, a stroke's width, cap, join and dash, and its segments; and `clip` and `text`, the clip rectangle in the `/Tx` sequence (or `none`) and each `Tj` by its font's resource name, size, origin (the `Td`s summed in `f32`) and codes, or `tx none` where there is no `/Tx` sequence; `idx N none` where PDFium made no appearance. The script reads the content with a reader of its own that stops the recording at any operator PDFium doesn't write in a text field's appearance.
- **`forms-ap-all`:** Complete `.pdf` whose button or choice fields have no `/AP` -> every appearance of each of page 0's widgets once PDFium has made what it makes, under the same form-fill environment, read back from the saved file: the widget's `/AS` (`as`, a name as `/Name`, a string as `(string)`, or `none`), then each of `/AP`'s `/N`, `/D` and `/R`, as `ap N` where it is a stream or `ap N/STATE` for each state of a state dictionary, each with its `/BBox`, its `/Matrix` and its content item by item in the order the content has them, paths and text in or out of `/Tx`: each path painted (as `forms-ap` writes one), `clip` and its segments and `]clip` where the `Q` that ends it comes, `tx[` and `]tx` around the `/Tx` sequence, and `text` for each `Tj` with its own color, font, size, origin and codes; a `cm` is applied to the points it moves. `ap none` where the widget has no `/AP`. Its reader stops the recording at any operator PDFium doesn't write in a button's or a choice's appearance (an icon's `Do` among them).
- **`forms-press`:** Complete `.pdf` + the page 0 annotation indices to press in turn (`.press`) -> each widget's `/AS` and each field's own `/V` (by its fully qualified name, from `/Fields` down) in the file PDFium saves after each widget is pressed by the pointer at its centre (`FORM_OnMouseMove`, `FORM_OnLButtonDown`, `FORM_OnLButtonUp`), under a form-fill environment whose first callbacks are the script's own and do nothing, or answer the one page there is; `forms` and `forms-ap` keep every callback null. A press PDFium doesn't take stops the recording.

## Bumping the PDFium Pin

1. Download the new `pdfium-linux-x64.tgz` from `bblanchon/pdfium-binaries`, verify `gh attestation verify FILE --repo bblanchon/pdfium-binaries`, check `args.gn` (confirm `libjpeg-turbo`, not `pdf_enable_rust_jpeg`), and record its SHA-256.
2. Run `PDF_LINT_PDFIUM=/path/to/new/libpdfium.so just test-pdfium` to list every case whose output changed.
3. Inspect PDFium's upstream commits for each change:
   - Update the Rust implementation, tests, docs, and `CHANGELOG.md` for intentional upstream behavior changes.
   - Record upstream PDFium crashes/regressions in `chromium-<NEW>.differs` to retain the previous expected answer.
4. Update `pdfium_build` and the SHA-256 in `justfile`, update `as of chromium/<NEW>` in `oracle/README.md` and each crate's docs, then run `just pdfium-answers` and `just ci`.
